# AvatarForcing

## 是什么

**一步式流式说话头像**：把"生成一小段、立刻渲染"做成一步生成，块与块之间靠局部未来的滑动窗口去噪衔接。论文口径的指标是**推理延迟约 500ms、加速比 6.8×、人类偏好 >80%**。

它在文献里的位置：属于"动作空间 + 快速渲染器"路线的**交互式分支**。与普通音频驱动头像的差别在于——后者只管让一张脸开口，它还要处理对话里的**听、说、反应与打断**，并且必须边收输入边出画面。

一句话读完：**把身份与运动显式分解，把条件分两路编码，把生成为按块向前滚。**

- 论文：`arXiv:2603.14331` — AvatarForcing: One-Step Streaming Talking Avatars via Local-Future Sliding-Window Denoising（2026）

## 架构核心

链路：**驱动信号 → 表示 → 生成 → 渲染**

| 环节 | 做什么 |
|------|--------|
| 驱动信号 | 用户的音频与视频（"用户在做什么"）+ avatar 待说的音频（"avatar 要怎么说"） |
| 表示 | 显式分解出**身份项**与**运动项**：身份项在整个对话中固定，模型只逐帧预测运动 |
| 生成 | 因果式扩散，按块向前滚动；块间用历史 offset 与缓存衔接 |
| 渲染 | 解码器用"固定身份项 + 当前运动项"出帧 |

### 三个模块

**运动潜空间编码（显式身份-运动分解）**：把一张图拆成"底片"和"滤镜"两张透明片——换表情只换滤镜，底片不动。好处有两层：一是把生成任务从"预测整帧像素"收缩成"预测运动增量"，二是身份项固定让**训练用视频、推理能用单图**成为可能。

**双路条件编码**：用户侧与 avatar 侧的输入格式不同，不能直接喂给生成器，所以先把两路编码成同一种条件——一路说"用户正在做什么"，一路说"avatar 这次要怎么说"。**这是它能生成听态画面、而不只是说话画面的原因。**

**因果流式生成**：按块向前滚动，每块生成完立即交给渲染器；块与块之间靠历史 offset 与 KV/条件缓存衔接（缓存超限弹出最旧）。为缓解严格因果带来的块边界抖动，训练期允许有限的 look-ahead，推理期用上一块的历史信息替代。生成端还用三路独立缓存并行比较"无条件 / 只有音频 / 完整条件"三种预测再合成，避免重复计算。

### 一个最容易误读的点

**给渲染器的运动接口是 512 维，但它落在最多 20 个独立方向的子空间里。** 看起来像 512 个"动作旋钮"，实际自由度只有 20 个——这个窄通道是**防身份泄漏**的设计：窄得装不下身份信息。所以讨论"加维度能不能提升细粒度控制"之前，要先确认瓶颈到底是表示容量，还是"从音频预测到运动"这一步。

### 与同类工作的差异

| 对比对象 | 表示 | 身份处理 | 生成范式 | 流式能力 |
|---|---|---|---|---|
| **AvatarForcing** | 身份项 + 运动项（接口 512 维，实际约 20 个独立方向） | 身份向量全程固定，与运动**相加** | 因果扩散，按块滚动、一步生成 | **原生流式**，支持打断与切换输入 |
| FLOAT（同血统） | 同样的显式分解 | 相加解耦 | 生成式，非为交互设计 | 无原生流式 |
| Ditto | 关键点 + 头姿/平移/表情（265 维） | 参考帧外观 + 关键点形变 | 运动空间扩散 + 快速渲染器 | 有（窗口式） |
| LivePortrait | 隐式关键点 | 参考图外观 + 形变搬运 | 无扩散（直接形变） | 有（轻量） |

### 训练策略要点

两阶段：先学"根据条件生成连续运动"，再用偏好微调偏向"更有交互反应"的样本——其中较好的样本来自**真实视频的运动**，较差样本来自只用音频条件生成的版本，因此在没有人工标注的情况下把"真实互动感"当成目标。数据侧用双人对话数据集，做场景切割、人脸裁剪到 512、语音分离（区分说话人与倾听方），并按 25fps / 16kHz 对齐。训练用单张 H100。

## 在我们体系中的角色

### 接入形态

作为 avatar 插件接入统一契约：设置形象、音频流进 / 视频流出、重置、上报帧率与输出尺寸；双向插件另外提供"用户音频 / 视频输入"的入口，支持听说双向会话。**契约统一是它能被替换进链路的前提**——编排层只看到一条统一的音视频流，模型内部差异由适配层吸收。

### 流式改造（我们做的）

把一次性批量生成改成连续流的**生产者 / 消费者**结构：逐块喂音频、连续出帧，缓存窗口有界。首块产出后即可持续出帧，并接入静默运行时（倾听态画面）。改造中踩到并修掉的问题包括：上游调用方的超时设置过短会扼杀首次加载、依赖版本与设备放置导致的初始化失败。

### 中文音频适配（我们做的）

原模型吃英文音频特征，中文接不上。做法不是在中文数据上重训主干，而是在**中文音频编码器与冻结主干之间加一座桥**：桥把中文特征翻译成主干熟悉的形式，主干保持冻结，避免有限的中文数据冲掉原有能力。三代桥各解决一个具体故障：**蒸馏桥**（接通特征空间）→ **几何约束桥**（帧对约束、防音节被压塌）→ **关系蒸馏**（保英文侧成对距离结构）。多域设置下的同步指标优于对照锚，但该实验同时改变了样本数量、来源域与身份多样性，只能读成"值得继续验证"。

### 微调形态与注入点（我们做的）

从"碰得最少"到"开放得最多"排了四档：全冻结+桥 / LoRA / 单层解冻 / 桥内 LoRA。结论是**注入点比 rank 更影响结果**（把增量挂在哪里带来的收益最大）；**全开放会让桥与主干失去配合**（为了训练集分数把桥改太多，主干收到不熟悉的输入，生成侧反而回退）；解冻单层的判据是找**历史空白区**（从未被微调过的组件）。

### 漂移诊断与治理（我们做的）

这个模型上最完整的一条实验线：

1. **诊断**：把每帧运动向量拆成"模长"和"方向"两个假说。测下来**模长撑开被否证**（模长没有持续增长），**方向游走在单身份长轨迹上得到支持**（持续转偏），所以治理方向优先约束方向
2. **治理裁决**：
   - **推理期锚点引导：有效**。用该身份的特征字典引导生成方向，长视频的身份相似度显著回升，且不需要重训、可随时开关
   - **训练期参考条件化：两轮失败**。第一轮失败原因是训练参考里混进了答案、条件只在最后一层注入；第二轮改成逐层注入多 seed 后同步反而退化，回退
   - **学习式锚力：终止**。身份指标更好，但人工观察出现头部抖动——**指标高不等于可用**
   - **把身份相似度当损失：放弃**。相似度确实改善，但管不住脸部尺度漂移；根因是身份相似度是标量，而漂移有模长、方向、尺度多个维度

### 结论文表格

| 项 | 结果 | 证据强度 | 边界 |
|---|---|---|---|
| 流式接入 | 可连续出帧并支持静默运行时 | 强（跑通并部署） | — |
| 中文音频适配 | 多域同步指标优于对照锚 | 弱（单次多域实验、混变量） | 不能归因成"数据量瓶颈" |
| 注入点结论 | 注入位置比 rank 更影响结果 | 中（有消融背书） | 限本轮中文域适配，非普适 |
| 全开放代价 | 生成侧回退，低于纯冻结桥 | 中（对照明确） | 低秩能减轻但不能超过纯桥 |
| 方向游走 | 单身份长轨迹支持 | 中（单身份） | 跨身份未验证 |
| 锚点引导 | 相似度显著回升、可开关 | 中（单身份） | 未写成通用部署默认值 |
| 训练期条件化 | 两轮失败并回退 | 中 | 同步会付"税" |
| 学习式锚力 | 终止（人眼头抖） | 中（指标 + 人工） | 指标≠体验 |
| 身份相似度当损失 | 放弃 | 弱（口述，无指标记录） | 管不住尺度漂移 |
