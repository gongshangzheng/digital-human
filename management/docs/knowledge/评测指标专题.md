## 一、先分清：有 GT、无 GT 与评测轨道

**GT（ground truth）** 是与生成结果配对的真实参考视频。有 GT 时可以算 PSNR、SSIM、LPIPS 等**有参**指标；没有配对 GT 时，这类重建指标不能使用，但仍可能可以计算唇同步、身份相似度或无参考画质指标，取决于该轨道提供什么输入。

**评测轨道**是固定场景与指标集合。例如 standard、cross_identity、listening、long_run、stress_test。不要仅凭“没有 GT”就写“只能用无参指标”：

- `cross_identity` 没有配对 GT，但配置中仍包含 sync_c、sync_d、csim、NR-IQA、时序类等指标；
- `listening` 的 `metrics` 为空，明确走人工评价；
- 是否运行某个指标以 `applies_to` 和轨道配置为准。

## 二、指标地图：问题 → 指标

| 问题 | 指标 | 方向与边界 |
|------|------|------------|
| 嘴型和声音对得上吗 | Sync-C / Sync-D | Sync-C 是置信度，越高越好；Sync-D 是音频/视频特征 L2 距离，越低越好 |
| 生成的人和参考是否一致 | CSIM、facesim_cur、CCIP 等 | 取决于真人/卡通域与参考模板口径 |
| 与 GT 的像素或感知差异 | PSNR、SSIM、LPIPS、TOPIQ-FR | 需要配对 GT；不等于主观质量的全部 |
| 没有参考图时画面质量如何 | NR-IQA（musiq_koniq、topiq_nr、arniqa、liqe 等） | 可按 512 人脸构图整帧、人脸裁剪、嘴唇裁剪运行 |
| 长时间后身份是否偏离 | CSIM-drift、LPIPS-drift | 关注相对参考的长期变化 |
| 相邻帧是否平滑 | Dino-S、flow_smoothness | Dino-S 是相邻帧 DINO 特征相似度，不是身份漂移指标 |
| 运动与表情是否合理 | SID、motion_magnitude、expression_nr/cls、THEval 动态指标 | 各指标覆盖不同局部行为 |
| 是否满足系统预算 | FPS、RTF、VRAM、GPU-Util、Throughput、Latency P50/P95/P99 | 需要同时看，不用单一 FPS 代表系统体验 |

## 三、两条评测路径，不能混口径

### 3.1 正式 `dh-eval` 路径

框架层会把输入和 GT 统一为 512×512 的头肩人脸构图（`crop_coeff=1.9`）。模型在已裁剪的输入上生成，正式评测时 pasteback 被关闭。指标层可能再次按各自需要裁脸、裁嘴或做 112×112/224×224 对齐。

因此“整帧”在本框架中指的是**整张 512×512 人脸构图帧**，不是原始全画面：

- SyncNet v2 会再做人脸检测并裁到 224×224；
- CSIM 会做五点对齐到 112×112；
- PSNR/SSIM、LPIPS、TOPIQ-FR 默认还会使用 face-margin；
- `musiq_koniq` 等 `crop_mode: frame` 指整张 512 构图。

### 3.2 speed-run 路径

speed-run 不走完整 orchestrator。素材在输入侧已预裁为 512×512 人脸构图，模型输出的 `output.mp4` 直接打分；没有额外的 `face.mp4` 层。身份模板在当前 `metrics-guide.md` 中说明为参考视频中间帧，但 `metrics.yaml` 仍留有“首帧”注释，二者存在配置/文档快照不一致。

因此写报告时必须注明采用的是哪条路径、哪一版 scorer 和哪一种身份模板，不能笼统说“口径已经完全统一”。

## 四、和参考实现对照时，哪些一致、哪些不一致

对 avatar_base 20 case 的对照显示：

- sync_c / sync_d / SID / expression_nr / flow_smoothness 的全量相关系数为 1.000，均值差绝对值不超过 0.006；
- CSIM 中间帧模板的单 case 冒烟样本逐像素 diff=0，数值 0.7868 一致；
- `musiq_koniq` **没有**与 guanmu 全面对齐：两边输入区域不同，当前记录的 corr 为 0.036。我们的口径是整张 512 人脸构图，guanmu 使用更紧的 face bbox crop。

对照的意义不是把所有指标强行调成相同数字，而是明确每个差异来自模型、输入区域还是测量实现。

## 五、指标如何指导排查

### 长视频身份下降

CSIM-drift 曲线能提示“身份随时间下降”，但不能单独说明原因。AF 的模长/夹角实验是下一步假设检验：当前 c1 单身份结果不支持范数持续撑开，并支持方向游走假说；是否能推广到其他身份仍待复核（见 [[knowledge/Avatar Forcing 微调实践|Avatar Forcing 微调实践]]）。

### 历史数值不能直接横比

统一裁剪口径改变后，同一视频的历史指标会显著变化。例如 musiq_koniq_face、musiq_koniq_lip、flow_smoothness 都有大幅变动；历史值应重建基线后再比较。不要用不同裁剪、不同模板或不同 SyncNet 版本下的高低分给模型排序。

## 面试追问预案

**Q：为什么不直接用一个总分评估数字人？**

因为没有一个指标同时覆盖身份、唇同步、动作、画质和实时性。PSNR 高不代表口型对，Sync-C 高不代表身份稳定，RTF 小于 1 也不代表浏览器不会卡。总分只有在明确场景权重、素材和口径后才有意义；日常评测更可靠的做法是先按问题分组，再解释指标之间是否一致。

**Q：为什么 cross_identity 没有 GT 还能算 Sync-C 和 CSIM？**

“没有 GT”指没有与生成视频一一配对的目标视频，因此不能计算 PSNR/SSIM 一类重建误差。但 cross_identity 仍有驱动音频和参考身份资产：SyncNet 可以比较输出嘴型与驱动音频，CSIM 可以比较输出和参考身份。listening 轨道则不同，它配置了空指标列表，交给人工按自然反应、眨眼、头动和 turn-taking 评价。

**Q：Dino-S 和 CSIM-drift 为什么不能互相替代？**

Dino-S 比较相邻帧，主要看帧间是否突变或闪烁；CSIM-drift 比较生成帧与身份参考，主要看“这个人是否逐渐变成另一个人”。一个视频可以非常平滑地缓慢变脸，也可以身份不变但帧间抖动严重，所以两者必须分开。
