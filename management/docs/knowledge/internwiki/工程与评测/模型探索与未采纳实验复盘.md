> 这不是“失败模型名单”。模型在一次实验里输出偏糊，可能是模型能力、资产、音频、分辨率、显存预算或参数设置共同造成的。本文记录的是**当前证据下为何暂不选用**，并保留复跑后推翻结论的入口。项目背景见 [[project:digital-human]]；评测口径见 [评测指标专题](评测指标专题.md)，输入准备见 [数据集整理专题](数据集整理专题.md)。

## 一、为什么要记录未采用的实验

只保留最终选中的模型，会让后续人重复踩同样的坑：不知道某个模型是没跑通、跑通但不适配当前场景，还是只是当时对照条件不公平。

未采用实验至少能回答三件事：

1. 当时到底跑了什么，哪些条件还缺失；
2. 当前不采用的依据是什么，依据强到什么程度；
3. 下一次复跑怎样才能让结果可比较，而不是再得到一段无法解释的 demo。

## 二、状态不是标签，而是证据等级

```mermaid
flowchart LR
    A[待复跑<br/>有口头或初步观察] --> B[初步观察<br/>已有输出但对照不完整]
    B --> C[已复现<br/>同协议重复得到一致现象]
    C --> D[已否决<br/>当前场景决定不采用]
    B --> A[补齐条件后重跑]
    C --> B[新证据与旧结论不一致]
```

| 状态 | 含义 | 可以写什么 | 不可以写什么 |
|------|------|------------|--------------|
| **待复跑** | 只有口头或初步观察 | 观察原话、待补字段、复跑计划 | 分数、模型排序、最终结论 |
| **初步观察** | 已有输出，但对照不完整 | 可见现象和运行条件 | “优于/不如”这种跨模型结论 |
| **已复现** | 同协议重复得到一致现象 | 现象、证据路径、影响范围 | 超出已测场景的泛化结论 |
| **已否决** | 在明确场景和证据下，当前决定不采用 | 决策范围、替代方案、保留条件 | “该模型永远不可用” |

状态可以向前推进，也可以因复跑结果回退。`已否决` 的意思只是“在当前场景暂不采用”，不是永久盖棺定论。

## 三、可复现协议：比较前先对齐什么

两段输出只有在下列条件对齐后，才可以讨论“谁更好”：

| 条件 | 复跑时要记录 |
|------|--------------|
| 身份资产 | 同一参考图片/视频，或明确资产差异 |
| 驱动音频 | 同一文件、同一裁剪和 offset 口径 |
| 输出规格 | 分辨率、帧率、时长、是否 pasteback |
| 资源预算 | GPU 型号、显存、并发情况、推理精度 |
| 关键参数 | 模型版本、checkpoint、采样步数、随机种子、控制开关 |
| 观察维度 | 画质、身份、唇同步、动作、时序、首帧/RTF/显存 |

无法完全对齐时，也可以记录实验，但必须把差异写出来，结论只限这一次运行。模型没输出、依赖没装好或显存 OOM 时，记录为**配置/部署问题**，不能评价模型本身的质量。

## 四、模型记录模板

后续每条记录按以下字段补充：

| 字段 | 内容 |
|------|------|
| 模型 / 版本 / 来源 | 名称、commit/checkpoint/仓库 |
| 当前状态 | 待复跑 / 初步观察 / 已复现 / 已否决 |
| 目标场景 | 要解决什么问题 |
| 输入与输出规格 | 身份资产、驱动音频、音频采样率（如16kHz）、分辨率、视频帧率（如25fps）、时长 |
| 硬件与参数 | GPU、显存、精度、采样/控制参数 |
| 对照对象 | 例如 Avatar Forcing，及是否同协议 |
| 观察 | 画质、身份、唇同步、动作、时序、速度分别记录 |
| 证据路径 | 日志、视频、指标 JSON、截图；未知则标 `待补` |
| 当前结论 | 只写当前证据支持的范围 |
| 下一步 | 复跑、调参、换资产、补指标或停止 |

## 六、复跑清单

复跑前逐项确认：

- [ ] 固定身份资产与驱动音频路径
- [ ] 记录音频采样率（例如16kHz）与视频帧率（例如25fps）；两者不是同一单位，并确认音频-视频窗口对齐方式
- [ ] 记录模型版本、checkpoint、命令和关键参数
- [ ] 记录 GPU、可用显存、精度和是否有其他任务争用
- [ ] 对齐输出分辨率、帧率、时长和 pasteback 设定
- [ ] 保存原始输出、日志和对应指标 JSON
- [ ] 在 [评测指标专题](评测指标专题.md) 规定的同一口径下打分
- [ ] 标注哪些维度可比、哪些仍不可比
- [ ] 复跑后更新状态；若无法复现原观察，撤回或降级旧结论

## 七、面试追问预案

**Q：为什么要专门记录没选用的模型？这不是浪费时间吗？**

不是。模型选型不是只看最终冠军：被排除的方案能说明比较过什么、排除了哪些变量、当前结论的边界在哪里。更重要的是，未采用不等于失败——如果以后换了资产、场景或资源预算，这份记录可以防止团队把一次不公平比较当成永久结论。

**Q：一次模型输出偏糊，为什么不能直接说模型效果差？**

“糊”是现象，不是原因。可能来自模型、低分辨率输入、错误 checkpoint、显存不足导致的降级、后处理或编码。只有同资产、同音频、同输出规格下复现，才能把现象与模型能力更可靠地关联；即使如此，结论也只覆盖测过的场景。

**Q：主观观察和客观指标冲突时听谁的？**

先查口径。指标可能只测唇同步或人脸裁剪区域，主观观察可能在看全身动作、背景或编码伪影；它们本来就不一定冲突。记录时分开写“看到什么”和“指标测到什么”，再决定要补哪个指标或人工评审，不用单一分数替代全部体验。
