## 一、问题：视频源双重驱动

视频源模式和单图模式不同：模型每一帧都会读取源视频。这样一来，源视频本来就在张合的嘴，可能绕过音频驱动直接出现在输出里；音频让嘴往一个方向动，源纹理又把它拉向另一个方向，最后就像“嘴在乱动”。

我们沿着“运动数据从哪来、外观纹理从哪来、骨架从哪来”三条路径排查：

| 路径 | 它怎样把源嘴动带进输出 |
|------|------------------------|
| exp 唇通道 | 逐帧参考的表情偏移直接混入驱动运动 |
| warp 源外观 f_s | 每帧源纹理本身就带着源嘴形，且会主导最终渲染 |
| x_d kp 回填 | 生成向量不含 kp，回填逻辑使用逐帧源帧 kp；源张嘴时下颌骨架位移也被带入 |

后文会用到的符号：x_d 是音频生成的驱动运动（265 维 = scale + 66×3 pose + t + 63 exp）；x_s 是源帧关键点；f_s 是源外观特征；M_c2o 是从 canonical crop 贴回原图的仿射变换；kp 是 21 点基准骨架。

## 二、从尝试到收敛：方案、观察与结论

### v1：只改运动通道

**方案**：把 exp 唇通道（行 [6,12,14,17,19,20]）的基底换成源首帧，只保留音频 delta。

**观察**：画面里的源嘴动几乎没有变少。逐帧 warp 的源外观 f_s 仍带着源嘴纹理：运动数据虽然改了，外观通道还在把原嘴形画出来。

**结论**：只隔离运动通道不够，主导泄露的是外观通道。

### v2：把外观也固定到首帧

**方案**：把 warp 使用的 f_s / x_s 整帧固定为**源首帧**，等同于把外观退回图像驱动形态；头动仍由 x_d 的逐帧 pose 承载。

**观察与结论**：v2 消除了外观通道的泄露，因此用户终裁保留这条方向并将代码回退到 v2 形态；但当时仍观察到变糊、眼神呆板和贴回观感问题，后续计划分别交给 LoRA 与 alignment 处理。最终的人眼对比判定仍待补齐，不能写成“已完全通过”。

### v3 / v4（均否决回滚）

- v3 嘴区像素合成：嘴区羽化替换首帧后重提 f_s，人工判定出现变糊、眼神呆滞和贴回观感问题，因此否决
- v4 生成式两遍：先隔离再重生成，仍无法消除外观通道泄露，复杂度也不值得，因此否决

最初曾把 v3 的问题归因于“帧 0 crop 配帧 t 的 M_c2o”，但代码复核后已撤回：`decode_f3d` 输出统一 canonical 512 栅格，贴回原帧时使用 `M_c2o[t]` 本来就是正确选择。v3 的视觉问题存在，但该坐标系归因未被证实。

### kp 回填泄露修复

**问题**：`_mix_s_d_info` 用逐帧源帧 kp 回填——源视频张嘴时下颌骨架（含嘴部 6 点）逐帧位移，把源嘴几何带进生成目标。

**修复**：`x_d["kp"]` 钉回首帧骨架（`x_s0_kp`），头动由逐帧 pose 旋转承载，理论无损失。

**效果**：LSE-C 3.74 → **4.87**（+30%）。

### 前 3.2 秒音画错位：已排查、尚未定因

用户观察到开头约 3.2 秒存在音画不齐。我们曾假设 HuBERT 左上下文的静音垫会稀释首窗特征，于是在 `inference.py` 前置 15 帧静音垫、提特征后丢弃对应帧。

这个方案复测后无效：0–3 秒分窗 LSE 只改善 0.09，人工观察也没有看到变化，因此已回滚。后续的首窗锚值、首窗二次生成与 `M_c2o` 贴回几何假设也被逐一否定或撤回。当前只能确认问题仍待通过固定随机种子的参考帧一致性/预热窗实验继续定位，不能宣称已经修复。

## 三、指标总表

这里用 LSE（lip-sync error）看口型与音频是否对齐：**LSE-C 越高越好**，表示同步置信度更高；**LSE-D 越低越好**，表示两者距离更近。两项一起看，避免只凭单一数字判断。

| 版本 | LSE-C ↑ | LSE-D ↓ |
|------|---------|---------|
| baseline（未隔离） | 3.44 | 11.12 |
| v2 整帧钉首帧 | 3.74 | 10.93 |
| v2 + kp 修复 | **4.87** | **8.81** |
| 单图模式上限（参考） | 5.01 | 8.75 |

这组数来自 videoc1 + audio_mid_man 的单 case 复测：kpfix 与单图参考只差 0.15 的 LSE-C 和 0.06 的 LSE-D，说明该样本的技术指标已接近单图上限。跨素材指标覆盖和最终人工对比判定仍待完成，因此不能概括为所有视频源模式都已追平单图。

## 四、后续尝试：从内部修到闭嘴源预处理

### 4.1 AppearanceExtractor-only LoRA：已否决

该路线的指标看似改善：LSE-C **3.85→4.71**。但人工确认的现象是嘴部变糊，源嘴动泄露没有消失。因此它被标为**已否决**：同步分数上升不等于泄露已经解决，也不等于画面可用。

### 4.2 闭嘴源管线：LatentSync 是当前有证据的路线

直接在 Ditto 内部切断外观、骨架和表情回灌很难彻底消除源嘴动，于是将问题前移：先把视频源处理成中性/闭嘴状态，再交给 Ditto 用目标音频生成嘴动。

| 方案 | 结果 | 状态 |
|---|---|---|
| LP v1 | 开合 `20.0≈源19.8`、相关 `0.612`、LSE-C `3.52<3.85` | 已失败 |
| LatentSync 闭嘴源 | 源嘴动相关 `0.005`、LSE-C `5.47` | 当前有证据的闭嘴化方案 |
| LP v2 | 尚未验收 | 待验证 |

LatentSync 是当前实现，不是唯一可行方案。真正需要保留的是“先中性化源嘴，再让目标音频驱动”的工程思路；后续可替换为更轻或更稳定的闭嘴化方法。详细模块边界见 [音画同步专题](../工程与评测/音画同步专题.md)。

### 4.3 Renderer-LoRA：指标门通过，人工与多素材未完成

Renderer-LoRA 的 guard1300 实验中，LSE-C **3.739→4.762**、LSE-D **11.859→10.876**，但 CSIM **−0.021**。当前仅能写“指标门完成”；人工观察和多素材门尚未完成，不能据此认定画质/泄露问题已解决。

## 五、工程形态

改动收敛为一个开关：`isolate_source_mouth`，**默认关**，仅视频源模式生效，**不改任何权重**——纯推理期管线改动，可随时回退。

## 面试追问预案

**Q：为什么 v2 整帧钉首帧反而比 v3 精细修补效果好？**

v3 的思路是“只修嘴区，其余保留视频源信息”，但人工观察到变糊、眼神呆滞和贴回观感问题；v4 也没能消除外观通道泄露，因此两条方案都被否决。最初曾将 v3 问题归因于帧 0 与帧 t 的 M_c2o 不匹配，但代码复核确认 `M_c2o[t]` 本来就是正确贴回变换，该归因已撤回。能确认的结论只有：v2 在表示/外观输入层固定首帧的方向能消除泄露；像素级替换的视觉问题仍需另行定位，不能用未经证实的坐标系解释。

**Q：怎么确认"泄露"确实存在，而不是模型本身的口型误差？**

对照实验：用噪声驱动（无音频信号）跑 baseline，源视频张嘴时输出嘴仍跟随开合——这说明嘴动来自源视频而不是音频，泄露成立；开隔离后输出近似静止。定量复核：嘴动相关系数 0.995。**先复现现象，再谈修复**——和 Avatar Forcing 漂移定位实验（[微调实践](Avatar%20Forcing%20微调实践.md)）是同一套方法论。

**Q：既然 isolate 效果这么好，为什么默认关闭？**

两个原因。一是默认路径的回归口径：Ditto DDIM 无种子非确定，逐像素一致不可达，我们以"同码重跑方差"为标尺验证了默认路径无可测差异——改动不破坏原行为。二是功能定位：隔离是为"视频源 + 音频驱动"这个特定组合设计的，单图模式用户不需要。默认关、按需开，是推理期改动最安全的发布方式。
