## Context

`management/docs/数字人概述/数字人领域问题` 的「一、身份」由四个小节组成，它们在收尾处反复指向同一个结论：

- 「身份一致性：长视频为什么会漂」结尾原话是"**还没有一个跨时长、跨机位、跨风格的统一判据**"；
- 「切分镜与多视角」结尾指出"跨机位一致性还没有形成普遍协议"；
- 「风格化」结尾指出"风格化程度没有连续尺子"；
- 「多参考注入」结尾指出"训练代价、姿态覆盖、风格化定义和跨视角度量仍相互牵制"。

四处都在说"缺一把尺子"，但整章没有回答这把尺子**应该满足什么条件**。同时新提交的 [[技术介绍/face-verification-models|人脸身份验证模型]] 已经建立了判断依据：现有身份判定手段全部是**借来的**（照片域人脸识别编码器、感知类度量、结构/生成类探针），它们的训练目标是"两张真实照片是否同一人"，与数字人要回答的"生成帧是否仍是同一个角色"不同构。失效的根因不是精度不够，而是**敏感的方向错位**。

因此本变更在「一、身份」章末补一个小节：把"缺一个数字人专用的身份一致性判别器"写成明确命题，并把该判别器需要满足的条件（对什么不敏感、对什么必须敏感、输出什么、按什么协议验收）写成可讨论的规格。

## Goals / Non-Goals

**Goals:**

- 讲清"缺的是什么"：不是更准的人脸识别编码器，而是**目标函数与数字人任务对齐的判别器**；现有手段的失效是敏感方向错位，不是精度不足。
- 给出**不变性清单**：口型、表情、姿态、说话风格、机位、光照背景、风格与风格化强度、正常时间演化——这些是合法变化，判别器不应因此扣分。
- 给出**敏感性清单**：换人与几何漂移、画质劣化、尺度漂移、遮挡塌陷、跨机位外观重置、多人身份归属错误，以及时序漂移的起始时刻与加速度——这些必须给出负面评价。
- 明确最容易做错的一条：**"对画质敏感"与"对身份敏感"是两条不同的敏感轴**，必须分开输出。低质帧应被判为"不可信/不可用"并被下游抑制，而不是被判成"换人了"，也不应该是"照样高分"。
- 给出输出形态（三通道：身份一致性 / 质量可信度 / 时序漂移量）与验收协议（风格化强度轴、视频长度轴、跨编码器方差、反度量循环性、人类判定作锚）。
- 为这条支线给出可复用的已有素材与未决代价（数据瓶颈、虚拟角色无真人对应、底座选型待实验），使后续可以据此立项。

**Non-Goals:**

- 不设计具体模型结构、损失函数或训练方案；本文档是**领域问题**文档，只写"需要满足什么"，不写"怎么实现"。
- 不重复「一、身份」既有小节已给出的数字与结论（六个量尺分歧 2.7 倍、StyleID 的 0.37→0.74、未见身份 CSIM 约 0.85、跨机位数据 7/16/9 视角等），需要时以指向代替复述。
- 不引入正式参考文献列表：全文风格是"内联点名 + 数字"，新小节保持一致，不新增 `参考来源` 段落。
- 不修改其余五章（动作、实时性、路线、条件与任务定义、跨域问题）的任何内容。
- 不写合规/风控（换脸冒用检测）——那属于「六、跨域问题」，本节只涉及生成质量判据。

## Decisions

### 1. 落点、标题与篇幅

- **落点**：`management/docs/数字人概述/数字人领域问题.md`，「一、身份」章末，即「风格化」小节之后。理由：该节是整章的收口，需要先有长视频漂移、多视角、说话风格、风格化四处铺垫，才能说"所以缺一把什么样的尺子"。
- **标题**（二选一，待用户确认）：
  - **A（推荐）** `### 身份一致性判别器：缺的是什么，要满足什么条件`
  - B `### 缺一个数字人专用的身份一致性判别器`
  推荐 A 的理由：与本章既有命名风格（"音唇同步：嘴对得上为什么仍然难"）一致，且标题即结论，不把"缺"写成抱怨。
- **篇幅**：与本章其余小节同量级，约 5 段正文 + 1 张两栏对照表 + 1 张 Mermaid，不膨胀成独立文档。不新增 `##` 级标题，不改章节编号。
- **元数据**：`数字人领域问题.md` 的 `title` / `order` / `tags` / `summary` 是否更新，取决于是否要在 `summary` 中补"专用判别器"这一项；默认只把 `summary` 从"身份、动作、实时性……"末尾补一句"身份判据的缺口"，其余不动。

### 2. 小节内容规格（六段）

**段 1 · 缺口：现有判定手段都是借来的。** 三类借用各有一处错位：照片域人脸识别编码器在风格化与尺度漂移上失效；感知类度量身份不可知（换了人但场景构图不变照样高分）；结构/生成类探针只探嵌入容量，不产出可排名的分数。非照片域的身份判定这条支线**确实存在**（卡通/动漫人脸识别：Cartoon Face Recognition 基准与后续的图拼图解法、Anime Style Recognition 基准），但它服务的是"检索既有作品里的角色"，没有接到生成管线上，也不含时序与质量；面向生成的身份编码器（BlendFace）只解决"身份表示不泄漏属性"，本身不做判别。结论：**缺的不是精度，是敏感方向对齐的判别器。**

**段 2 · 不变性清单：这些是合法变化，扣分就是错。** 表格呈现"变化类型 / 在数字人里的剧烈程度 / 期望行为"：

| 变化类型 | 在数字人里的剧烈程度 | 期望行为 |
|---|---|---|
| 口型与嘴部形变 | 音素级，一秒内大幅变化 | 不敏感 |
| 表情（含夸张表情） | 眉眼嘴大范围形变 | 不敏感 |
| 姿态 / 头动 / 大角度侧脸 | 跨分镜可达侧脸甚至后脑 | 不敏感 |
| 说话风格（点头节奏、眨眼频率） | 分钟级个体习惯 | 不敏感 |
| 机位 / 焦距 / 构图 | 跨分镜剧烈变化 | 不敏感 |
| 光照 / 色温 / 背景 | 场景切换级变化 | 不敏感 |
| 渲染风格与风格化强度 | 写实 ↔ 卡通 ↔ 手绘连续变化 | 不敏感 |
| 正常时间演化 | 长视频内的自然渐变 | 不敏感 |

**段 3 · 敏感性清单：这些必须给出负面评价。** 同样用表格，与段 2 形成对照：

| 变化类型 | 具体形态 | 期望行为 |
|---|---|---|
| 换人与几何漂移 | 五官比例、脸型、发际线偏移 | 强敏感，给负分 |
| **画质劣化** | 模糊、失焦、压缩伪影、噪点、低分辨率 | 强敏感，但走**质量通道**给负分 |
| 尺度漂移 | 脸忽大忽小、越变越大 | 敏感（现有余弦度量对此是盲的） |
| 遮挡与局部塌陷 | 伪影、五官糊成一团 | 敏感 |
| 跨机位外观重置 | 发际线、五官比例、服饰纹理无规律跳变 | 敏感，同时容忍合理相机变化 |
| 多人身份归属错误 | 张三的脸长在李四身上 | 敏感 |
| 时序漂移量 | 起始时刻、加速度，而非平均值 | 必须作为独立量输出 |

**段 4 · 两条敏感轴必须分开（本节最重要的判据）。** 若把"画质"与"身份"揉进同一个标量，两种错误必然同时出现：把模糊判成"换人了"（假阳性，会诱导去改身份通道来修清晰度）；把模糊判成"一致"（假阴性，这正是当前 CSIM 的行为）。因此输出至少三通道：

- **身份一致性**：对段 2 不敏感、对段 3 中的身份类变化敏感；
- **质量可信度**：对画质劣化单调下降，用于把低质帧标记为"不可信"，从而在选帧、加权、拒识等下游环节被**抑制**，而不是被当成身份证据；
- **时序漂移量**：模长 / 方向 / 尺度三条曲线与漂移起始点。

并给出 Mermaid：合法变化与非法变化分别进入"应忽略"与"应惩罚"两支，非法变化再分为"身份轴"与"质量轴"，最终汇聚到三通道输出。

**段 5 · 验收协议：怎么算这把尺子合格。** 四条硬性要求：风格化强度轴必须是**连续**的（不能把高度抽象的角色排除在测试外）；必须有**视频长度轴**（单帧分数看不到漂移）；必须报告**跨编码器与跨协议方差**（已有实测证据表明换尺子会翻转排名）；必须做**反度量循环性**检查（不允许"更会讨好这把尺子"得高分）。人类判定作为锚——已有可复用素材：StyleID 的感知校准数据与评测框架、ID-Sim 的 selective sensitivity 公理、MagFace 用嵌入模长编码质量的做法、FCB 的协议反转证据、Cartoon Face Recognition 系列的数据设定。

**段 6 · 代价与未决。** 数据是瓶颈：需要"同一数字人跨风格、跨动作、跨机位"的成对标注，这类配对数据的构建成本高于通用人脸识别；虚拟角色的"身份"可能没有真人对应，判别对象实际上是**角色同一性**，这与真人核验是不同任务；底座选型（语义基座微调 vs 人脸识别基座微调）尚无定论，StyleID 的实验显示语义基座更鲁棒，但样本量只有一组。这些未决项就是后续立项要回答的问题。

## Risks / Trade-offs

- [与既有小节重复] → 既有小节已给的数字一律不复述；本节只增加"不变性/敏感性清单"与"两条敏感轴"这两块新内容，其余以指向处理。
- [把领域问题写成方案设计] → Non-Goals 明确不写结构、损失与训练方案；正文只出现"应满足的条件"，不出现"可以怎么做"的具体架构。
- [清单被当成主观偏好] → 每一条都给出"在数字人里剧烈程度"这一列，把"为什么它属合法变化"落到场景事实上；不确定性（如风格化程度到哪算改变身份定义）显式标为未决。
- [新增引用未经全文核实] → 本节只做内联点名，不引用具体数值；表中 9 篇均已核实到书目级，若正文需要其数字，须先开 VPN 补全并回写白名单。
- [章末小节过长破坏本章节奏] → 控制在 5 段 + 2 表 + 1 图的量级，与其余小节持平。

## 长期演进约定（本 change 不归档）

「数字人领域问题」不是交付即冻结的文档，而是一份**持续积累的问题清单**。因此：

1. **本 change 保持 open**，不归档；后续发现新的领域问题时，直接在同一 change 内追加：design 里追加新的小节规格、tasks 里追加新的任务组，不另开 change。
2. **新条目的形式约定**：每个问题条目仍用 `###` 级标题，命名遵循本章风格（现象 + 为什么会难 / 缺什么），控制在 5 段以内并至少带一张表或图，避免单条膨胀。
3. **新增外部引用仍需先核实到书目级**，并回写 design 的引用白名单；未核实的编号不得写入正文。
4. **既有条目只增不改**：新条目不得复述已有数字；如需修正旧条目的事实，单独说明并保留原口径痕迹。
5. **完成判据**：本 change 没有"全部任务完成"这个终点——tasks 勾选只代表当轮补充已落地。是否归档由用户单独决定，不由 tasks 全勾自动触发。
6. 如未来条目多到难以导航，再单独提一个 change 把它拆成多个文档或加目录，不在本 change 里预先重构。
