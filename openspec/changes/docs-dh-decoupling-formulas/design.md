## Context

"身份与运动可分解"这一族有两种具体写法，此前文档只写了其中一种：

| 写法 | 公式 | 落在哪 | 谁 |
|---|---|---|---|
| **隐空间加法** | $z = z_S + m_S$（$z_S$ 512D 每步恒等） | 表示层 | FLOAT / Avatar Forcing |
| **关键点变换** | LivePortrait：$x = s\cdot(x_c R + \delta) + t$ | 关键点空间 | LivePortrait / Ditto |
| **关键点变换（改次序）** | PerformRecast：$x = s\cdot((x_c + \delta) R) + t$ | 关键点空间 | PerformRecast |

三者的关系：前两者是"两种不同的分解方式"，后两者是"**同一种方式里次序对不对**"。

- LivePortrait 式**先乘头姿、再加表情** ⇒ 表情形变被头姿旋转"污染"，"只改表情、头不动"做不到；
- PerformRecast 式**先加表情、再乘头姿**，与 FLAME 前向一致（表情是规范空间的形变、头姿是整体旋转）⇒ 继承 3DMM 的自然解耦。

**要点**：**"可分解"不只是"分成两项"，还要问"两项以什么方式组合"**；次序/位置错了，分解名存实亡。

## Goals / Non-Goals

**Goals：** 在身份与动作两份文档里补上这条对比；把"次序"这一层作为"可分解"的第三个维度点明；交叉引用三篇论文笔记。

**Non-Goals：** 不重写既有小节结构；不改既有数字；不为 PerformRecast 复述方法细节（那在论文笔记里）。
