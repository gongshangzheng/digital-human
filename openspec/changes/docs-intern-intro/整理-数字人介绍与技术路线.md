## 一、数字人是什么（概念层）

### 1.1 两层划分【已验证·《数字人基础》§一】

- **数字人（模型）**：给定输入生成可控形象的技术问题
- **数字人系统**：ASR + LLM + TTS + Avatar 渲染的级联产品形态

一句话定义（《5分钟认识数字人》）：**用可驱动的形象，把语音/文本变成会说话、有表情的画面。**

### 1.2 三个基础判断问题【已验证·《数字人基础》§二】

1. 表现质量 — 像不像、自然不自然
2. 表现范围 — 只动嘴 / 带头姿表情 / 带身体手势
3. 工程性能 — 能不能实时、要多少算力

### 1.3 常见任务名称【已验证】

| 名称 | 范围 |
|------|------|
| 换嘴配音（lip sync） | 只改说话口型 |
| talking head | 头像说话 + 表情头动 |
| 3D avatar | 可驱动三维资产生成形象 |

## 二、为什么重要（价值层）

- 应用形态：会议面试官数字人（本项目）、虚拟客服、直播主播、陪伴 Agent【已验证·project-README】
- 产业价值：把"AI 回复"从文字/语音升级为"可见的面对面交互"；对话式产品的最强临场感载体【推断】
- 技术价值：数字人是多模态（语音理解→语言生成→语音合成→视觉生成）端到端系统的集成试炼场【推断】
- 关键约束：实时性决定可用性（对话场景 <1s 级 TTFF 才自然）【已验证·《数字人基础》§五】

## 三、主要技术路线（现行做法）

### 3.0 框架对勘【重要·需用户确认】

**用户口径**：三条路线 — 视频基本模型 / 动作空间扩散模型 / 3D GS 模型。

**knowledge《数字人基础》口径**：**两条轴**，且明确反对把它们当成互斥路线：

| 轴 | 取值 | 代表 |
|----|------|------|
| **生成方式**（模型直接预测什么） | ① 局部换嘴（嘴部 ROI） | Wav2Lip、MuseTalk |
| | ② 动作空间生成（低维运动序列） | SadTalker、VASA-1、Ditto、Avatar Forcing |
| | ③ 整帧视频生成（视频 latent / 帧） | FlashHead、LiveAvatar、Self-Forcing |
| **渲染/资产后端**（画面靠什么落地） | ① 2D 参考图/视频外观渲染 | 多数 2D talking head |
| | ② 可驱动 3D 资产（rigged mesh / NeRF / 3DGS） | LAM、FlexAvatar、UIKA |

原文关键句【已验证】："生成方式与渲染后端可自由组合，不能混成互斥路线。动作空间模型既可以配 2D renderer，也可以配 FLAME、NeRF 或 3DGS。"

**建议正文处理**（D1）：以用户的三路线为主叙述框架（读者直觉友好），但：
1. 显式说明三路线描述的是"生成方式"这条轴，渲染后端可自由组合；
2. "视频基座模型"对应"整帧视频生成"，"动作空间扩散"对应"动作空间生成"，"3D GS"主要是**渲染后端**选择（可与动作空间或整帧生成组合，如 LAM = FLAME 动作驱动 3DGS）；
3. 附两条轴的小图说明组合关系。

> ⚠️ 待用户确认：正文是否采用"三路线 + 两轴说明"的混合框架，还是改叫"两类生成方式 + 一类渲染后端"。

### 3.1 路线一：视频基座模型（整帧视频生成）【已验证】

做法：直接在视频 latent / 帧空间生成，模型同时负责身份纹理、动作与背景。

代表模型（papers 库互链）：

| 模型 | slug | 一句话 | 时间 |
|------|------|--------|------|
| FlashHead | paper-soulx-flashhead | Oracle-guided 无限时长生成 | 2025 |
| LiveAvatar | live-avatar-paper | 流式实时音频驱动 avatar | 2024 |
| Hallo3 | paper-hallo3 | 高动态真实肖像动画 | 2024 |
| HunyuanVideo-Avatar | paper-hunyuan-avatar | 高保真音频驱动人体 avatar | 2025 |
| OmniAvatar | paper-omniavatar | 高效音频驱动 avatar 视频生成 | 2025 |
| Wan-Streamer | wan-streamer-2026 | 端到端实时交互生成 | 2026 |
| OmniMate | omnimate-2026 | 开放式实时流式音视频 | 2026 |
| LeapTalk | leaptalk-2026 | 延迟-质量权衡突破 | 2026 |

优点：表现范围大（身体/背景/场景）、上限高、可零样本泛化到未见形象。
缺点：每帧重算身份纹理与背景，算力浪费；长时稳定性与实时化困难（领域级挑战【已验证·survey-map】："扩散路线的实时化困难"）。

### 3.2 路线二：动作空间扩散模型【已验证】

做法：把"身份外观"与"运动"解耦——模型只预测低维运动序列（Ditto 仅 265 维），渲染器负责把运动作用到参考身份上。

代表模型：

| 模型 | slug | 运动表示 / 特点 |
|------|------|----------------|
| Ditto | paper-ditto | HuBERT→LMDM 运动隐空间扩散，贴回源人脸 |
| Avatar Forcing | avatarforcing-2026 | FLOAT motion latent 显式分解 + 因果 Diffusion Forcing，双向听说 |
| VASA-1 | paper-vasa1 | 3D 面部 latent 生成 |
| SadTalker | paper-sadtalker | 3DMM 系数（经典基线） |
| EMO2 | paper-emo2 | 表情可控 |
| Teller | paper-teller | 自回归运动 token 流式 |
| X-Portrait | paper-x-portrait | 层次化运动迁移 |
| AniPortrait | paper-aniportrait | 音频→3D 关键点→渲染 |
| MuseTalk | paper-musetalk | 实时换嘴（局部 ROI） |
| LatentSync | paper-latentsync | 潜在扩散唇形同步 |
| JoyVASA | paper-joyvasa | 扩散式肖像/动物动画 |
| UniLS | unils-2024 | 统一听说端到端 |

优点：算力集中花在"怎么动"、便于实时与控制（Ditto RTF 可压到 <1；AF 天然因果流式）【已验证】；身份纹理由渲染器保留，一致性有第二重保障。
缺点：效果上限受运动表示与渲染器限制；需要生成身体/复杂背景时仍要回到整帧路线【已验证】。

### 3.3 路线三：3D GS 模型（渲染后端）【已验证】

做法：以 3D Gaussian Splatting 作为可驱动 3D 资产/渲染器，动作参数（FLAME 等）驱动高斯渲染。

NeRF → 3DGS 成本演进【已验证·《数字人基础》】：

| 工作 | 训练成本 | FPS |
|------|---------|-----|
| AD-NeRF | 167.6h | 0.04 |
| ER-NeRF | — | 15.2 |
| EGSTalker | 3.7h | 68.5 |
| GSTalker | 40min | 125 |

关键变化：从 NeRF 体采样转向 3DGS 光栅化，训练/渲染成本数量级下降。

代表模型与实测（VFHQ-Test，3D Portrait Animation）【已验证·《3dgs-methods-research》】：

| 模型 | slug | PSNR↑ | SSIM↑ | LPIPS↓ | CSIM↑ | A10 可行性 | 接入状态 |
|------|------|-------|-------|--------|-------|-----------|---------|
| GAGAvatar | — | 21.83 | 0.818 | 0.122 | 0.816 | — | — |
| LAM | lam-2025 | 22.65 | 0.829 | 0.109 | 0.822 | — | — |
| FlexAvatar | flexavatar-2025 | **23.47** | **0.837** | **0.099** | **0.830** | ✅ 可行 | 已接入 |
| HyperGaussians | hypergaussians-2025 | 增强模块 | | | | ✅ 可行 | 可作增强 |
| MATCH | match-2026 | 多视角输入 | | | | ❌ 需多视角+SM90 | 不接入 |
| AniGS | anigs-2024 | 单图全身 | | | | ⚠️ 显存高 | 参考价值 |
| UIKA | uika-2026 | 免位姿快速头部 avatar | | | | — | 主线候选 |
| LHM | lhm-2025 | 单图可动画人体重建 | | | | — | — |
| EmoTaG | emotag-2026 | 情绪感知高斯说话头 | | | | — | — |

优点：前馈式方法可单图秒级建 avatar（UIKA/MATCH 10× 加速）【已验证】；渲染成本低、可自由视角。
缺点：需要采集/拟合，泛化与拓扑处理复杂；MATCH 类需多视角+新硬件；全身方案（AniGS）显存要求高。

## 四、数字人系统与实时性（现行做法）【已验证·《数字人基础》§四/§五】

- 级联四组件：ASR → LLM → TTS → Avatar 渲染
- 三种架构：级联（可控、延迟高）vs 端到端（A2-LLM TTFA 535ms）vs 混合
- 流式级联全链路约 **3.2s**；差距来自分块等待与组件排队
- 传输层：实时交互基本必选 WebRTC（jitter buffer / NetEQ / 抗弱网）
- 推理层：流式 TTS 分块 + Avatar 异步渲染；轻量技巧（滑窗重叠融合、静音回退中性口型、说话/静音状态机）
- 系统还集成 Agent 能力（RAG/工具/记忆人格）

## 五、评价口径（现行标准）【已验证·《数字人基础》§六】

| 指标族 | 代表指标 | 回答的问题 |
|--------|---------|-----------|
| 唇同步 | Sync-C / Sync-D | 嘴型与声音是否对得上 |
| 身份与长时漂移 | CSIM / CSIM-drift / LPIPS-drift | 是否还是同一个人、长时是否偏离 |
| 画质 | PSNR / SSIM / LPIPS / NR-IQA | 画面质量 |
| 时序流畅 | Dino-S / flow_smoothness | 相邻帧是否平滑、有无闪烁抖动 |
| 效率 | FPS / TTFF / 延迟 / 显存 | 能否实时、算力代价 |

关键口径【已验证】：**论文 FPS ≠ 产品 SLA**。

## 六、我们的选择与理由（本文只写结论，详述在《数字人行业全景》）【已验证】

- 2026-06-08 起三路线调研 → **2026-06-22 选型结论：以 GAGAvatar / UIKA 系前馈式方案为主要探索方向**（project-README 时间线）
- 最终落地的系统形态：CyberVerse（实时 Agent 框架）+ AvatarForcing / Ditto 模型插件（@4968280）
- 理由要点（待《行业全景》补实测支撑）：前馈式建 avatar 成本低、动作空间路线便于实时化

## 七、术语表

| 术语 | 全称/含义 |
|------|----------|
| ASR | Automatic Speech Recognition，自动语音识别 |
| TTS | Text-to-Speech，文本转语音 |
| TTFF | Time To First Frame，首帧延迟 |
| FFTT | First Frame To Talk，开口延迟 |
| RTF | Real-Time Factor，推理耗时/音频时长的比值，<1 为可实时 |
| FLAME | 参数化 3D 面部模型（表情/头姿/眼动） |
| blendshape | 表情基向量组合表示 |
| 3DGS | 3D Gaussian Splatting，三维高斯泼溅 |
| NeRF | Neural Radiance Fields，神经辐射场 |
| CSIM | Cosine Similarity of Identity embedding，身份余弦相似度 |
| Sync-C / Sync-D | 唇同步置信度 / 距离 |
| LMDM | Latent Motion Diffusion Model（Ditto 的核心生成模型） |
| motion latent | 低维运动隐表示 |
