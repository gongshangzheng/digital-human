## 一、数字人是什么（概念层）

### 1.1 两层划分【已验证·《数字人基础》§一】

- **数字人（模型）**：给定输入生成可控形象的技术问题
- **数字人系统**：ASR + LLM + TTS + Avatar 渲染的级联产品形态

一句话定义（《5分钟认识数字人》）：**用可驱动的形象，把语音/文本变成会说话、有表情的画面。**

### 1.2 三个基础判断问题【已验证·《数字人基础》§二】

1. 表现质量 — 像不像、自然不自然
2. 表现范围 — 只动嘴 / 带头姿表情 / 带身体手势
3. 工程性能 — 能不能实时、要多少算力

### 1.3 常见任务名称【已验证】

| 名称 | 范围 |
|------|------|
| 换嘴配音（lip sync） | 只改说话口型 |
| talking head | 头像说话 + 表情头动 |
| 3D avatar | 可驱动三维资产生成形象 |

## 二、为什么重要（价值层）

- 应用形态：会议面试官数字人（本项目）、虚拟客服、直播主播、陪伴 Agent【已验证·project-README】
- 产业价值：把"AI 回复"从文字/语音升级为"可见的面对面交互"；对话式产品的最强临场感载体【推断】
- 技术价值：数字人是多模态（语音理解→语言生成→语音合成→视觉生成）端到端系统的集成试炼场【推断】
- 关键约束：实时性决定可用性（对话场景 <1s 级 TTFF 才自然）【已验证·《数字人基础》§五】

## 三、技术路线版图（现行做法）

### 3.0 框架：两条轴，不是互斥路线【已验证】

knowledge/《数字人基础》原文："生成方式与渲染后端可自由组合，不能混成互斥路线。动作空间模型既可以配 2D renderer，也可以配 FLAME、NeRF 或 3DGS。"

| 轴 | 取值 |
|----|------|
| 生成方式（模型直接预测什么） | ① 局部换嘴/视频级修正 ② 动作空间生成 ③ 整帧视频生成 |
| 渲染/资产后端（画面靠什么落地） | ① 2D warping renderer ② FLAME/3DMM ③ NeRF/3DGS 专人资产 ④ **ARKit/blendshape/game engine** ⑤ 视频级后处理 |

《5分钟认识数字人》原话："3D 资产不是第四种互斥模型，而是画面如何落地的一种后端；可以和动作空间组合。"

### 3.1 六条技术路线 taxonomy（依据 digital-human-avatar-survey 表 2）【已验证】

| # | 路线 | 核心表示 | 适配任务 | 代表工作 | 优势 | 限制 |
|---|------|---------|---------|---------|------|------|
| 1 | 2D talking-head / latent inpainting | landmarks、mask、latent feature | head/portrait | MuseTalk、SadTalker | 简单快、生态成熟 | 身体手势弱、3D 一致性弱 |
| 2 | 结构化动作策略 | SMPL-X、FLAME、MANO、VQ motion token | full-body、upper-body gesture | EMAGE、Audio2Photoreal、EMO2 | 可解释可控、动作可单独评估 | 仍需 renderer |
| 3 | 动作扩散 + 快速渲染器 | 低维 motion + warping GAN/renderer | 实时上半身 avatar | ChatAnyone；**Ditto、Avatar Forcing（我们的主线）** | 实时性强、工程闭环清晰 | 画面自由度低于整帧大模型 |
| 4 | 视频基座模型适配 | video latent、DiT/MM-DiT、ReferenceNet、LoRA | full-frame avatar video | OmniAvatar、HunyuanVideo-Avatar | 场景/全画幅表达强 | 训练推理重、资产不可复用 |
| 5a | 3D 资产（学习式） | Gaussian particles、NeRF field | renderable avatar | GaussianTalker、UIKA、FlexAvatar | 身份可复用、渲染可控、几何一致 | 注册/训练成本高、极端动作风险 |
| 5b | **3D 资产（参数化装配式）** | **mesh + blendshape / FLAME rig（ARKit 52 等标准接口）** | 工业实时角色 | FLAME/3DMM 系、Audio2Face 类（游戏引擎渲染） | 接口标准、可跨软件、实时可靠 | 写实度靠美术资产、制作成本高 |
| 6 | 掩码局部多人控制 | face mask + localized cross-attention | 多人 avatar video | HunyuanVideo-Avatar | 可指定说话人 | 依赖 mask、复杂互动未解 |

路线可组合【已验证】：EMAGE 的 motion 可进 photoreal renderer；Audio2Photoreal 把 face/body/hand motion 接 personalized renderer；One Shot, One Talk 把 2D diffusion 伪视频与 SMPL-X/3DGS-mesh 资产结合。

### 3.2 渲染后端光谱（依据 数字人渲染器专题 §二）【已验证】

| Renderer / 后端 | 输入契约 | 典型用途 | 替换难度 |
|---|---|---|---|
| Ditto / LivePortrait renderer | reference appearance、canonical keypoints、pose/exp/translation | one-shot 音频驱动头像 | 高（与 motion 表示强绑定） |
| LIA-X renderer | source identity/features + 40D motion code | T2AV motion 解码 | 高（与 flow-warp 绑定） |
| FLOAT / Avatar Forcing decoder | 512D appearance `s` + 512D motion 接口 `r=Bα` | Motion AE / 交互头像 | 高（与 20D α 和 Direction 基绑定） |
| FLAME / 3DMM renderer | mesh、表情/头姿系数、相机/光照 | 可解释控制、3D 资产驱动 | 中 |
| NeRF / 3DGS avatar | 专人可渲染资产 + motion/pose | 专人高质量数字人 | 高（需专人训练） |
| **ARKit / blendshape / game engine** | 标准 blendshape、rig、材质资产 | 工业实时角色 | 中（接口标准、写实度靠资产） |
| Wav2Lip / LatentSync | 视频帧 + 音频/同步条件 | 口型替换/视频级修正 | 低到中（是后处理，非完整 renderer） |

具体数据点【已验证】：LIA-X decoder 在 A10、512²、bf16、batch=1 下约 **333ms/帧**（渲染器本身可能是瓶颈）。

### 3.3 视频基座路线的代表模型（papers 库互链）【已验证】

FlashHead `paper-soulx-flashhead`、LiveAvatar `live-avatar-paper`、Hallo3 `paper-hallo3`、HunyuanVideo-Avatar `paper-hunyuan-avatar`、OmniAvatar `paper-omniavatar`、Wan-Streamer `wan-streamer-2026`、OmniMate `omnimate-2026`、LeapTalk `leaptalk-2026`。

### 3.4 动作空间路线的代表模型【已验证】

### 3.5 动作表示谱系（深度见《数字人动作》）【已验证】

3DMM 系数（BFM/FLAME，语义高）→ Blendshape 系数（ARKit 52 维，工业标准接口）→ 隐式关键点（LivePortrait）→ latent（Ditto 265 维、AF 20 维）。表示越靠后越难人读、越贴模型内部。

## 四、数字人系统与实时性（现行做法）【已验证·《数字人基础》§四/§五】

- 级联四组件：ASR → LLM → TTS → Avatar 渲染
- 三种架构：级联（可控、延迟高）vs 端到端（A2-LLM TTFA 535ms）vs 混合
- 流式级联全链路约 **3.2s**；差距来自分块等待与组件排队
- 传输层：实时交互基本必选 WebRTC（jitter buffer / NetEQ / 抗弱网）
- 推理层：流式 TTS 分块 + Avatar 异步渲染；轻量技巧（滑窗重叠融合、静音回退中性口型、说话/静音状态机）
- 系统还集成 Agent 能力（RAG/工具/记忆人格）

## 五、评价口径（现行标准）【已验证·《数字人基础》§六】

| 指标族 | 代表指标 | 回答的问题 |
|--------|---------|-----------|
| 唇同步 | Sync-C / Sync-D | 嘴型与声音是否对得上 |
| 身份与长时漂移 | CSIM / CSIM-drift / LPIPS-drift | 是否还是同一个人、长时是否偏离 |
| 画质 | PSNR / SSIM / LPIPS / NR-IQA | 画面质量 |
| 时序流畅 | Dino-S / flow_smoothness | 相邻帧是否平滑、有无闪烁抖动 |
| 效率 | FPS / TTFF / 延迟 / 显存 | 能否实时、算力代价 |

关键口径【已验证】：**论文 FPS ≠ 产品 SLA**。

## 七、术语表

| 术语 | 全称/含义 |
|------|----------|
| ASR | Automatic Speech Recognition，自动语音识别 |
| TTS | Text-to-Speech，文本转语音 |
| TTFF | Time To First Frame，首帧延迟 |
| FFTT | First Frame To Talk，开口延迟 |
| RTF | Real-Time Factor，推理耗时/音频时长的比值，<1 为可实时 |
| FLAME | 参数化 3D 面部模型（表情/头姿/眼动） |
| blendshape | 表情基向量组合表示 |
| 3DGS | 3D Gaussian Splatting，三维高斯泼溅 |
| NeRF | Neural Radiance Fields，神经辐射场 |
| CSIM | Cosine Similarity of Identity embedding，身份余弦相似度 |
| Sync-C / Sync-D | 唇同步置信度 / 距离 |
| LMDM | Latent Motion Diffusion Model（Ditto 的核心生成模型） |
| motion latent | 低维运动隐表示 |
