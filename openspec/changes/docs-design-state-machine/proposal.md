## Why

「角色从说话态转到聆听态」这条线的信息现在散在 `管理文档/数字人概述/工程设计` 的 **5 处**，而且**原始设计文档在另一个仓库**：

| 位置 | 记了什么 |
|---|---|
| `### 打断与收声的状态机`（稳定性设计） | 期望行为、两个已定位缺陷、四组改动**名目**、一条失败结论（4 版被推翻） |
| `### 背压与限流（进行中）`（稳定性设计） | 限流阀自锁、两级水位 + FLUSH + work-ahead 上限、lead 记账缺陷 |
| `### 编码进程`（传输与发布设计） | 「打断时强制重生」以保证新段从关键帧开始 |
| `### 段与发布节奏`（传输与发布设计） | 段长按状态区分（待机 / 说话 / 爬坡 / 预缓冲），粒度可配 |
| 音频链路设计（待机静音流、分段与归一化） | 静音流必须跨块连续（10Hz 锯齿）；带下限归一化（否则头部放大漂移） |

而**真正的状态机与转场设计在 CyberVerse 仓库**的 `management/docs/silent-avatar-feed-gate.md`（待机/说话两级水位的由来与取值、**「视频永不剪」的转场策略**、**三次误诊与纠正**、转场时序图、按日志定位的诊断表）——本仓库**只在 `knowledge/README.md` 第 52 行登记了文件名，正文里没有任何链接**。

后果有三：① 没有一个地方能读到完整状态机（标题叫"状态机"，内容却只有期望行为 + 四组改动名目）；② 我们唯一讲打断收声的地方与它的源文档断开；③ 反向切换（聆听→说话）在《数字人加速》的 `### 首帧与开口` 里，两篇互不指向。

## What Changes

- 在 `management/docs/数字人概述/工程设计.md` 新增一个专讲状态机的二级节 `## 状态机设计`，把上述 5 处信息按「状态与事件 → 喂料阀与两级水位 → 转场策略 → 音频侧连续性 → 收尾与失败判据 → 三次误诊 → 诊断表 → 未决」组织。
- **收编外部源文档的结论与判据**（状态与水位取值、视频永不剪、三次误诊、日志诊断表），代码级细节仍外链到 CyberVerse 仓库；本仓库不复制其全文与源码行号。
- **消除重复**：原 5 处按「事实只在状态机节出现一次」处理——`### 打断与收声的状态机` 整体移入新节（原位留一行指针），其余 4 处保留机制细节、在新节引用而非搬走。
- 修好两处断链：新节文末指向 CyberVerse `silent-avatar-feed-gate.md`，并回链《数字人加速》的 `### 首帧与开口`。
