## Context

`数字人概述/数字人领域问题` 现有六章都在讲"问题是什么、现有解法做到哪一步"，没有一章讨论**这些问题的解应该放在哪一层**。并行推进的 `docs-dh-field-tech-applicability` 正在加 `## 七、技术适用性`（以**外来技术**为主语）——本章是反方向：**以我们已有的工程问题为主语**，问"能不能从工程侧搬进模型里解决"。

本章的价值来自库内已有的双向一手证据：

| 证据方向 | 事实 |
|---|---|
| 工程侧做不动 | "打断立即止声"4 版被推翻（画面冻结 / 长度难调 / 尾音被一起丢弃），判据是人眼与听感（`工程设计`） |
| 模型侧做成了 | OmniMate 的 GPC 把"说到哪了"变成模型内连续条件（1–1000 / 0），按进度收束并转态（`论文笔记/omnimate`） |
| 上移失败 | 参考条件化 v1 干净失败、v2 多 seed 回退、CSIM-as-loss 放弃、学习式锚力终止（`Avatar Forcing 微调实践`） |

**用户已指定：本章必须给一个完整例子，例子就是 OmniMate，并且指出 GPC 就是"工程问题模型化"本身**——它不只是可选例证，而是**范例**：GPC 处理的问题（何时停、还剩多少）原本的归属层是系统侧的**调度**（状态机 + 缓冲 + 门控 + 时长控制），是全套里"工程味"最重的部分；GPC 把它改写成**模型每一步都能读到的条件标量**。同一个问题在我们这被工程侧 4 版推翻、在别人那被搬进模型解决——这是能把判据跑通一遍的唯一现成对照。

## Goals / Non-Goals

**Goals：**

- 给出可复用的**五维判据**（信息可得性 / 接缝代价 / 连续量需求 / 监督信号可得性 / 上移代价）与判读顺序。
- **用一个完整范例（OmniMate 的 GPC）把五维判据逐条跑一遍**，让读者看到"判定 → 依据 → 结论"的完整推理，而不是只看结论表。
- 用库内已有一手证据逐条判定 7 个候选（含一条明确"不该上移"的反例）。
- 写出上移的三类代价与失败反例，避免被读成"什么都能上移"。
- 收口到可检验判据与三个开题点，并与《工程设计》的状态机节对齐。

**Non-Goals：**

- 不写具体实现方案（训练配置、网络结构、数据管线）。
- 不重复《工程设计》的机制细节与数字；不重复 `## 七、技术适用性` 的技术评估维度。
- 不把本章写成工作清单；判定必须由五维判据推导。
- 不把 OmniMate 的论文结论写成我们的实测（证据等级必须分开标注）。

### 2.1 范例小节（`### 范例：GPC 把一个调度问题改写成模型的条件`）规格

必须包含七块，**逐块给出证据等级**：

| 块 | 内容 | 证据等级 |
|---|---|---|
| ⓪ 为什么它是范例 | GPC 处理的问题（何时停 / 还剩多少）原本归属系统侧的**调度层**：状态机决定状态、缓冲与门控决定何时喂料、时长由外部给定。它是"工程味"最重的一类问题——不是画质、不是运动质量，而是**控制流程**。GPC 的做法是把它整体改写成模型的条件：问题从"调度器怎么切"变成"模型在每一步看到自己推进到哪" | 本文的定性（标注为我们的分析） |
| ① 问题 | 开放式回合里"这一轮该说多长"外部不可预知：固定时长会截断未说完的回应或产生冗余；显式完成检测会引入延迟、破坏实时 | 论文原文（`omnimate` §问题与动机） |
| ② 工程侧的做法与失效（我们） | 外挂门控 + 两级水位 + 视频永不剪 + 转场策略；**"打断立即止声"4 版全被推翻**（画面冻结 / 长度难调 / 尾音被一起丢弃），判据是人眼与听感 | **我们的实测**（`工程设计`） |
| ③ 模型侧的做法（OmniMate） | LLM 估执行时长 → 整段 token 铺满 **1–1000**（末位 1000 = 该收尾；超出预估一律 **0 = 聆听**）→ 正弦 PE + **小 MLP 逐元素相加**到 latent；训练用 **DMD 蒸馏后的双向 teacher** 造 exec↔listen 四类序列，掩码 $m_i$ 与条件插值 $P_i$ 只给教师与 score 网络，**student 只看进度值** | **论文级对照**（非我们实测） |
| ④ 换来了什么 | 按进度**收束**而非到点硬切；exec/listen **无缝转态**（聆听态由同一骨干生成，无拼接接缝）；**优雅降级**（估短了自动转入聆听，不会硬撑） | 论文级对照 + 机制推论（标注） |
| ⑤ 代价 | 控制权外移到 LLM 的时长估计（**估不准→偶发漏词/重复**，论文自陈）；训练期需造状态切换数据（并因 temporal prompt leakage 弃用多步扩散教师）；消融显示去掉 GPC 后交互准确度指标从 0.097 劣化到 **0.239** | 论文级对照（含消融数字） |
| ⑥ 逐条过判据 + 与我们做法的差别 | 五维判据逐条给"是/否 + 依据"；结论：它在五维上都通过，因此"该说多久"属于**该搬进模型**的一类。与我们的差别精确落在**第三维（连续量需求）**：外挂门控只能在**块边界**切且需要外部信号；进度条件是**每步都读到的连续标量** | 本文的判定（标注为我们的分析） |

**必须写清的两条边界**：① OmniMate 的 GPC 是**论文级对照**，我们没有复现；② 它的代价是真实的（时长估计依赖 LLM），所以这个例子说明的是"**这类问题可以搬进模型**"，不是"搬进去就没有代价"。

### 2.2 实测清单（`### 我们的实测清单`）的 7 条

| 候选 | 工程侧现状 | 判定 | 证据与等级 |
|---|---|---|---|
| 打断与回合边界 | 外挂门控 + 两级水位 + 视频永不剪 | **建议上移**（与例子同源） | 4 版被推翻（已否决）；GPC 为模型侧对照（论文级） |
| 聆听态内容（呼吸/注视/闭嘴） | 静默运行时喂呼吸静音 + 闭嘴聆听画面 | **部分上移** | 静音流锯齿已复现并修复；内容一致性未量化 |
| 静音期归一化 | 带下限归一化 | **上移候选** | 头部放大漂移已复现并修复；上移后是否更好未验证 |
| 视频源唇动隔离 | 推理期开关，默认关、不改权重 | **上移候选** | LSE-C 3.74→4.87（已复现，单 case）；训练期条件化未做 |
| 锚定与漂移治理 | 推理期锚帧库 + 方向约束（A1） | **不建议上移** | 参考条件化 v1 失败、v2 回退、CSIM-as-loss 放弃、LAF 终止（均已否决） |
| 发布节奏 / 背压 / 传输 / 编码 | work-ahead + FLUSH + 常驻 NVENC | **不该上移** | 纯系统问题；判据是发布 cadence 与丢包隐藏率（实测） |
| 首帧与开口 | 排空待机存粮 + 首块推理 | **边界**：存粮是工程，首块耗时是模型 | TTFF ≈ 1.12s + 0.3s（实测口径） |
