## Why

`数字人概述/数字人领域问题` 的六章都在讲"问题本身"，没有一章讨论**这些问题的解应该放在哪一层**。而我们的实测里已经积累了一批双向证据，它们指向同一个元问题：

- **工程侧解不动的**：让"打断立即止声"试了 4 个版本全部被推翻（画面冻结 / 长度难调 / 尾音被一起丢弃），判据是人眼与听感；
- **模型侧已经做成的**：OmniMate 用 GPC 把"说到哪了"变成模型内的连续条件（1–1000 / 0），从而按进度收束并转态；
- **上移失败的**：把推理期锚定上移到训练期（参考条件化 v1/v2 两轮回退、CSIM-as-loss 放弃、学习式锚力终止）——**不是所有上移都值**。

也就是说：我们既知道"工程侧硬做会失败"，也知道"上移不一定成功"。缺的是一个**判断框架**：什么问题该留在工程侧、什么该上移到模型内、代价与判据是什么。没有这个框架，每次都得凭感觉在"加个开关"和"重训一版"之间选。

这一章与并行推进的 `## 七、技术适用性` **方向相反、不重复**：七章以**外来技术**为主语（"某个技术能不能用在数字人"），本章以**我们已有的工程解/问题**为主语（"这个解该不该进模型"）。

## What Changes

- 在 `管理文档/数字人概述/数字人领域问题` 新增一章 `## 八、工程问题模型化`（接在六章之后；若 `## 七、技术适用性` 先落地则顺延为八，否则本章先占七并在 design 里注明确认）。
- 章内固定结构：**判断框架（五维判据表）→ 我们的实测清单（逐条判定）→ 上移的三类代价与反例 → 可检验判据与开题点**。
- 实测清单覆盖 7 条，全部用库内已有一手证据：打断与回合边界、静默期连续性（呼吸/口型闭合）、静音期归一化、视频源唇动隔离、锚定与漂移治理（含失败案例）、发布/背压/传输（**不该上移**的反例）、首帧与待机存粮（边界情形）。
- 章末给三条与本章直接相关的开题点（回合边界模型化、唇动隔离训练期化、聆听态连续性模型化），并指向《工程设计》的状态机节。
