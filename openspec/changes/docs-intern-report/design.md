### 3. 第三部分（新写）的组织方式

**重写记录（2026-09-24，第四次）**：初版按"判断类型"罗列（逻辑散）；第二版"一条链 + 三个软肋"被指出**硬凑**且混淆了范式级与变体级；第三版按"判别标准"重排。本次按用户补充再改一处：**限制 3 从"缺一个量"升级为架构事实——运动侧没有角色条件**。

**判别标准**：

> **缺陷 = 换掉实现也依然存在的限制（范式级）；靠工程或外挂能缓解的，单列"变体级问题"。**

据此：撤回"解耦只是近似"（用户确认 **Avatar Forcing 漂的就是动作**）；出局"条件只给一半自由度"（条件生成本来就有剩余自由度）；"长时漂移"降为变体级（流式化引入，且我们已缓解）。

全章只回答一个问题：**我们怎么理解潜动作空间（扩散）数字人模型。**

**来源口径**：3.1–3.4 的骨架来自两个在跑 change 的共享上游命题与裁决记录（`docs-motion-space-modeling` / `docs-identity-consistent-learning`），**不是已发布文档**；汇报稿只写理解本身，不写成"引用某文档"。

**每条统一四段式**：**它是什么 → 导致什么失败 → 依据（标来源）→ 为什么是范式级 / 边界**。

---

**3.1 它是什么：两级结构（动作生成 + 渲染器）**

- 潜动作空间模型把生成拆成两级：**先在低维运动空间里生成"怎么动"，再由渲染器把运动套回参考外观出画面**。
- **为什么这样切**：算力花在 265 / 20 维而不是像素上 → 换来三件事——**实时**（单卡可跑）、**可控**（维度可读、可逐维扰动）、**身份复用**（换一张参考图就换人）。
- 依据：`论文笔记/{ditto,liveportrait,float}.md`、`数字人概述/数字人身份`；**观察**。

**3.2 它靠什么成立：假设"身份与运动可分解"**

- 这一族的优点建立在一处：**把身份与运动分开**——`z = z_S + m_S`（身份项每步恒等）、**运动量里不含关键点**（265 维只含 scale / 头姿 / 平移 / 表情形变）、**身份被钉在渲染入口**。
- **"可分解"有两种具体写法，而且还有第三个维度**：

| 写法 | 公式 | 落在哪 |
|---|---|---|
| 隐空间加法 | $z = z_S + m_S$（$z_S$ 512D 每步恒等） | 表示层（FLOAT / Avatar Forcing） |
| 关键点变换 | LivePortrait 式：$x = s\cdot(x_c R + \delta) + t$（**先旋头姿、再加表情**） | 关键点空间 |
| 关键点变换（改次序） | PerformRecast 式：$x = s\cdot((x_c + \delta) R) + t$（**先加表情、再整体旋转**，与 FLAME 一致） | 关键点空间 |

  前两行是"两种分解方式"，后两行是"同一种方式里次序对不对"：先旋再加会让表情形变混进头姿信息，"只改表情、不动头"做不到。所以**"可分解"不只是"分成两项"，还要问"两项以什么方式组合"**。
- 边界：论文承认没有任何一种表示能保证完全解耦；**推断**。

**3.3 这一类模型的四个固有限制（范式级：换掉实现也消不掉）**

| # | 限制 | 导致什么失败 | 依据 |
|---|---|---|---|
| **1** | **只解脸**——工作单元是"裁剪对齐的人脸框" | 身体、手、交互几何（看向谁、靠近、前后遮挡关系）、场景变化都不在表示里；**换机位不是移动相机，而是重新生成一段**；多人场景的做法是**逐框处理 + 贴回**（这是正确做法、不是缺陷——LivePortrait 把"多脸同时动画"列为 stitching 的收益），代价是**框外画面与框间遮挡关系仍不在表示里** | AF 自认"只建模头部运动，无法表达手势等更丰富的身体线索"；LivePortrait 的 stitching 正是为"贴回原图空间"而设计（并因此支持多脸/全身图）；`数字人领域问题` §二「手部与全身」 |
| **2** | **只能搬运，不能合成**——渲染器把参考外观 warp 出来 | 改不了服饰/背景/光照/场景；大外观变化做不了；源图没观测到的区域（大偏航、被遮挡）只能由解码器"想象"，**几何不保证正确**；本质是**重演**而不是**生成** | LivePortrait 明说"不是 3D 重建、几何不保证正确；源图只见正面，转过身后越依赖想象，论文未给最大角度"；我们的跨路线对照："画面完全由源图 warp 而来，生成力受源图约束" |
| **3** | **运动侧没有角色条件**：身份只进 decoder，运动生成侧的条件只有音频 / 情绪标签 / 源运动 / 时间步——**没有"这个角色"这一路**，所以**运动分布天生是角色无关的** | ① **生成侧塌向均值**：生成的是"谁都能用的平均动作"，而不是"这个人怎么动"——AF 学成"被动、不回应的倾听"（须靠 DPO 拉回），GDPO-Listener 的听者动作塌成静态脸；② **治理侧只能外挂或事后手算**（没有"这个角色的正常范围"这个概念可用）；③ **语义级控制要逐维扰动反推** | `docs-motion-space-modeling` 的裁定「**运动侧没有角色条件 = 架构级根因**」；FLOAT 的条件入口清单（身份只进 decoder）；我们的实测（锚帧库 = 外挂的 KDE）与 Ditto 的逐维控制索引 |
| **4** | **隐式运动空间与它的渲染器是一套私有契约**（三层绑定：**语义**——表示"是什么"由渲染器定，如 Ditto 那 63 维表情形变 = 21 个 LivePortrait warper 学出来的隐式 3D 关键点 xyz；**接口**——维数/基/尺度私有；**训练耦合**——运动编码器与渲染器联合训练，表示里嵌着该渲染器的归纳偏置） | ① **换后端 = 换表示**（Ditto 265 维不能喂 LIA-X 的 40D，也不能喂 FLOAT 的 $r=B\alpha$，不是接口不匹配而是**语义对不上**）；② **不能部件级替换**（升级渲染器要重训运动侧，反之亦然）；③ **跨模型组合几乎不可能**（如"Ditto 运动 + 3DGS 渲染"需先解决表示转换）；④ **生态碎片化**——领域几乎没有"运动表示的标准接口" | `knowledge/数字人渲染器专题`（"motion、stitching、warp、decoder 是一套契约"）；`数字人领域问题` 第七章「技术适用性」；反面对照：**ARKit 52 维 blendshape 能标准化，正因为它独立于任何渲染器** |

**限制 3 的两面性（要点）**："运动与角色无关"**同时是优点和缺陷**——正因为如此，**换一张参考图就换人**（最便宜的换身份方式）；代价是**生成的动作不属于任何具体的人**。这不是实现没做好，而是这套切法的直接后果。

**边界（两条）**：① 限制 3 的准确说法是"**运动侧缺角色条件**"——扩散/流匹配模型本身隐式有分布（score 原则上可算 $-\log p$），不能写成"模型没有分布"，缺的是**逐角色**这一层的条件与标定；② 限制 4 的准确说法是"**隐式**运动空间与渲染器是私有契约"——**3DMM 系（FLAME 系数）是弱绑定**，同一组系数可喂不同后端（这正是它在工业界流通的原因）。限制 3 与 4 合起来是一条取舍：**自由度越语义化就越通用、越可控制，越隐式就越绑定、越难编辑**——这是选取舍，不是谁的失误。

**另有三类问题是变体级（流式化或选型引入）**：长时运动漂移 · 静音放大 · 条件被当成同一类处理。它们**可由工程或选型缓解**，因此**不属于范式的固有限制**；其事实、数字与我们的缓解写在**第二部分**（2.2 工作线 / 2.3 量化成果表 / 2.4 方法沉淀）。

**3.4 由上面推出的判断**（压缩成清单，不再展开）

- **我们的增量位置**：限制 1/2 属范式边界（要换范式才能解），**限制 3/4 才是我们能做的增量**——而且限制 3 给了增量一个非常具体的说法：

  > **给运动侧补回"角色"这一路条件**——逐角色运动先验 $p_p(\alpha)$ 就是"这个角色的运动条件"；**不是去改 decoder**。

  配套的是表示层的另一件事：**给运动表示补上语义分工与可复用接口**（限制 4）。
- **技术格局（压缩保留）**：模型层与推理层的开源共生（观察）· 开源做底座、闭源做产品（观察）· 芯片厂商沿栈向上渗透（观察 + 推断）· "合成问题正在变成编辑问题"（推断）· 实时性的瓶颈会继续留在系统层（观察 + 推断）。
- **方法论与工程（压缩保留）**：负结论与正结论同等有价值 · 证据分级决定能写什么 · **指标改善 ≠ 体验可用** · 探针先于消融 · 口径裂缝比模型缺陷更值得警惕 · 局部变快 ≠ 用户侧变快 · 可插拔是工程主线 · 换形象成本决定路线选择 · 授权合规是前置条件 · **条件注入要按类处理**（必须硬生效的走加法/拼接，区域类条件适合投影/拒绝采样；证据：GPC 的 `Use CrossAttn` 伪影）。

### 4. 压缩与口径原则（硬约束）

1. **单事实源**：任何数字只从既有文档摘抄并标出来源（如"锚点引导 0.645 → 0.935〔数字人身份〕"），**不重算、不换算、不合并**。
2. **长内容用链接**：`[[数字人概述/数字人身份|数字人身份]]` 形式；汇报稿不复制长段。
3. **每条结论带边界**：单身份 / 单素材 / 未跨身份验证 / 未复现等，必须留在句内或紧随其后。
4. **观察与推断分标**，不混写。
5. **删掉 wiki 自述**：如"数字全部来自前七篇，本篇不做二次加工"这类面向文档体系的句子不进汇报稿。

### 5. 第⑤部分是否需要新增候选方向

本轮调研（AdapTok / TivTok / Pixel3DMM / PerformRecast / Causal Forcing / 身份一致性判别器缺口）在**表示层**新增了一条素材线：**身份—运动解耦的表示机制**（TivTok 的 TIV/TV 分解、PerformRecast 的 FLAME 一致变换）+ **显式跟踪监督**（Pixel3DMM）+ **蒸馏中的教师因果性**（Causal Forcing）。

建议在汇报稿里**评估是否新增候选 E**：主张 = "在表示层做身份/运动解耦并用显式跟踪监督替代隐式自监督"；证据 = 库内 4 篇新笔记；缺口 = 需要自己的消融；撞车风险 = 中（与第七章「技术适用性」正在写的内容重叠，但那条是**领域问题**视角，候选 E 是**可发表工作**视角）。

**默认处理**：在 5.3 写成一个**待定候选**（给主张/证据/缺口，不给优先级），并在文中标注"是否立项待定"。若用户决定立项，再更新原 `总结.md` 的候选列表（另开小改动）。

### 7. 新增一条主轴：两条主流范式与算力门槛（用户补充）

第①部分必须把下面这一刀讲清楚，它比“六条路线”更高一层：

**A. 视频基模（video foundation model）路线——当前最主流**

- 能力上限最高：全画幅、场景与全身动作一起出，整帧重绘，画面“生成力”不受源图约束。
- **代价是算力门槛高**：训练通常在**数张 A100** 量级，实时化还要额外做蒸馏与加速工程。
- 工程与就业相关性最高：这是当前工业界与招聘市场最认的方向。

**B. 动作潜空间（motion latent space）路线——我们更熟、不吃算力**

- **核心特征：把身份与动作分离**；工作**主要集中在面部**。
- 内部再拆成**两个动作**（这一拆是本节的关键结构）：
  - **B1 动作生成**：给定语音 / 文字等信息，生成真实动作（表情、嘴型、头姿）。代表：Ditto（265 维运动空间 + 条件 DiT）、FLOAT / Avatar Forcing（20 维运动子空间 + Flow）、LIA-X（40D motion code）。
  - **B2 画面生成（渲染器）**：有动作之后驱动画面。后端光谱与各自契约（引用 `knowledge/数字人渲染器专题.md`）：**SPADE 系**（LivePortrait，**Ditto 复用的就是这一套**：Appearance Feature Extractor + Face Renderer，隐式关键点 warp + SPADE 解码器）、**flow-warp + StyleGAN2 风格调制卷积**（LIA-X）、**加法解耦 decoder**（FLOAT / Avatar Forcing，$z=z_S+m_S$）、**FLAME / 3DMM**、**3DGS / NeRF 专人资产**。
- **渲染器契约互不兼容**：Ditto 的 265 维不能直接喂 LIA-X 的 40D，也不能喂 FLOAT 的 $r=B\alpha$——换渲染器等于换运动表示。这条边界必须写进汇报稿，对照表里也要体现。

**呈现方式**：一张“范式 → 能力上限 / 算力门槛 / 我们掌握程度 / 就业相关性”对照表 + 一张“B 范式内两级分解（B1 动作生成 → B2 渲染器）”的 Mermaid。

**与第③⑤部分的联动**：

- 第③部分加一条判断：**算力预算直接决定可选赛道**；视频基模是主流与就业风口，动作潜空间是我们当前的立足点与可低成本闭环的地方（观察 + 推断）。
- 第⑤部分在 30 天清单后补一句**方向选择待定项**：是否先在动作潜空间做出可发表工作再向视频基座迁移（标“待定”，不写成结论）。

**口径**：算力门槛只写“量级”（数张 A100）；渲染器细节引用 `论文笔记/ditto.md`、`论文笔记/liveportrait.md`、`knowledge/数字人渲染器专题.md`，不新造数字；SPADE 的出处（Park et al. 2019）与“StyleGAN2 风格积木”只属于 LIA-X 这一支，不要混写。

## Risks / Trade-offs

- [汇报稿与原文数字不一致] → Decision 4 硬约束：只摘抄 + 标来源；交付前抽查 5 处数字与来源逐字比对。
- [第③部分写成原文复述] → 强制三段式（判断 → 依据 → 边界）并按判断类型重组；复述式句子一律改写。
- [压缩丢掉边界，被追问时被动] → 每条结论必须带边界；"单身份 300 秒"这类限定不得删。
- [20 分钟装不下五部分] → 按时长折算字数；若超，优先压①②（已有长文可查），保证③④⑤完整。
- [候选 E 被误读为已定项] → 文中明确标"待定候选"，不进决策建议的优先级排序。
- [order 冲突] → 取当前最大 +10，实施前复核（并行会话持续新增文档）。
