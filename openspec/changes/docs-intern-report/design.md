### 3. 第三部分（新写）的组织方式

**重写记录（2026-09-24，第二次）**：初版按"判断类型"罗列（技术格局 / 方法论 / 工程产品），被指出**逻辑散**；第二版加了"基本分解 / 分界 / 动作分布空间"，但仍把**命题、方法论、行业判断**三条线并列，没有因果链。

**来源口径**：3.1–3.5 的骨架来自两个在跑 change 的共享上游命题与裁决记录（`docs-motion-space-modeling` / `docs-identity-consistent-learning`），**不是已发布文档**。汇报稿可以写这些理解（是我们自己的推理），但**不得写成"引用某文档"**；待 `动作空间建模/` 等文档落地后再补链接。

**每条统一三段式**：**理解 → 依据（标明来源或"我们的推理"）→ 边界（适用范围或反例）**，并标「观察 / 推断」。

---

**3.1 它是什么：两级结构（动作生成 + 渲染器）**

- 潜动作空间模型把生成拆成两级：**先在低维运动空间里生成"怎么动"，再由渲染器把运动套回参考外观出画面**。
- **为什么这样切**：算力花在 265 / 20 维而不是像素上 → 换来三件事——**实时**（单卡可跑）、**可控**（维度可读、可逐维扰动）、**身份复用**（换一张参考图就换人）。
- **代价**：画面完全由参考外观搬运，**"生成力"受源图约束**（背景、服饰本来就稳，但也不会被重新合成）；且**工作单元是"裁剪对齐的人脸框"**，所以**它只解脸**（见 3.5 的边界与「多人场景」节的补充）。
- 依据：`论文笔记/{ditto,liveportrait,float}.md`、`数字人概述/数字人身份`；**观察**。

**3.2 它成立的前提，是"身份与运动可分解"这一个假设**

- 这一族的全部优点建立在一处：**把身份与运动分开**——`z = z_S + m_S`（身份项每步恒等）、**运动量里不含关键点**（265 维只含 scale / 头姿 / 平移 / 表情形变）、**身份被钉在渲染入口**。
- 所以"**身份 = 一条轨迹里【不变】的部分；运动风格 = 这条轨迹里【变化】的部分**"这条命题，就是这一类模型的工作假设；它也解释了身份与风格为什么总是纠缠（物理上真耦合，例如"脸型决定笑起来什么样"）。
- **“可分解”有两种具体写法，而且还有第三个维度**：

| 写法 | 公式 | 落在哪 |
|---|---|---|
| 隐空间加法 | $z = z_S + m_S$（$z_S$ 512D 每步恒等） | 表示层（FLOAT / Avatar Forcing） |
| 关键点变换 | LivePortrait 式：$x = s\cdot(x_c R + \delta) + t$（**先旋头姿、再加表情**） | 关键点空间 |
| 关键点变换（改次序） | PerformRecast 式：$x = s\cdot((x_c + \delta) R) + t$（**先加表情、再整体旋转**，与 FLAME 一致） | 关键点空间 |

  **前两行是“两种分解方式”，后两行是“同一种方式里次序对不对”**。后者的结论：先旋再加会让表情形变混进头姿信息，“只改表情、不动头”做不到。所以**“可分解”不只是“分成两项”，还要问“两项以什么方式组合”**——次序错了，分解名存实亡。
- 边界：论文自己也承认**没有任何一种表示能保证完全解耦**；**推断**。

**3.3 软肋一：解耦只是近似 ⇒ 于是必须回答"分界画在哪"**

- **反例（我们的实测）**：身份项每步恒等，但输出身份照样漂——300 秒里方向以 **+2.1°/min** 持续转偏（模长没有持续增长，漂的是方向）。**身份项固定 ≠ 输出身份固定。**
- 既然解耦是近似的，那"哪些量算身份、哪些算运动"就**必须被定义**；可**运动空间没有自带分工**（20 维 / 265 维只是数值坐标，语义是反推出来的），所以——

  > **★ 分界线不是先验给定的：** 低头/抬头幅度算身份还是风格？脸部尺度变化算身份漂移还是风格？眨眼频率算身份还是习惯？
  > **"划分线在哪里"本身就是第一个要研究的问题，不是可以假定的前提。**

- 这正是我们实测里"模长 / 方向 / 尺度"三条曲线**有歧义的根源**——不是测得不准，是分界没定义（尺度漂移就是例子：若先验假定"尺度属于运动"，脸忽大忽小就不会被当成身份问题去治）。
- **怎么处理**：把划分线当研究对象，并用**三条分解判据**检验：① 不变分量确实不变（沿轨迹方差小）② 变化分量确实承载风格（跨角色可分）③ **交换任一分量、另一分量统计不变**（标准解耦检验，把"可分性"从额外难题变成分解本身的指标）。
- 依据：`数字人概述/数字人身份`（漂移诊断）、`论文笔记/avatar-forcing`；**我们的实测 + 推理**。

**3.4 软肋二：动作是一个分布，不是一个点 ⇒ 建模对象是"逐角色的运动先验"**

- 上一节的治理（推理期锚点引导）之所以有效，是因为它把"参考"从"第 0 帧编码一次"变成"每一步都在场"；但**它本质上还是非参数做法**。
- 更一般的看法：**潜动作空间模型真正要建模的是一个"动作分布空间"，不是拟合一条流形、也不是回归一个点。** 对象是**逐角色运动先验 $p(\alpha)$**；**流形只是密度的水平集**（解释，不是实现）。
- 由此同时得到三件事：**可打分**（判定 = 密度分位）、**可投影**（沿 $\nabla\log p$ 上升）、**可采样**；**越界量 = $-\log p$**，**约束强度 = 引导权重 $w$**。与"回归一个点"的范式差别在于：后者**给不出"越界多远"**，而这正是治漂移需要的量。
- **一条重要的连续性结论**：我们那条锚帧库（A1 引导）**本质就是非参数密度估计（KDE）** → 所以这是**升级路，不是推翻重来**；漂移诊断（模长/方向/尺度）也能重新表述为分量的统计量。
- 边界：密度族要选（正态 → 混合 → 流 / RBIG → score）；可逆流能给出**闭式投影**，但表达力与代价要权衡；**推断**。

**3.5 软肋三：条件只给出一半自由度 ⇒ "音频→点"要写成后验采样，情绪是区域约束**

- 音频/文字**不提供完整的运动自由度**（它约束"怎么说"，不约束"这个人怎么动"）。所以正确的框架不是"音频 → 一个点"，而是**后验采样**：

$$p(\alpha \mid a) \;\propto\; p(a \mid \alpha)\, p_p(\alpha)$$

  **先验项正好补上音频给不出的那一半自由度**，先验即正则项。（依据：`docs-motion-space-modeling` 的调研记录；**我们的推理**。）
- **情绪与音频不同类**：音频是**数据/条件项**（似然），情绪是**区域约束项**（$\alpha \in \mathbb{E}_e$）——情绪不生成动作，它**限制哪些运动是"这个情绪下可接受的"**。合成形式即三项相加：音频项 + 逐角色先验项 + 情绪区域项。
- 由此带出**本范式的边界**：条件给不全 → 需要先验补；先验要逐角色学 → 于是回到 3.3 的分界线问题；这是同一件事在三个层次上的表现。
- **推断**。

- **我们的位置**：这一族的增量空间集中在**逐角色 + 输出侧 + 轨迹级**这三处（不是"再刷一遍指标"）。

### 5. 第⑤部分是否需要新增候选方向

本轮调研（AdapTok / TivTok / Pixel3DMM / PerformRecast / Causal Forcing / 身份一致性判别器缺口）在**表示层**新增了一条素材线：**身份—运动解耦的表示机制**（TivTok 的 TIV/TV 分解、PerformRecast 的 FLAME 一致变换）+ **显式跟踪监督**（Pixel3DMM）+ **蒸馏中的教师因果性**（Causal Forcing）。

建议在汇报稿里**评估是否新增候选 E**：主张 = "在表示层做身份/运动解耦并用显式跟踪监督替代隐式自监督"；证据 = 库内 4 篇新笔记；缺口 = 需要自己的消融；撞车风险 = 中（与第七章「技术适用性」正在写的内容重叠，但那条是**领域问题**视角，候选 E 是**可发表工作**视角）。

**默认处理**：在 5.3 写成一个**待定候选**（给主张/证据/缺口，不给优先级），并在文中标注"是否立项待定"。若用户决定立项，再更新原 `总结.md` 的候选列表（另开小改动）。

### 7. 新增一条主轴：两条主流范式与算力门槛（用户补充）

第①部分必须把下面这一刀讲清楚，它比“六条路线”更高一层：

**A. 视频基模（video foundation model）路线——当前最主流**

- 能力上限最高：全画幅、场景与全身动作一起出，整帧重绘，画面“生成力”不受源图约束。
- **代价是算力门槛高**：训练通常在**数张 A100** 量级，实时化还要额外做蒸馏与加速工程。
- 工程与就业相关性最高：这是当前工业界与招聘市场最认的方向。

**B. 动作潜空间（motion latent space）路线——我们更熟、不吃算力**

- **核心特征：把身份与动作分离**；工作**主要集中在面部**。
- 内部再拆成**两个动作**（这一拆是本节的关键结构）：
  - **B1 动作生成**：给定语音 / 文字等信息，生成真实动作（表情、嘴型、头姿）。代表：Ditto（265 维运动空间 + 条件 DiT）、FLOAT / Avatar Forcing（20 维运动子空间 + Flow）、LIA-X（40D motion code）。
  - **B2 画面生成（渲染器）**：有动作之后驱动画面。后端光谱与各自契约（引用 `knowledge/数字人渲染器专题.md`）：**SPADE 系**（LivePortrait，**Ditto 复用的就是这一套**：Appearance Feature Extractor + Face Renderer，隐式关键点 warp + SPADE 解码器）、**flow-warp + StyleGAN2 风格调制卷积**（LIA-X）、**加法解耦 decoder**（FLOAT / Avatar Forcing，$z=z_S+m_S$）、**FLAME / 3DMM**、**3DGS / NeRF 专人资产**。
- **渲染器契约互不兼容**：Ditto 的 265 维不能直接喂 LIA-X 的 40D，也不能喂 FLOAT 的 $r=B\alpha$——换渲染器等于换运动表示。这条边界必须写进汇报稿，对照表里也要体现。

**呈现方式**：一张“范式 → 能力上限 / 算力门槛 / 我们掌握程度 / 就业相关性”对照表 + 一张“B 范式内两级分解（B1 动作生成 → B2 渲染器）”的 Mermaid。

**与第③⑤部分的联动**：

- 第③部分加一条判断：**算力预算直接决定可选赛道**；视频基模是主流与就业风口，动作潜空间是我们当前的立足点与可低成本闭环的地方（观察 + 推断）。
- 第⑤部分在 30 天清单后补一句**方向选择待定项**：是否先在动作潜空间做出可发表工作再向视频基座迁移（标“待定”，不写成结论）。

**口径**：算力门槛只写“量级”（数张 A100）；渲染器细节引用 `论文笔记/ditto.md`、`论文笔记/liveportrait.md`、`knowledge/数字人渲染器专题.md`，不新造数字；SPADE 的出处（Park et al. 2019）与“StyleGAN2 风格积木”只属于 LIA-X 这一支，不要混写。
