## Why

需要一份**实习汇报稿**，五部分：① 什么是数字人、有哪些路线；② 实习期间做了哪些工作；③ 我们对数字人的思考；④ 领域有哪些核心问题；⑤ 我们能做什么事。

盘点现有材料后发现：**四部分已有存货，只有第三部分需要新写**：

| 汇报部分 | 现有素材 | 状态 |
|---|---|---|
| ① 数字人是什么 + 路线 | `数字人概述/数字人介绍与技术路线.md`（两轴框架 + 六条路线 + 动作表示/渲染后端谱系 + 评价体系）、`数字人关键技术地图.md`（13 张技术图 + 谱系 + 时间线）、`数字人行业全景.md` | ✅ 有，需**压缩合并**（178+481+76 行 → 汇报粒度） |
| ② 实习工作 | `数字人概述/总结.md`（实习背景与主线 / 核心工作导览 / 量化成果总表）+ 五篇专题（身份 / 动作 / 工程设计 / 加速 / 行业全景） | ✅ **现成**，基本可直接改写成汇报结构 |
| ③ 我们的思考 | **散落**在 `总结.md` 的「趋势判断」「选型结论」「工作方法沉淀」、各专题的「我们的结论」、`数字人领域问题` 各章的判据里 | ⚠️ **需新写**（本 change 的主要新增内容） |
| ④ 领域核心问题 | `数字人领域问题.md`（558 行，八章：身份 / 动作 / 实时性 / 路线 / 条件与任务定义 / 跨域问题 / 技术适用性 / 工程问题模型化） | ✅ 有，需压缩成汇报粒度 |
| ⑤ 能做什么 | `总结.md`（选题漏斗 + 候选 A–D + 决策建议 + 30 天清单） | ✅ 有，但**可能需要新增候选**（见 Decision 5） |

因此本 change 的实质是：**新建一份汇报稿，把 ①②④⑤ 压缩整合、把 ③ 新写出来**，并明确"汇报稿不新造数字、只提炼并指回原文"，避免形成第二份事实源。

## What Changes

- 新建汇报稿文档（落点与形态见 Decision 1），按五部分组织，每部分给**页面要点 + 可直接念的口播段**。
- 第 ③ 部分**新写**：把散落的 "我们的判断" 收成三类并列出——对**技术格局**的判断、对**方法论**的判断、对**工程与产品**的判断；每条标注「观察 / 推断」。
- 第 ① ④ ⑤ 部分做**压缩改写**：从长文中提炼到汇报粒度，数字与结论一律引用既有文档并注明来源，不重新表述、不新造。
- 第 ⑤ 部分评估是否需要**新增一个候选方向**（本轮调研新增了表示层/解耦与跟踪监督的素材，可能改变优先级）。
- 不改动被引用的既有文档（除非发现事实错误，另行提出）。
