## 4. 第三部分：我们对潜动作空间（扩散）数字人模型的理解（新写）

**判别标准**：缺陷 = 换掉实现也依然存在的限制（范式级）；能靠工程/外挂缓解的单列"变体级问题"。

- [ ] 4.1 3.1 **它是什么**：两级结构（低维运动生成 + 渲染器）；三个好处（实时/可控/身份复用）；两个代价。
- [ ] 4.2 3.2 **它靠什么成立**：假设"身份与运动可分解"；**三式对照表**（隐空间加法 / LivePortrait 式 / PerformRecast 式），点明"两项以什么方式组合"也是分解的一部分。
- [ ] 4.3 3.3 **四个固有限制**（范式级，每条给"是什么 → 导致什么失败 → 依据"）：
  - [ ] 4.3a **只解脸**（裁剪对齐脸框 ⇒ 换机位=重新生成一段；多人靠**逐框处理 + 贴回**解决（正确做法），代价是框外画面与框间遮挡不在表示里）
  - [ ] 4.3b **只能搬运不能合成**（warp 渲染 ⇒ 改不了服饰/场景；未观测区靠想象，几何不保证）
  - [ ] 4.3c ★ **运动侧没有角色条件**（身份只进 decoder ⇒ 运动分布天生角色无关 ⇒ **塌向均值**：AF 被动倾听、GDPO 静态脸；治理只能外挂/事后手算；语义控制靠逐维扰动反推）；**必须写两面性**（同源优点是"换参考图就换人"）
  - [ ] 4.3d **隐式运动空间与渲染器是私有契约**（三层绑定：语义/接口/训练耦合；四类后果：换后端=换表示、不能部件替换、跨模型组合难、生态碎片化；反面对照=ARKit blendshape 能标准化因为它独立于渲染器）
  - [ ] 4.3e 两条边界：限制 3 写"运动侧缺角色条件"，**不写"模型没有分布"**；限制 4 写"**隐式**运动空间"，**3DMM 系是弱绑定**；两句合起来给出一条取舍（越语义化越通用可编辑、越隐式越绑定）
