## 【待审核】正文大纲（到二级标题）

### 一、`## 为什么重要`
- 表达内容：身份是数字人的两个核心因素之一（呼应 intro 的"动作 × 身份"）；长视频与长对话里"越说越不像"直接破坏可用性；身份与音唇同步是并列门槛——**指标高不等于体验可用**
- 论证/结论：身份一致性不是画质问题，而是"还是不是同一个人"的问题；它和动作质量必须同时成立
- 素材：微调实践 §三引言、《digital-human-identity-consistency》的 CSIM 批判、LAF 反例

### 二、`## 现行做法`
- 2.1 `### 身份表示`
  - 固定身份 latent / 外观向量 `s`（Avatar Forcing 的 `z_S`、FLOAT 的 appearance `s`）
  - 参考图或参考视频直接驱动（one-shot 路线）
  - 3D 先验与资产（FLAME canonical space、3DGS/NeRF 专人资产）
  - 论证：表示决定后续能怎么约束——latent 可加法解耦，资产可复用但要训练成本
  - 引用：《数字人介绍与技术路线》"动作表示谱系 / 渲染后端谱系"；《数字人动作》表示谱系深挖
- 2.2 `### 注入与保持的做法`
  - 加法解耦：外观与运动分开，`x = 身份 + 运动`（FLOAT 系显式分解）
  - 推理期锚点引导（anchor guidance）：用该身份的特征字典约束每一步的走向
  - 训练期条件化：参考条件注入（单层/逐层拼接）、参考库构造
  - 区域抑制：flow suppression 压制下半脸/颈部区域的运动噪声
  - 论证：主流思路是"把身份钉住、把运动放开"，分歧在**在哪一层约束、用什么信号约束**
  - 引用：intro 的"动作生成与身份呈现的绑定关系"（接口契约与资产成本）
- 2.3 `### 一致性度量`
  - CSIM 系（FR embedding，如 ArcFace 特征余弦）、CSIM-drift、LPIPS-drift
  - 度量的固有裂缝：色彩/风格、时序漂移、环境变化、长时演变、指标同时充当 loss/奖励/选帧器（源自身份一致性度量综述的五类痛点）
  - 论证/结论：**CSIM 是借来的尺子**，风格化/长时/跨环境会失效；用单一指标裁决身份治理会误判
  - 引用：《数字人介绍与技术路线》评价体系（身份与长时漂移族）

### 三、`## 我们的工作`
- 3.1 `### 漂移诊断：两个假说先测后治`
  - 把每帧 motion latent 当向量：**模长 = 运动量，方向 = 走向**；两个候选解释——范数撑开（挤压身份）或方向游走
  - **假说 A（模长撑开）：否定**。300 秒视频分首/中/末三段测 `|r_d|`：GT 2.17/2.18/2.16（斜率≈0）、noguide 2.03/2.04/2.01（-0.01/min）、A1 2.09/2.09/2.09（≈0）——无持续增长
  - **假说 B（方向游走）：单身份支持**。夹角：noguide 10.1°→15.1°→17.5°（**+2.1°/min**，离 GT 方向字典最近邻峰值 24.8°），A1 3.4°→3.3°→2.5°（≈0，峰值 6.2°），GT 自身带宽 3~5°
  - **适用边界（必须写明）**：结果来自 c1 单身份 300 秒轨迹，不是跨身份结论
  - 论证/结论：证据不支持范数撑开、在单身份上支持方向游走 → 优先用"约束方向"的工程手段
- 3.2 `### 治理尝试与裁决`（按"尝试 → 结果 → 裁决"写，三种手段并行对照）
  - **推理期锚点引导 A1：GO**。`c_hi=0.99`，300 秒 CSIM 0.645 → **0.935**，后半段塌方消失，唇同步未观察到下降；边界是单身份实验，未写成通用部署默认值
  - **训练期参考条件化 v1：干净失败**。两个原因——训练库含答案（模型学会回放 GT，换库输出差 <0.001）、尾层单层注入容量不够；6/6 指标劣于零条件臂
  - **v2 设计：逐层拼接 + ref_mode（fixed/rolling/reset-N）→ 多 seed 裁决失败并回退**。同步反而退化（sync_c 5.342 vs 6.437；sync_d 10.022 vs 9.294），300 秒验证未执行
  - **Learned Anchor Force：指标高、体验不可用 → 终止**。双身份 300 秒 CSIM .728 > A1 .665、DINO .913 > .841，但三版人眼观察均头抖（motion flow .043 vs GT .022）
  - 论证/结论：身份治理的判据不能只看身份指标——**同步与动作稳定性会付出"税"**，必须同时看人工检查
  - **必须附 mermaid `flowchart TB`**：把整条路径画出来（身份漂移 → 两个假说 → 两次测量与结论 → 三种治理手段与裁决），一图看清"哪个被否定、哪个只在单身份成立、哪个回退）
- 3.3 `### 身份资产与参考提供`
  - 锚帧库 / 身份特征字典：怎么建、用多少帧、角距分布
  - 参考帧策略与训推一致性：fixed（恒首帧） / rolling（上一块尾帧） / reset-N；rolling 引入分布差，用扰动混合补偿的设计
  - 注入时机与成本：初始化一次编码身份 latent 与方向基准；推理期每步引导的开销
  - 代码落点（路径与常量写入 change 的整理记录，**正文不写出处**）：初始化编码 `s_r`、由 motion autoencoder 取方向基准 `r_s`、按 face bbox 开启 flow suppression（ratio 0.7）、`anchor_guide` 挂钩点
- 3.4 `### 微调类身份提升尝试（证据待补）`
  - 口述线索：用 ArcFace 系身份特征/loss 做微调提升身份一致性
  - **当前状态：知识库、博客、CyberVerse 代码三处均未检索到实验记录**（本文不编造数字）
  - 与该节并列的对比维度：是否动权重、训练成本、是否影响音唇同步、跨身份稳健性
  - 论证/结论：列为待补缺口，并在汇报中明示证据状态

### 四、`## 可能的改进方向`
- 夹角结论的多身份 / 跨素材复核（把"支持的假说"变成"主要机制"）
- 治理手段消融：A1（推理期）与条件化（训练期）在同一判据下对照；"身份指标 vs 同步 vs 动作稳定性"的三方评分表
- 身份资产协议：锚帧库表示、参考帧策略、注入时机能否标准化（呼应 intro 的"接口契约"）
- 度量侧：CSIM 之外的长时/跨环境指标接入评测流程

### 五、`## 汇报要点`
- 一页可直取：三个结论（模长否证 / 方向单身份支持 / A1 有效）+ 两个反例（v2 失败、LAF 头抖）+ 一个缺口（ArcFace 待补）

## Decisions

- **D1 素材不落仓库**：整理结果只在对话中提交审核；仓库只保留正文
- **D2 数字以实验记录版为准**：InternWiki 表格 vs 博客复述冲突时取前者，冲突记入对勘
- **D3 治理按"尝试—裁决"写**：三种手段并列（A1 GO / v2 失败回退 / LAF 终止）。旧契约把"参考条件化 v2"写成既定治理方案，现按最新证据改为**已归档失败**
- **D4 无证据不编造**：ArcFace 一节明示"证据待补"，不写任何数字
- **D5 正文不写出处**：代码路径与 commit 只记在 change 的整理记录里，正文不出现

## Risks / Trade-offs

- [夹角结论仅是单身份] → 正文与结论句都带适用边界，不写成普适机制
- [失败项写多了像负面清单] → 失败项只保留"结论 + 判据价值"，过程细节留在整理记录
- [与《数字人动作》交叉（latent 表示）] → 本文只到"身份侧怎么约束"，表示谱系深度链过去
