## 【待审核】正文大纲（到二级标题）

### 一、`## 为什么重要`
- 表达内容：身份是数字人的两个核心因素之一（呼应 intro 的"动作 × 身份"）；长视频与长对话里"越说越不像"直接破坏可用性；身份与音唇同步是并列门槛——**指标高不等于体验可用**
- 论证/结论：身份一致性不是画质问题，而是"还是不是同一个人"的问题；它和动作质量必须同时成立
- 素材：微调实践 §三引言、《digital-human-identity-consistency》的 CSIM 批判、LAF 反例

### 二、`## 身份表示与渲染后端`（**合并成一节，按主要路线叙述**）

- **配图 1**：`flowchart LR` 画"身份信号怎么走到画面"——参考图 → 三支身份信号（隐式关键点+外观 / 源肖像多尺度特征 / appearance code）→ 对应渲染器（warp / flow-warp / 加法解耦）→ 画面帧

- **为什么合并**：表示与渲染后端本来是一体的——**表示决定渲染器能吃什么，渲染器决定身份怎么落地**。拆成两节会来回重复（讲 LivePortrait 的表示必然要讲它的 warping renderer）。所以按**路线**组织，一条路线一次讲清"身份表示是什么 → 谁来落地身份 → 身份怎么被保持 → 有哪些主要方案与代表模型"。
- 开头一句话 + 结尾一张**跨路线对照表**（表给对比，正文给机制）：

  | 路线 | 身份表示 | 渲染后端 | 身份怎么被保持 | 换身份代价 |
  |------|---------|---------|--------------|-----------|
  | 2D 换嘴 / latent inpainting | 参考帧外观（像素/latent） | 局部 inpainting 解码器 | 只在嘴部区域重绘，其余像素原样保留 | 低：换参考帧 |
  | 动作空间 + 快速渲染器 | 身份 latent / 关键点 / 外观特征 | warping renderer、flow-warp decoder、加法解耦 decoder | warp 搬运参考外观，或让身份项在每步恒等（加法解耦） | 低：重新编码一张参考图 |
  | 视频基座模型 | 参考图 + 适配器条件 | DiT / 视频解码器（模型自带） | 身份长在权重或 LoRA 里 | 高：换适配器或重训 |
  | 3D 资产（学习式） | 3DGS / NeRF 资产 | 光栅化 / 体渲染 | 身份被训练进 3D 表示 | 高：重训 |
  | 3D 资产（参数化装配式） | mesh + blendshape/FLAME rig | 游戏引擎 / 离线渲染 | 身份在材质与 rig 资产里 | 中：美术重做 |
  | 掩码局部多人控制 | 参考图 + mask | 视频模型自带解码 | 掩码限定谁在被驱动，身份仍来自参考图 | 中到高 |

- 各路线小节（`###`，父标题是主题名，不是分类名）：
  - `### 2D 换嘴 / latent inpainting`：身份就是参考帧外观，渲染器做局部重绘——**MuseTalk**、SadTalker（学 3DMM 系数 + 3D-aware warping）
  - `### 动作空间 + 快速渲染器`（**我们的主线，写最细**）：这是身份表示最丰富的一路，按"身份信号从哪来"分三支：
    - 隐式关键点 + warping：**LivePortrait**（隐式关键点 + stitching/retargeting，身份=参考图外观）、Ditto renderer、**MegaPortraits / Face-vid2vid 血统**（canonical 身份容积）、FOMM 类
    - 外观特征 + flow-warp：**LIA-X**（源肖像身份/多尺度特征 + 40D motion code，身份特征单独注入）
    - appearance code + 加法解耦：**FLOAT / Avatar Forcing decoder**（512D appearance `s` 与 `r=Bα` 加法解耦，身份项每步恒等）
    - 写法要求：三支各讲"身份表示 → 靠什么保持 → 换身份贵不贵"，并点名代表模型；与《数字人动作》的边界——**动作表示谱系在那边，这里只讲身份那一半**
  - `### 视频基座模型`：身份当条件注入（参考图 + ReferenceNet/LoRA），没有独立渲染后端可换——**VASA-1**（latent + 扩散解码）、HunyuanVideo-Avatar、OmniAvatar
  - `### 3D 资产（学习式）`：身份就是训练出来的资产——GaussianTalker、GAGAvatar、UIKA、FlexAvatar（**不作为我们的重点，只作路线条目**）
  - `### 3D 资产（参数化装配式）`：mesh + blendshape/FLAME rig，身份在美术资产里——FLAME/3DMM 系、Audio2Face 类（标为二手、我们未实测）
  - `### 掩码局部多人控制`：参考图 + mask 指定说话人——HunyuanVideo-Avatar
- 边界：**《数字人介绍与技术路线》已有"渲染后端谱系"表（输入契约 + 替换难度）**，本文不重复整表，只从**身份视角**讲"身份信号从哪来、怎么保持、换身份多贵、代表模型是谁"；动作表示深度在《数字人动作》
- 素材：knowledge/《数字人渲染器专题》§二/§三；papers 库 LivePortrait（`arxiv-2407.03168`）、LIA-X（`arxiv-2508.09959`）、VASA-1（`arxiv-2404.10667`）、SadTalker（`arxiv-2211.12194`）、EchoMimic/AniPortrait/JoyVASA；代表模型中库内无条目者（MegaPortraits、FOMM）只点名不展开

### 三、`## 身份注入与保持`

- **配图 2**：`flowchart TB` 画四类注入路径 + 各自的**约束层与代价**（隐空间每一步 / 采样每一步 / 写进权重 / 渲染前运动流）

- **定位（与 5.3《锚帧库与参考图怎么选》的边界，必须写清）**：本节是**业界手法的横切归纳**（"现行做法"层）——回答"身份怎么进去"；5.3 是我们**自己**在资产侧的做法（"我们的工作"层）——回答"身份从哪来、给什么、给多少"。一句话：**本节讲投递方式，5.3 讲包裹内容**。
- 内容（四类注入路径，每类写"做什么 → 在哪一层约束 → 代价"）：
  1. **加法解耦**：外观与运动分开，身份做成每步恒等的常量项
  2. **推理期锚点引导**（anchor guidance）：用该身份的特征字典逐步约束生成方向；**时机与开销**：初始化一次编码身份表示，之后每步引导都带增量成本
  3. **训练期条件化**：参考条件注入（单层注入 vs 逐层拼接）
  4. **区域抑制**（flow suppression）：压掉某片区域（如下半脸/颈部）的运动噪声
- 论证：主流思路是"把身份钉住、把运动放开"，分歧在**在哪一层约束、用什么信号约束**；四类可叠加

### 四、`## 一致性度量`

- **配图 3**：`flowchart LR` 画"一把尺子兼四职"的循环——参考图与生成结果 → FR 编码器 → CSIM → 裁判／教练／奖励／球员，并标出教练与球员**反过来改变生成结果**（评测循环性）

- 写什么（**压缩写：写清"用哪把尺子、它会怎么失效、我们怎么用"，完整证据账本归论文笔记与《数字人行业全景》**）：
  1. **尺子不止一把，按三族写**（先给谱系，再落到我们实际用的）：
     | 族 | 代表度量 | 底层假设 | 边界 |
     |----|---------|---------|------|
     | **FR embedding 余弦族（事实标准）** | **CSIM**：两张人脸经同一个 FR 模型编码后算 embedding 余弦。常用编码器是 **ArcFace 系**（VBench-2.0 的 Human Identity、ConsisID 的 FaceSim-Arc），也有 **CurricularFace**（OpenS2V 的 FaceSim-Cur、PuLID 的评测尺）、**AdaFace**（ID-V2V）、FaceNet / CosFace 系 | FR embedding 是身份的忠实向量表示，余弦单调代理身份失配 | 照片域、裁剪对齐的单人近景；换一把 FR 编码器或换协议，排名可能翻转 |
     | **感知类** | DINO Subject Consistency（VBench 1.0）、CLIP-I（IP-Adapter / PuLID 的插入污染代理）、DreamSim | 人类感知的"像不像"可由通用视觉特征距离近似 | **身份不可知**：换了人但服装场景不变，全帧特征照样高分 |
     | **结构/生成类** | Arc2Face 反演（能否从 embedding 重建出人脸，用重建保真度探嵌入信息量） | embedding 含足够身份信息 ⇔ 存在生成器能逆回去 | 不产出可直接排名的分数；天花板就是嵌入容量 |

     - **专用 / 新生度量**（点名即可，不展开）：**CCIP**（人物重识别系编码器算相似度，在个性化生成里当一致性指标，**来源待核实**）、FaceSim-Arc / FaceSim-Cur、StyleID 的感知对齐度量 + StyleBench、**ID-Sim**（把 selective sensitivity 写成公理）、OpenS2V 的 NexusScore（弃用 FR，人脸身份单列 FaceSim-Cur）
     - **时序 / 漂移类**：CSIM-drift、LPIPS-drift（长时相对参考的偏离）；注意 Dino-S 量的是**相邻帧平滑**，不是身份漂移
     - **我们实际用的**：CSIM（ArcFace 系）为主线 + 人工检查；**我们试过把 CSIM 当训练 loss，最终放弃**（见 5.4）
  2. **尺子的出身**：CSIM 是从**人脸识别借来的**——FR 模型为"验证两张真实照片是否同一人"训练，生成社区挪用为"生成是否保持了参考身份"；它**不是为生成评测设计的，且没有标准化协议**（阈值、锚定方式（参考图 / 首帧 / 随机帧对）、预处理各论文自定）
  3. **五种失效场景**（用"用户会遇到什么"来写，不堆公式）：

     | 失效 | 用户语言 | 度量层的缺口 |
     |------|---------|-------------|
     | 照片域依赖 | 动漫 / 3D 渲染 / 素描角色跨图跨视频保脸，工具说"查无此人" | 参考落在非照片域时，照片域 FR 编码器外推失效 |
     | 时序漂移 | 片头像、片尾走样，排行榜身份分依然漂亮 | 协议不可靠：同一模型在双协议下排名会反转；随机帧对协议平均只覆盖约三分之一的端到端漂移 |
     | 环境不鲁棒 | 换个灯光、转个侧脸就被判成另一个人 | 对光照 / 姿态 / 遮挡缺少选择性不变性；大姿态下读数崩塌 |
     | 长时演变 | 角色跨十年成长或做过医美，系统认不出"还是她" | FR embedding 并非时不变身份表示；现有评测锚（参考图 / 首帧）全是静态 |
     | 风格化不可度量 | 把真人参考做成油画 / 赛博朋克后，身份保住几分没人答得出 | 风格化输出落在 FR 训练分布外，读数与人类判断脱钩（风格偏移被误判成身份变化、几何劣化被漏检） |

  4. **一把尺子身兼四职**：CSIM 同时被用作**裁判**（评测指标）、**教练**（训练 loss）、**奖励**（RL 奖励信号）、**球员**（选帧器）——当尺子同时是这四者，分数语义就失真："更高的 CSIM"未必等于"身份保持更好"，也可能只是"更会讨好这把尺子"
     - **我们的亲历**：把 CSIM 当**教练**（训练 loss）这条路我们自己走过并放弃了（见 5.4）——业界同类证据是 PuLID 的精确 ID loss：Identity 分数上去了，但文本可控性下降、面部变模糊。**"指标上去、体验没上去"不是别人的故事**
  5. **本文的用法（三条结论）**：
     - 身份指标只作**必要条件**，不作充分条件——指标不过一定不行，指标过了不代表可用
     - **必须配人工检查**：5.2 的 Learned Anchor Force 就是反例（CSIM 更高但三版人眼观察均头抖）
     - 跨域 / 长时 / 风格化场景要**显式声明度量边界**，不能拿照片域的数直接比
- 论证/结论：**CSIM 是借来的尺子且身兼多职**，用单一身份指标裁决治理方案会误判 → 全文一律"指标 + 人工检查"双轨
- 边界：P1–P5 的完整论证与证据账本归论文笔记（身份一致性度量综述）与《数字人行业全景》，本文只保留"尺子 + 裂缝 + 用法"
- 素材：knowledge/《digital-human-identity-consistency》§1.1（CSIM 定义与四重角色）、§1.3（P1–P5 表）；knowledge/《评测指标专题》的 CSIM / CSIM-drift 定义；博客 `id-sim-2026`、`digital-human-cartoon-stylized-evaluation`

#### 5.1 `### 漂移出在哪：模长还是方向`
- 诊断方法：把每帧 motion latent 当向量——**模长 = 运动量，方向 = 走向**；两个候选解释：范数撑开（挤压身份）或方向游走
- **假说 A（模长撑开）：否定**。300 秒视频分首/中/末三段测 `|r_d|`：GT 2.17/2.18/2.16（斜率≈0）、noguide 2.03/2.04/2.01（-0.01/min）、A1 2.09/2.09/2.09（≈0）——无持续增长
- **假说 B（方向游走）：单身份支持**。夹角：noguide 10.1°→15.1°→17.5°（**+2.1°/min**，离 GT 方向字典最近邻峰值 24.8°）；A1 3.4°→3.3°→2.5°（≈0，峰值 6.2°）；GT 自身带宽 3~5°
- **适用边界（必须写明）**：结果来自 c1 单身份 300 秒轨迹，不是跨身份结论
- 结论：不支持范数撑开、单身份支持方向游走 → 优先用"约束方向"的工程手段

#### 5.2 `### 三种治理手段与结果`（按"尝试 → 结果 → 裁决"写，三种手段并列）
- **推理期锚点引导 A1：GO**。`c_hi=0.99`，300 秒 CSIM 0.645 → **0.935**，后半段塌方消失，唇同步未观察到下降；边界是单身份实验，未写成通用部署默认值
- **训练期参考条件化 v1：干净失败**。两个原因——训练库含答案（模型学会回放 GT，换库输出差 <0.001）、尾层单层注入容量不够；6/6 指标劣于零条件臂
- **v2（逐层拼接 + ref_mode fixed/rolling/reset-N）：多 seed 裁决失败并回退**。同步反而退化（sync_c 5.342 vs 6.437；sync_d 10.022 vs 9.294），300 秒验证未执行
- **Learned Anchor Force：指标高、体验不可用 → 终止**。双身份 300 秒 CSIM .728 > A1 .665、DINO .913 > .841，但三版人眼观察均头抖（motion flow .043 vs GT .022）
- 结论：身份治理的判据不能只看身份指标——**同步与动作稳定性会交"税"**，必须同时看人工检查

#### 5.3 `### 锚帧库与参考图怎么选`
- **锚帧库 / 身份特征字典**：怎么建（用哪些帧、多少帧）、质量判据（角距分布）、库的好坏如何影响引导效果
- **参考帧策略与训推一致性**：fixed（恒首帧） / rolling（上一块尾帧） / reset-N 三档的取舍；rolling 信息量大但引入训推分布差，用扰动混合（p=0.3）补偿的设计
- **换身份的成本曲线**：换参考图 / 重建资产 / 重训各档的实际代价（与第二节"换身份代价"一列呼应，这里给我们的实测数）
- 代码落点（路径与常量只记在 change 的整理记录，**正文不写出处**）：初始化编码身份表示 `s_r`、由 motion autoencoder 取方向基准 `r_s`、按 face bbox 开启 flow suppression（ratio 0.7）、`anchor_guide` 挂钩点

#### 5.4 `### CSIM 当损失函数：已放弃`

- **术语先分清（正文要写对）**：
  - 我们做的是**把"身份相似度"这个度量直接当训练损失**——生成帧与参考帧各过同一个 FR 模型，优化两者 embedding 的余弦；只有参考图、没有身份标签，这是单身份微调唯一可行的形态
  - 这不等于"ArcFace 当 loss"：ArcFace 原论文的 AAM softmax 是**加性角度间隔分类损失**，要多个身份类别才能训练判别式人脸空间，不是我们这种场景
  - 三种叫法指同一件事：CSIM-as-loss（度量视角）/ ArcFace 余弦损失（编码器视角）/ **ID loss / Face Sim loss**（业界常用名，PuLID 的精确 ID loss 就是"对生成结果的 ArcFace 余弦做优化"）
  - 正文采用：**"身份相似度损失（ArcFace 系 embedding 的余弦）"**，并括注"也就是把 CSIM 这个度量当损失"，避免读者以为是 AAM 分类损失
- **放弃的原因（口述，已确认）**：加上这个身份相似度损失后，相似度确实是改善的（损失下降），但它**管不住脸部尺度漂移**——脸会越变越大、忽大忽小。而尺度漂移才是流式体验上最刺眼的问题，身份相似度损失对它是盲的。
  - 要写出的因果：**身份相似度是一个标量，漂移却有好几个维度**（模长、方向、尺度）——5.1 测的是模长与方向，这条损失管的是"像不像"，管不了"脸多大"。三者不重合，所以指标上去不等于漂移消失。
  - 这条漂移后来是在**流式侧按归一化处理**的（细节归《工程改进》），不属于身份损失能覆盖的范围。
- **依据状态**：放弃原因来自口述（已确认）；**指标记录仍待补**——知识库、博客、CyberVerse 代码三处均未检索到这次实验的数据，正文**不编造任何数字**
- 与 5.2 的相互印证：A1 有效、参考条件化与 LAF 回退、CSIM 损失放弃——三条路径合起来的判据是同一句：**盯着身份指标优化，会漏掉体验上的真实故障**
- 与本章其余手段的对比维度：是否动权重、训练成本、对音唇同步的影响、跨身份稳健性
