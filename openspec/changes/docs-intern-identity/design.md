## 【待审核】正文大纲（到二级标题）

### 一、`## 为什么重要`
- 表达内容：身份是数字人的两个核心因素之一（呼应 intro 的"动作 × 身份"）；长视频与长对话里"越说越不像"直接破坏可用性；身份与音唇同步是并列门槛——**指标高不等于体验可用**
- 论证/结论：身份一致性不是画质问题，而是"还是不是同一个人"的问题；它和动作质量必须同时成立
- 素材：微调实践 §三引言、《digital-human-identity-consistency》的 CSIM 批判、LAF 反例

### 二、`## 身份表示与渲染后端`（**合并成一节，按主要路线叙述**）

- **为什么合并**：表示与渲染后端本来是一体的——**表示决定渲染器能吃什么，渲染器决定身份怎么落地**。拆成两节会来回重复（讲 LivePortrait 的表示必然要讲它的 warping renderer）。所以按**路线**组织，一条路线一次讲清"身份表示是什么 → 谁来落地身份 → 身份怎么被保持 → 有哪些主要方案与代表模型"。
- 开头一句话 + 结尾一张**跨路线对照表**（表给对比，正文给机制）：

  | 路线 | 身份表示 | 渲染后端 | 身份怎么被保持 | 换身份代价 |
  |------|---------|---------|--------------|-----------|
  | 2D 换嘴 / latent inpainting | 参考帧外观（像素/latent） | 局部 inpainting 解码器 | 只在嘴部区域重绘，其余像素原样保留 | 低：换参考帧 |
  | 动作空间 + 快速渲染器 | 身份 latent / 关键点 / 外观特征 | warping renderer、flow-warp decoder、加法解耦 decoder | warp 搬运参考外观，或让身份项在每步恒等（加法解耦） | 低：重新编码一张参考图 |
  | 视频基座模型 | 参考图 + 适配器条件 | DiT / 视频解码器（模型自带） | 身份长在权重或 LoRA 里 | 高：换适配器或重训 |
  | 3D 资产（学习式） | 3DGS / NeRF 资产 | 光栅化 / 体渲染 | 身份被训练进 3D 表示 | 高：重训 |
  | 3D 资产（参数化装配式） | mesh + blendshape/FLAME rig | 游戏引擎 / 离线渲染 | 身份在材质与 rig 资产里 | 中：美术重做 |
  | 掩码局部多人控制 | 参考图 + mask | 视频模型自带解码 | 掩码限定谁在被驱动，身份仍来自参考图 | 中到高 |

- 各路线小节（`###`，父标题是主题名，不是分类名）：
  - `### 2D 换嘴 / latent inpainting`：身份就是参考帧外观，渲染器做局部重绘——**MuseTalk**、SadTalker（学 3DMM 系数 + 3D-aware warping）
  - `### 动作空间 + 快速渲染器`（**我们的主线，写最细**）：这是身份表示最丰富的一路，按"身份信号从哪来"分三支：
    - 隐式关键点 + warping：**LivePortrait**（隐式关键点 + stitching/retargeting，身份=参考图外观）、Ditto renderer、**MegaPortraits / Face-vid2vid 血统**（canonical 身份容积）、FOMM 类
    - 外观特征 + flow-warp：**LIA-X**（源肖像身份/多尺度特征 + 40D motion code，身份特征单独注入）
    - appearance code + 加法解耦：**FLOAT / Avatar Forcing decoder**（512D appearance `s` 与 `r=Bα` 加法解耦，身份项每步恒等）
    - 写法要求：三支各讲"身份表示 → 靠什么保持 → 换身份贵不贵"，并点名代表模型；与《数字人动作》的边界——**动作表示谱系在那边，这里只讲身份那一半**
  - `### 视频基座模型`：身份当条件注入（参考图 + ReferenceNet/LoRA），没有独立渲染后端可换——**VASA-1**（latent + 扩散解码）、HunyuanVideo-Avatar、OmniAvatar
  - `### 3D 资产（学习式）`：身份就是训练出来的资产——GaussianTalker、GAGAvatar、UIKA、FlexAvatar（**不作为我们的重点，只作路线条目**）
  - `### 3D 资产（参数化装配式）`：mesh + blendshape/FLAME rig，身份在美术资产里——FLAME/3DMM 系、Audio2Face 类（标为二手、我们未实测）
  - `### 掩码局部多人控制`：参考图 + mask 指定说话人——HunyuanVideo-Avatar
- 边界：**《数字人介绍与技术路线》已有"渲染后端谱系"表（输入契约 + 替换难度）**，本文不重复整表，只从**身份视角**讲"身份信号从哪来、怎么保持、换身份多贵、代表模型是谁"；动作表示深度在《数字人动作》
- 素材：knowledge/《数字人渲染器专题》§二/§三；papers 库 LivePortrait（`arxiv-2407.03168`）、LIA-X（`arxiv-2508.09959`）、VASA-1（`arxiv-2404.10667`）、SadTalker（`arxiv-2211.12194`）、EchoMimic/AniPortrait/JoyVASA；代表模型中库内无条目者（MegaPortraits、FOMM）只点名不展开

### 三、`## 身份注入与保持`

- 定位：**跨路线的注入手法清单**（不重复逐路线描述；路线里的具体做法放到第二节，我们的实测裁决放第六节）
- 内容：加法解耦（外观与运动分离）→ 推理期锚点引导（anchor guidance）→ 训练期条件化（参考条件注入、单层 vs 逐层）→ 区域抑制（flow suppression）
- 论证：主流思路是"把身份钉住、把运动放开"，分歧在**在哪一层约束、用什么信号约束**
- 引用：与第七节《治理尝试与裁决》呼应——那边是我们的实测裁决，这边是业界手段分类

### 五、`## 漂移诊断：两个假说先测后治`
  - 把每帧 motion latent 当向量：**模长 = 运动量，方向 = 走向**；两个候选解释——范数撑开（挤压身份）或方向游走
  - **假说 A（模长撑开）：否定**。300 秒视频分首/中/末三段测 `|r_d|`：GT 2.17/2.18/2.16（斜率≈0）、noguide 2.03/2.04/2.01（-0.01/min）、A1 2.09/2.09/2.09（≈0）——无持续增长
  - **假说 B（方向游走）：单身份支持**。夹角：noguide 10.1°→15.1°→17.5°（**+2.1°/min**，离 GT 方向字典最近邻峰值 24.8°），A1 3.4°→3.3°→2.5°（≈0，峰值 6.2°），GT 自身带宽 3~5°
  - **适用边界（必须写明）**：结果来自 c1 单身份 300 秒轨迹，不是跨身份结论
  - 论证/结论：证据不支持范数撑开、在单身份上支持方向游走 → 优先用"约束方向"的工程手段
### 六、`## 治理尝试与裁决`（按"尝试 → 结果 → 裁决"写，三种手段并行对照）
  - **推理期锚点引导 A1：GO**。`c_hi=0.99`，300 秒 CSIM 0.645 → **0.935**，后半段塌方消失，唇同步未观察到下降；边界是单身份实验，未写成通用部署默认值
  - **训练期参考条件化 v1：干净失败**。两个原因——训练库含答案（模型学会回放 GT，换库输出差 <0.001）、尾层单层注入容量不够；6/6 指标劣于零条件臂
  - **v2 设计：逐层拼接 + ref_mode（fixed/rolling/reset-N）→ 多 seed 裁决失败并回退**。同步反而退化（sync_c 5.342 vs 6.437；sync_d 10.022 vs 9.294），300 秒验证未执行
  - **Learned Anchor Force：指标高、体验不可用 → 终止**。双身份 300 秒 CSIM .728 > A1 .665、DINO .913 > .841，但三版人眼观察均头抖（motion flow .043 vs GT .022）
  - 论证/结论：身份治理的判据不能只看身份指标——**同步与动作稳定性会付出"税"**，必须同时看人工检查
  - **必须附 mermaid `flowchart TB`**：把整条路径画出来（身份漂移 → 两个假说 → 两次测量与结论 → 三种治理手段与裁决），一图看清"哪个被否定、哪个只在单身份成立、哪个回退）
### 七、`## 身份资产与参考提供`
  - 锚帧库 / 身份特征字典：怎么建、用多少帧、角距分布
  - 参考帧策略与训推一致性：fixed（恒首帧） / rolling（上一块尾帧） / reset-N；rolling 引入分布差，用扰动混合补偿的设计
  - 注入时机与成本：初始化一次编码身份 latent 与方向基准；推理期每步引导的开销
  - 代码落点（路径与常量写入 change 的整理记录，**正文不写出处**）：初始化编码 `s_r`、由 motion autoencoder 取方向基准 `r_s`、按 face bbox 开启 flow suppression（ratio 0.7）、`anchor_guide` 挂钩点
