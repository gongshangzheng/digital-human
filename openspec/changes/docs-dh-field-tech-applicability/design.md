## Context

`数字人概述/数字人领域问题` 现有六章，各自的组织单位是**问题**（身份难在哪、动作难在哪、实时性难在哪）或**我们的选择**（路线）。没有任何一章的组织单位是**一个外来技术**。而这类判断已经在正文里以单条形式出现过两次（`### 面部解剖先验：知识从哪里进训练回路`、`### 身份一致性判别器：缺的是什么，要满足什么条件`），说明需求真实，但没有固定形态、无法累积、也没有统一的评估维度。

第六章「跨域问题」名字接近但含义不同：它讲研究域 ↔ 业务域（数据分布、合规、复现），不是外来技术 → 数字人的接口评估。

用户提出的第一个正式条目已经明确：**1D 视觉分词器（TiTok 一类，"An image is worth 32 tokens"）能不能用在数字人**——具体到"从视频里提取角色身份""从一帧里提取动作信息"。这个技术的背景资料库内已有：博客的 `titok-1d-visual-tokenizer-survey`（含 TiTok 的 263 篇引用整理，以及"我们自己的 ProgressiveDiTok 与双流编码器"定位）。

## Goals / Non-Goals

**Goals：**

- 新增 `## 七、技术适用性`，**以技术为组织单位**，让"某个技术能不能用在数字人领域"成为一等问题。
- 给每个条目定死五个评估维度，使条目可累积、可比较、可复现判断过程：原生优化目标 / 数字人侧要什么 / 表示与接口是否匹配 / 可检验判据 / 已知证据与代价。
- 首个条目写 1D 视觉分词器，并把"同一个技术、三条迁移路径、三套判据"这件事演示出来（提身份 / 提动作 / 管线侧压缩）。
- 每个条目的结论都要区分**论文或他人已证**、**我们的推断**、**未验证**；不得把推断写成结论。
- 同步 frontmatter `summary` 与开头分类段。

**Non-Goals：**

- 不写成"技术选型指南"（不排序、不推荐采购），只回答"能不能用、用来干什么、卡在哪"。
- 不把 §四「路线」的内容搬过来：那章讲我们自己的生成路线，本章讲外来技术。
- 不为 1D 分词器补跑实验；所有结论标为未验证或引述他处。
- 不改其余六章任何内容；不为本章重排既有章节编号顺序（七加在最后）。
- 不引入正式参考文献列表（与全文"内联点名"风格一致）。

## 1. 章节定位与标题

- **位置**：`## 七、技术适用性`，加在 `## 六、跨域问题` 之后（用户确认"可以添加一个第七章"）。
- **标题候选**（用户要求"重新拟一个，核心点在技术"）：
  1. **`## 七、技术适用性`（推荐采纳）** —— 最短、以技术为主语，与"身份 / 动作 / 实时性 / 路线"同级的名词短语风格一致；
  2. `## 七、单点技术适用性` —— 更强调逐条看；
  3. `## 七、外来技术适用性` —— 点出"来自别域"，但视角偏回数字人；
  4. `## 七、技术能不能用` —— 最直白，但与前六章风格不一致。
- **小节命名约定**：`### <技术名>：能不能用在数字人做什么，卡在哪`。条目内不出现"迁移/跨域/引进"这类以我们为主语的词。
- **章首一段**要写清组织方式：本章按技术组织，每条给原生目标、接口匹配、可检验判据与代价；与 §四（我们的路线）、§六（研究↔业务）的分工各一句。

## 2. 条目的固定结构（五维度）

每个 `###` 条目按同一顺序展开，避免写成随笔：

| 维度 | 要回答的问题 | 写作要求 |
|---|---|---|
| 技术是什么 | 一句话 + 原生域 + 代表工作 | 只写必要的原信息，不复述论文 |
| 原生优化目标 | 它在原来那个域里为了什么而优化 | 必须点明**它不优化什么**（这是判断的关键） |
| 数字人侧要什么 | 对应到数字人任务的具体要求 | 引用既有章节已定义的要求，不重新发明 |
| 表示与接口是否匹配 | 维度 / 时序性 / 因果性 / 可控性 / 可比性 | 逐项判"匹配 / 不匹配 / 需改造" |
| 可检验判据 | 用什么实验判定能用或不能用 | 判据要写死指标；引用既有判据（如身份章的 selective sensitivity、动作章的 LSE-C/LSE-D） |
| 已知证据与代价 | 已验证 / 我们的推断 / 未验证 | 三者必须分列；代价含流式冲突、算力、数据 |

## 3. 首个条目：1D 视觉分词器 → 从视频提身份

**标题**：`### 1D 视觉分词器：能不能用视频 token 提身份`

**技术是什么（三个实例，两篇笔记已完成）**：

| 粒度 | 代表 | 关键设定 | 笔记 |
|---|---|---|---|
| 图像 1D | TiTok（NeurIPS 2024，"An image is worth 32 tokens"） | 一张图压成少量（默认 32）1D token | — |
| 视频 1D · 自适应 + **块级因果** | **AdapTok**（arXiv:2505.17011） | 按帧内容密度分配 token 预算；因果粒度是**块**（每块 4 帧）；分配依据是**重建质量**（感知损失） | `论文笔记/adaptok`（已完成） |
| 视频 1D · **不变/变分分解** | **TivTok**（arXiv:2606.17590） | TIV（跨帧共享语义，论文明确含"物体身份"）/ TV（逐帧残差）；SIF 非对称注意力范围让分解**涌现**、IB 广播复用；**编码非时间因果** | `论文笔记/tivtok`（已完成） |

**参照基线**：**Face Vid2vid**（`论文笔记/face-vid2vid`，已完成）从**单张图**提身份（隐式 3D 关键点 + 外观 + canonical 容积）。本条要问的是"**一段视频里用 token 能给出多少身份、比单图多给了什么**"。

**原生优化目标**：重建保真度 + 压缩率 + 生成先验；AdapTok 另优化"预算按内容密度分配"，TivTok 另优化"跨时间复用"。三者的共同缺项是——**都不优化判别性、都不优化身份可比性**；TivTok 的解耦是**架构涌现**（无显式监督），不是被优化出来的。

**数字人侧要什么**（引用 §一 已定义的 selective sensitivity，不重新发明）：跨条件稳定、对合法变化（姿态/表情/机位/风格化）不变、**可比对**（能算相似度）、可跨风格使用。

**表示与接口是否匹配**（用两篇的实测事实逐项判）：

| 维度 | 判定 | 依据 |
|---|---|---|
| 维度 | ✅ 匹配 | TivTok-T128 只用 128 token、T-P 比 0.012%，比 512 维单帧嵌入紧凑得多 |
| 身份—运动解耦 | ✅ TivTok 有机制、❌ AdapTok 没有 | TivTok §4.5 明确：TIV 抓**语义不变**（含物体身份与外观），**运动物体只要身份稳定也可进 TIV**，TV 只负责姿态/位置 |
| 时序性 | ⚠️ 双刃 | 视频 token 会把运动一起编码；AdapTok 靠"块内可变长"缓解，TivTok 靠 TIV/TV 分工缓解，但都没有身份侧的约束 |
| 因果性 | ✅ AdapTok（块级，每块 4 帧）；❌ TivTok（编码非因果，TIV 需看全 clip） | 两篇的机制决定；这是两者的核心取舍 |
| 可控性 | ⚠️ 部分 | TivTok 可用 TIV 数量与 TIV:TV 比例调节容量；AdapTok 可调平均预算；都没有语义级控制 |
| 可比性 | ❌ 未知 | 两篇都没有涉及"token 距离是否代理身份失配" |

**可检验判据**（五条，全部写死指标）：

1. **TIV 的身份纯度**（TivTok 专属）：把 TIV 换成另一段视频的、保持 TV 不变，看身份是否随之改变、背景是否也跟着变——分解 TIV 里"身份"与"场景"各占多少。论文的滑冰者例子说明它**可能**主要抓人物外观，但只是定性证据。
2. **跨条件可比性**：同一角色跨姿态/表情/机位/风格时 token 表示的距离分布，对比换人时的分布是否可分（直接复用 §一 的 selective sensitivity 判据）。
3. **与单图基线对照**：同一批样本上，视频 token 身份表示与 Face Vid2vid 式单图身份表示在跨机位/跨表情下谁更稳——这是"从视频提身份值不值"的直接回答。
4. **与现成身份编码器的排序一致性**：token 距离与 ArcFace 系嵌入余弦在同一批样本上的排序是否一致。
5. **因果化改造的代价**：TivTok 的思路若要用于流式，需要把"全局 TIV"换成"跨块递推的 TIV 状态"，评估改造后的质量损失（两篇都没做这个消融）。

**已知证据与代价**：两篇笔记已完成，本条的机制事实可直接引用；代价有三——TivTok **编码非因果**（接流式需改造）、AdapTok 按**运动/复杂度**分配预算而身份恰在运动之外、两者都**没有身份监督**因而可比性无保障。

**预判（我们的推断，未验证）**：

- **TivTok 的 TIV 是目前最接近"身份载体"的现成机制**：它明确把"身份与外观稳定"归入不变量分支，且是架构涌现的。但必须由判据 1 证明纯度——TIV 的语义里同时含场景几何与背景。
- **AdapTok 提供因果与预算，但不解耦**；两者互补：理想形态是"TIV/TV 分解 + 块级因果 + 自适应预算"，**目前没有任何一篇同时具备**。
- **"视频优于单图"不能先验判断**：视频信息更多，但引入了身份—运动解耦与因果化两个新问题；必须由判据 3 回答。

**同一技术的另两条路径（判据不同，本条只用一段带过）**：

- **提动作**：需要低维、连续、因果可流式、逐帧可对齐；单帧全局语义 token 给不出"这一帧相对上一帧转了多少"，大概率卡在接口而非画质；判据是 LSE-C/LSE-D 与逐帧关键点误差。
- **管线侧压缩传输**：判据是带宽/时延/重建质量/与生成器兼容，指向博客的 `gvcc-zero-shot-video-compression`、`contour-video-compression-survey`，以及我们自己的 ProgressiveDiTok / 双流编码器（见博客 `titok-1d-visual-tokenizer-survey`）。

## Risks / Trade-offs

- [把推断写成结论] → 第 2 节的五维度表强制"已验证 / 我们的推断 / 未验证"三分列；路径 A、B 的预判句都带"我们的推断，未验证"。
- [与 §四 路线章重复] → Decision 4 划界；本章"接口匹配"一栏只引用路线章结论，不复述。
- [写成技术选型或采购建议] → Non-Goal 明确：不排序、不推荐，只回答能不能用、用来干什么、卡在哪。
- [章名被判成"迁移/跨域"的近义词] → 采纳 `技术适用性`；正文避免以我们为主语的"迁移/引进"等词。
- [首个条目太长] → 按"技术原信息（2 段）+ 五维度表 + 三条路径（各 4 项）+ 证据与代价"控制，约与 §一 的判别器条目同量级。
- [博客素材与库内风格不一致] → 只做定位与判据设计，不搬运博客结论数字。
