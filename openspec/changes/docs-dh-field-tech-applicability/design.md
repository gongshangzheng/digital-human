## Context

`数字人概述/数字人领域问题` 现有六章，各自的组织单位是**问题**（身份难在哪、动作难在哪、实时性难在哪）或**我们的选择**（路线）。没有任何一章的组织单位是**一个外来技术**。而这类判断已经在正文里以单条形式出现过两次（`### 面部解剖先验：知识从哪里进训练回路`、`### 身份一致性判别器：缺的是什么，要满足什么条件`），说明需求真实，但没有固定形态、无法累积、也没有统一的评估维度。

第六章「跨域问题」名字接近但含义不同：它讲研究域 ↔ 业务域（数据分布、合规、复现），不是外来技术 → 数字人的接口评估。

用户提出的第一个正式条目已经明确：**1D 视觉分词器（TiTok 一类，"An image is worth 32 tokens"）能不能用在数字人**——具体到"从视频里提取角色身份""从一帧里提取动作信息"。这个技术的背景资料库内已有：博客的 `titok-1d-visual-tokenizer-survey`（含 TiTok 的 263 篇引用整理，以及"我们自己的 ProgressiveDiTok 与双流编码器"定位）。

## Goals / Non-Goals

**Goals：**

- 新增 `## 七、技术适用性`，**以技术为组织单位**，让"某个技术能不能用在数字人领域"成为一等问题。
- 给每个条目定死五个评估维度，使条目可累积、可比较、可复现判断过程：原生优化目标 / 数字人侧要什么 / 表示与接口是否匹配 / 可检验判据 / 已知证据与代价。
- 首个条目写 1D 视觉分词器，并把"同一个技术、三条迁移路径、三套判据"这件事演示出来（提身份 / 提动作 / 管线侧压缩）。
- 每个条目的结论都要区分**论文或他人已证**、**我们的推断**、**未验证**；不得把推断写成结论。
- 同步 frontmatter `summary` 与开头分类段。

**Non-Goals：**

- 不写成"技术选型指南"（不排序、不推荐采购），只回答"能不能用、用来干什么、卡在哪"。
- 不把 §四「路线」的内容搬过来：那章讲我们自己的生成路线，本章讲外来技术。
- 不为 1D 分词器补跑实验；所有结论标为未验证或引述他处。
- 不改其余六章任何内容；不为本章重排既有章节编号顺序（七加在最后）。
- 不引入正式参考文献列表（与全文"内联点名"风格一致）。

## 1. 章节定位与标题

- **位置**：`## 七、技术适用性`，加在 `## 六、跨域问题` 之后（用户确认"可以添加一个第七章"）。
- **标题候选**（用户要求"重新拟一个，核心点在技术"）：
  1. **`## 七、技术适用性`（推荐采纳）** —— 最短、以技术为主语，与"身份 / 动作 / 实时性 / 路线"同级的名词短语风格一致；
  2. `## 七、单点技术适用性` —— 更强调逐条看；
  3. `## 七、外来技术适用性` —— 点出"来自别域"，但视角偏回数字人；
  4. `## 七、技术能不能用` —— 最直白，但与前六章风格不一致。
- **小节命名约定**：`### <技术名>：能不能用在数字人做什么，卡在哪`。条目内不出现"迁移/跨域/引进"这类以我们为主语的词。
- **章首一段**要写清组织方式：本章按技术组织，每条给原生目标、接口匹配、可检验判据与代价；与 §四（我们的路线）、§六（研究↔业务）的分工各一句。

## 2. 条目的固定结构（五维度）

每个 `###` 条目按同一顺序展开，避免写成随笔：

| 维度 | 要回答的问题 | 写作要求 |
|---|---|---|
| 技术是什么 | 一句话 + 原生域 + 代表工作 | 只写必要的原信息，不复述论文 |
| 原生优化目标 | 它在原来那个域里为了什么而优化 | 必须点明**它不优化什么**（这是判断的关键） |
| 数字人侧要什么 | 对应到数字人任务的具体要求 | 引用既有章节已定义的要求，不重新发明 |
| 表示与接口是否匹配 | 维度 / 时序性 / 因果性 / 可控性 / 可比性 | 逐项判"匹配 / 不匹配 / 需改造" |
| 可检验判据 | 用什么实验判定能用或不能用 | 判据要写死指标；引用既有判据（如身份章的 selective sensitivity、动作章的 LSE-C/LSE-D） |
| 已知证据与代价 | 已验证 / 我们的推断 / 未验证 | 三者必须分列；代价含流式冲突、算力、数据 |

## 3. 首个条目：1D 视觉分词器 → 从视频提身份

**标题**：`### 1D 视觉分词器：能不能用视频 token 提身份`

**技术原信息（三种粒度，同一个技术家族）**：

| 粒度 | 代表 | 关键设定 |
|---|---|---|
| 图像 1D | TiTok（NeurIPS 2024，"An image is worth 32 tokens"） | 一张图压成少量（默认 32）1D token；动机是 2D tokenizer 的 token 数与分辨率绑定（256×256 → 16×16=256 token）且每个 token 只含局部信息 |
| **视频 1D · 自适应 + 时间因果** | **AdapTok**（arXiv:2505.17011，`Learning Adaptive and Temporally Causal Video Tokenization in a 1D Latent Space`，代码 `VisionXLab/AdapTok`） | 按帧内容密度**动态分配** token 预算，且 tokenization 本身**时间因果**——直接对上我们两条硬约束 |
| 视频 1D · **时间不变/时变分解** | **TivTok**（arXiv:2606.17590，`TivTok: Broadcasting Time-Invariant Tokens for Scalable Video Tokenization`，2026-06，清华 Weiliang Chen 等） | 把一个 clip 拆成 **TIV（Time-Invariant）token**（跨帧共享的信息）与 **TV（Time-Variant）token**（逐帧残差）；SIF 给两组不同注意力范围（TIV 看整段、TV 只看本帧+TIV），解码端用 Invariant Broadcasting 把同一批 TIV 跨帧跨块复用。128 帧压缩效率 +2.91×，token 数仅 downsample 类的 1.1% |

**参照基线（我们已有的单图身份提取路线）**：**Face Vid2vid**（`论文笔记/face-vid2vid.md` 已完成）从**单张图**提身份——隐式 3D 关键点 + 外观，配合 canonical 容积。它回答的是"一张图能给出多少身份"；本条要问的是"**一段视频里用 token 能给出多少、且是否比单图更好**"。

**原生优化目标**：重建保真度 + 压缩率 + 生成先验（token 序列可被自回归/扩散建模）；AdapTok 额外优化 token 预算的分配效率与时间因果性。**不优化**身份判别性、**不优化**身份—运动的解耦、**不优化**跨条件可比性——这三条决定了下面判据怎么写。

**数字人侧要什么**（引用 §一 已定义的 selective sensitivity，不重新发明）：跨条件稳定、对合法变化（姿态/表情/机位/风格化）不变、**可比对**（能算相似度）、可跨风格使用。

**表示与接口是否匹配**（逐项判）：

| 维度 | 判定 | 说明 |
|---|---|---|
| 维度 | 匹配 | 少量 1D token 比 512 维单帧嵌入更紧凑，天然适合做身份表示 |
| 时序性 | **双刃** | 视频 token 会把**运动**一起编码进来——身份需要跨帧稳定，而 token 序列携带的恰恰是随时间变化的量，必须先解决"哪些 token/哪些维是身份、哪些是运动" |
| 因果性 | AdapTok 匹配、TivTok 需确认 | AdapTok 明写时间因果，可直接用于流式；TivTok 的时间因果性需查证 |
| 可控性 | 不匹配 | tokenizer 本身不提供控制接口，控制要靠下游 |
| 可比性 | **未知** | token 距离是否单调代理身份失配，没有任何保证 |

**可检验判据**（四条，均写死指标）：

1. **身份信息量**：把一段视频的 token 聚合成一个身份表示后，能否在跨机位/跨表情/跨风格下与同一人另一段视频配对成功——按 §一 的 selective sensitivity 判据做分布可分性，而不是只看重建。
2. **身份—运动解耦度**：固定身份、改变动作（不同语音/不同驱动视频）时身份表示的漂移量，对比固定动作、改变身份时的漂移量；两者应显著分开。
3. **与单图基线对照**：同一批测试样本上，视频 token 身份表示与 Face Vid2vid 式单图身份表示在跨机位/跨表情条件下的一致性谁更好——这是"从视频提身份到底值不值"的直接回答。
4. **与现成身份编码器的排序一致性**：同一批样本上，token 距离与 ArcFace 系嵌入余弦的排序是否一致（作为可比性的代理检验）。
5. **TIV 的身份纯度**（TivTok 专属）：把 TIV token 换成另一段视频的、保持 TV 不变，看身份是否随之改变、背景是否也跟着变——用来分解 TIV 里"身份"与"场景"各占多少。这条判据决定了 TIV 能不能直接当身份表示，还是必须先做一次过滤/条件化。

**已知证据与代价**：库内已有 1D tokenizer 的系统调研（博客 `titok-1d-visual-tokenizer-survey`，含六大改进方向与我们的 ProgressiveDiTok / 双流编码器定位）与 AdapTok 快读草稿；**我们没有跑过任何数字人侧实验**，下面预判全部标为推断。

**预判（我们的推断，未验证）**：

- **AdapTok 与 TivTok 各对准一个硬约束，且互补**：AdapTok 的"按内容密度分配预算 + 时间因果"对上"流式 + 算力"；TivTok 的 TIV/TV 分解对上"身份—运动解耦"这个核心难点。理想形态是两者叠加（TIV/TV 分解 + 时间因果 + 自适应预算），但没有任何一篇同时具备，需要先各自验证再谈组合。
- **TivTok 直接对准解耦难点**：它把"跨帧共享"与"逐帧残差"在构造上分开，几乎是为"从视频提身份"准备的接口。但有一个必须验证的前提——**TIV 的定义是"时间不变"，不是"身份"**：静态背景、固定服装、恒定光照同样会被收进 TIV。所以真正要问的是"TIV 里身份占多少、场景占多少"（见判据 5）。
- **"从视频提身份"未必优于单图**：视频带来更多信息（多机位、多表情），也带来身份—运动解耦的额外难题；Face Vid2vid 的单图路线仍有可能是更稳的基线。这一点必须用判据 3 回答，不能先验判断。

**同一技术的另两条路径（判据不同，本条只用一段带过）**：

- **提动作**：需要低维、连续、因果可流式、逐帧可对齐；单帧全局语义 token 给不出"这一帧相对上一帧转了多少"，大概率卡在接口而非画质；判据是 LSE-C/LSE-D 与逐帧关键点误差。
- **管线侧压缩传输**：判据是带宽/时延/重建质量/与生成器兼容，指向博客的 `gvcc-zero-shot-video-compression`、`contour-video-compression-survey`。

**素材与阅读安排**：AdapTok 与 TivTok 已登记进 `论文笔记/README.md` 待读清单（状态 `待写`）；本章写正文前应先完成这两篇的笔记，避免只有标题级的判断。（早前按误听登记过的 `vidtok.md` 一行已撤，不再作为对照保留。）

## Risks / Trade-offs

- [把推断写成结论] → 第 2 节的五维度表强制"已验证 / 我们的推断 / 未验证"三分列；路径 A、B 的预判句都带"我们的推断，未验证"。
- [与 §四 路线章重复] → Decision 4 划界；本章"接口匹配"一栏只引用路线章结论，不复述。
- [写成技术选型或采购建议] → Non-Goal 明确：不排序、不推荐，只回答能不能用、用来干什么、卡在哪。
- [章名被判成"迁移/跨域"的近义词] → 采纳 `技术适用性`；正文避免以我们为主语的"迁移/引进"等词。
- [首个条目太长] → 按"技术原信息（2 段）+ 五维度表 + 三条路径（各 4 项）+ 证据与代价"控制，约与 §一 的判别器条目同量级。
- [博客素材与库内风格不一致] → 只做定位与判据设计，不搬运博客结论数字。
