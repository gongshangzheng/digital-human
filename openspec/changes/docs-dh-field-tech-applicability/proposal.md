## Why

`数字人概述/数字人领域问题` 现在是六章（身份 / 动作 / 实时性 / 路线 / 条件与任务定义 / 跨域问题），**没有一章以"某个技术能不能用在数字人"为对象**。这个模式其实已经以单条形式出现过两次：

- `### 面部解剖先验：知识从哪里进训练回路`（§二 动作，`ff970b9` 补入）—— 本质是"外部知识能否进训练回路"，只是被归在动作章下；
- `### 身份一致性判别器：缺的是什么，要满足什么条件`（§一 身份）—— 形式上是"外部度量接进来要满足什么条件"，但只覆盖身份判别这一个技术。

结果是：每次要讨论一个外来技术，都得临时塞进某一章，既没有固定评估维度，也无法累积。用户提出把"1D 视觉分词器（TiTok 一类，An image is worth 32 tokens）能不能用来从视频提身份 / 从一帧提动作"作为一个正式问题讨论——这正是需要一个**以技术为主语**的常设章节。

第六章「跨域问题」不是这个：它的"跨域"指研究域 ↔ 业务域（数据分布、合规、复现），不是"外来技术 → 数字人"的接口评估。

## What Changes

- 新增 `## 七、技术适用性` 一章，**以技术为组织单位**：每个 `###` 讨论一个技术，标题写成 `<技术名>：能不能用在数字人做什么，卡在哪`。
- 章内每个条目固定按五维度评估：原生优化目标 / 数字人侧要什么 / 表示与接口是否匹配 / 可检验判据 / 已知证据与代价；"已验证"与"未验证"分开写。
- 首条目：**1D 视觉分词器 → 从视频提身份**。技术实例取三粒度：TiTok（图像 1D）、**AdapTok**（arXiv:2505.17011，自适应 token 分配 + 时间因果的 1D **视频**分词）、**TivTok**（arXiv:2606.17590，时间不变/时变 token 分解：TIV 跨帧复用 + TV 逐帧残差）；参照基线取 **Face Vid2vid**（单图提身份，已有笔记），把问题定为"**一段视频里用 token 能给出多少身份、是否优于单图**"。
- 给出四条写死指标的可检验判据：身份信息量（selective sensitivity 分布可分）、身份—运动解耦度、与单图基线对照、与现成身份编码器的排序一致性。
- 把 AdapTok 与 TivTok 登记进 `论文笔记/README.md` 待读清单（状态 `待写`），因为本章首条目的判断需要先完成这两篇的笔记，不能停在标题级。
- 同步更新 `数字人领域问题` 的 frontmatter `summary`（六章 → 七章）与开头的分类说明段（补一句第七章的归类口径）。
- 明确与既有章节的分工：§四「路线」是我们自己的生成路线选择；§六「跨域问题」是研究↔业务；本章是外来技术 → 数字人的适用性评估。
