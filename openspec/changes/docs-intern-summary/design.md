# Design: docs-intern-summary（含待审核大纲）

## Context

- 伞 change 登记表 #8，全套文档体系的**收口篇**；依赖 1–7。
- 目标读者：**自己**（汇报 + 发文决策 + 后续推进）。
- 三个职责：**给一张总图**（做了什么、成果有多少）· **沉淀方法**（哪些做法可复用）· **产出发文方向**（选题漏斗 + 证据盘点 + 撞车扫描 + 决策建议）。
- 按方案 B：**选型结论**与**趋势判断**由《数字人行业全景》汇入本篇（那两件是"判断"，与"事实"分家）。
- 正文目标路径：`management/docs/实习复盘/总结.md`

## Goals / Non-Goals

**Goals：** 一页能读懂的主线 + 一张不新造数字的量化成果总表 + 可复用的方法沉淀 + 可执行的发文方向。
**Non-Goals：**
- **不新造证据**：数字全部从 1–7 篇搬运，逐项标注来源
- 不重复各篇的技术细节（链过去）
- 不写"将胜出"式的趋势定论（观察与推断分开标）

## 【待审核】正文大纲（11 节 / 2 张图）

## 第一部分 总览

### 一、`## 实习背景与主线`

- 方向与目标：会议面试官数字人；要回答的核心问题——**实时、可控、可插拔的数字人系统怎么做出来**
- **时间轴与工作线**（配图 1）：三路线调研 → 选型结论 → 模型接入与统一接口 → 实时化与工程优化 → 身份/动作治理 → 沉淀为文档体系
  - 调研阶段：前端三条路线（2D talking-head / 3D 高斯头像 / 扩散式生成）→ 前馈式 3D 资产方向
  - 接入阶段：模型统一接口、插件化、管理模块迁移
  - 优化阶段：贴回、传输与发布、音频链路、会话生命周期（→《工程设计》）
  - 治理阶段：身份漂移诊断与治理、动作侧中文适配与眼嘴拆分（→《数字人身份》《数字人动作》）
- **配图 1**：`flowchart LR` 时间轴与工作线（标出每段的主要产出）

### 二、`## 核心工作导览`

- 每条工作一段，统一句式"**问题 → 方法 → 结果一句话**"，并链到对应篇：
  - **身份**：长视频漂移 → 先测模长与方向两个假说 → 模长被否证、方向单身份支持、锚点引导把 300 秒相似度从 0.645 提到 0.935
  - **动作**：原模型听不懂中文音频 → 蒸馏桥 + 几何约束 + 关系蒸馏 → 同步指标优于对照锚；另加眼嘴拆分的四层机制
  - **工程设计**：生成帧要贴回、要稳定发出去 → 贴回六阶段 + 传输与发布设计 + 生命周期兜底 → 丢包隐藏占比 3.6% → 0.022%、会话约 35 秒回收
  - **数字人加速**：GPU 预算只剩几毫秒余量 → 生成侧与系统侧两条路径 → Decoder 推理 4.2×、首响应 3.5s → 2.9s；同时明确"局部变快 ≠ 用户侧变快"
  - **行业全景**：市场与实测事实 → 竞品五层栈 + 待复跑清单
- 结论：五条线各自独立，合起来是"一个能跑起来的实时数字人系统"

### 三、`## 工作方法沉淀`

把可复用的做法单独抽出来（这是本篇对后续最有价值的一节）：

- **任务树管理**：以任务为单位记录"目标 / 范围 / 验收 / 非目标"，进展按时间追加，状态如实标注（进行中不写成已完成）
- **实验记录与负结论**：**负结论与正结论同等保留**——例如打断止声的四版方案全部被推翻、参考条件化的两轮失败、某个"不可用"结论被复测推翻；判据要写清（人眼 / 听感 / 指标）
- **证据等级**：待复跑 → 初步观察 → 已复现 → 已否决，每档规定"能写什么、不能写什么"
- **探针与消融方法**：
  - 注入点先审计再消融（路径后缀精确匹配 + 打印命中清单）
  - 隐式表示靠**扰动观察反推**控制映射（眼 / 嘴索引就是这么来的）
  - 先分层定位瓶颈（音频表征 / 桥 / 生成 / 渲染 / 口径），再决定改哪一层
- **共享脚手架协作**：把通用能力（隐藏配置、文档系统、排序等）标为共享项并登记回灌，避免每个项目重造

### 四、`## 量化成果总表`

- 按主题分组的数字表（**逐项标注来源篇目**，不新造）：
  - **身份**：模长三段表、夹角 +2.1°/min、A1 引导 0.645 → 0.935、条件化 v2 同步退化数字、LAF 指标与头抖
  - **动作**：桥系列指标（6.299 / 8.853 对 6.122 / 9.044）、注入点收益 +0.39、全开放代价 4.565 对 5.719 对 5.483
  - **工程**：丢包隐藏 2.5–3.6% → 0.022%、会话回收 35 秒、RSS 9.8 → 20.5GB、贴回 p95 67.3 → 12.7ms、RTF 0.698 → 0.588、TTFF 1.39 → 1.18s
  - **加速**：GPU 合计 38.5ms 对 40ms 预算、Decoder 4.2×、编码 679ms 拆解、首响应 3.5 → 2.9s
  - **平台**：论文库规模、知识库规模、文档体系篇数（这些是"资产计数"，不算技术成果，单列）
- 表下写一句：**所有数字均可回溯到对应篇目**，本篇不做二次加工

### 五、`## 选型结论`（由《数字人行业全景》汇入）

- 三路线调研 → 前馈式 3D 资产 → 最终体系：**CyberVerse（框架）+ AvatarForcing / Ditto（模型插件）**
- 依据：动作空间路线便于实时化与逐区域控制；前馈式建资产成本低、便于换形象；框架把模型变成插件
- 代价与未选：整帧视频基座训练推理重；专人 3D 资产换形象要重训；多卡大模型方案被硬件门槛排除

### 六、`## 趋势判断`（由《数字人行业全景》汇入）

- 三条结构性关系，**逐条标注"观察"或"推断"**：模型层与推理层的开源共生 · 开源做底座与闭源做产品 · 芯片厂商沿技术栈向上渗透
- 一条方向性推断：**"合成问题"正在变成"编辑问题"**（改内容、改表情强度、动注视点、改语速，同时保持身份）
- 写法纪律：不写"某路线将胜出"式定论

## 第二部分 发文方向

### 七、`## 选题漏斗`

- 把全部工作倒进漏斗，三层筛选（配图 2）：
  1. **有第一手证据**（不是二手综述）
  2. **有增量**（相对已有工作解决了一个别人没解决的困难）
  3. **有可复现实验**（补实验的成本可承受）
- **配图 2**：`flowchart TB` 选题漏斗（工作线 → 候选 → 推荐主攻）

### 八、`## 候选 A 身份漂移的诊断与治理`

- **主张**：把"身份漂移"从现象拆成可测的维度（模长 / 方向 / 尺度），并给出推理期锚点引导的有效性与边界
- **已有证据**：三段模长表、夹角曲线（+2.1°/min）、A1 引导 0.645 → 0.935、两组失败（训练期条件化、学习式锚力）
- **缺口**：单身份（c1）300 秒，跨身份未验证；尺度漂移只有流式侧归一化处理，缺机制解释
- **要补的实验**：多身份 × 多素材复核夹角结论；治理手段在同一判据下消融（身份 / 同步 / 动作稳定性三项 + 人工检查）
- **撞车风险**：见 1.5 的 related-work 扫描结果

### 九、`## 候选 B 流式 Talking-Head 系统论文`

- **主张**：系统层的工程设计与优化本身可以成文——贴回设计、发布节奏、音频链路、缓存与生命周期
- **已有证据**：贴回三轮迭代与参数、丢包隐藏 3.6% → 0.022%、发布节奏稳态 1.000、贴回像素 max diff 为 0
- **缺口**：需要一套"系统级指标"来支撑论文叙事（目前是工程指标）
- **要补的实验**：与至少一个开源实时系统同协议对照（端到端延迟分解 + 主观评测）
- **撞车风险**：与现有实时数字人系统的工程报告重叠度高，需要明确增量

### 十、`## 候选 C 数字人评测基准`

- **主张**：身份/同步/动作的评测口径混乱，可以做一套**协议明确、可复现**的数字人评测
- **已有证据**：三族尺子的梳理与失效分析、指标口径不统一的具体数字（换子集 0.46–0.73、跨集 0.466 → 0.242）、我们自己踩过的评测坑
- **缺口**：要走候选 C 必须**自建多模型同协议评测**（评测协议、锚定方式与编码器选择都要自己定），前期成本高
- **要补的工作**：重跑多模型同协议评测；补齐长时与跨环境指标；给出可执行协议（锚定方式 / 预处理 / 编码器选择）
- **撞车风险**：赛道已有多个 benchmark 工作，必须差异化

### 十一、`## 候选 D 动作分层与听态生成`

- **主张**：动作是分层能力（音唇 → 情绪与听态 → 手部/全身），当前层的"听态"缺乏评价口径，是可以切进去的空位
- **已有证据**：桥系列适配结果、眼嘴拆分四层机制、听态实现路径（双路条件编码）
- **缺口**：听态没有评价指标；手部与全身未接入
- **要补的实验**：听态评价口径的设计与验证；情绪可控性的可编辑接口
- **撞车风险**：偏"机制组合"，需要更强的单点创新

### 十二、`## 决策建议`

- 优先级排序 + 理由（证据完整度 × 增量 × 补实验成本）
- **下一步 30 天清单**：多身份复核夹角、听态评价口径、候选 B 的同协议对照、候选 C 的重跑范围评估

## Decisions

- **D1 不新造证据**：所有数字从 1–7 篇搬运并标注来源；本篇只做组织与判断
- **D2 观察与推断分开**：趋势判断逐条标注性质
- **D3 素材不落仓库**；**D4 正文不写出处**（篇目名可点名，不写路径与 commit）
- **D5 配图 2 张**：时间轴与工作线图、选题漏斗图
- **D6 标题规范**：不用桶标题、标题不用冒号、文内引用用 heading 链接
- **D7 与《行业全景》的分工**：本篇放判断（选型、趋势、发文），行业全景放事实

## Risks / Trade-offs

- [总结容易写成流水账] → 主线只保留"调研 → 选型 → 接入 → 优化 → 治理"五段，细节全部链出去
- [候选方向写成愿望清单] → 每个候选必须给"已有证据 / 缺口 / 要补的实验 / 撞车风险"四栏，缺一栏就不算候选
- [候选 C 需要自建评测，成本高] → 在决策建议里如实拉开优先级，并把"重跑范围评估"列入 30 天清单
