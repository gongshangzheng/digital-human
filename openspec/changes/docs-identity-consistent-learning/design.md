## Context

- **来源**：本 change 由 `docs-motion-space-modeling` 的讨论中派生——那条线解决"学*怎么动*"，本 change 解决"学*是谁*"。
- **新命题**：**如何从【一个视频 / 多段视频 / 多视角照片】学出角色的【身份】，并让它在【多种动态】下保持一致。**

### 共享上游命题（与 `docs-motion-space-modeling` 共同持有；**双向必须同步**）

> **身份 = 一条轨迹里【不变】的部分；运动风格 = 这条轨迹里【变化】的部分。**

一条轨迹 $\alpha_{1:T}$ 的分解：

$$\alpha_{1:T}\;\xrightarrow{\ \text{分解}\ }\;\big(\underbrace{s}_{\text{轨迹里【不变】的部分}},\ \underbrace{\{\alpha_t\}}_{\text{轨迹里【变化】的部分}}\big)$$

**两件事是同一个分解问题的两个输出** —— 这解释了为什么它们总是纠缠（`数字人领域问题` §一 `### 说话风格` 原话：「身份回答'是谁'，风格回答'这个人怎样说话、怎样动'。**两者容易纠缠**」）。

**为什么两个 change 共享它**：素材同一份（一段视频），且**物理上真的耦合**（「脸型决定了笑起来什么样」）—— 强行拆干净反而失真。正解是 **共享表示 + 解耦约束**（disentangled representation 的标准范式：共享底层 + 独立分量 + 约束）。他们已在旁边见过这个套路：EDTalk++ 的**四个正交空间** · PSM 的**逐人 vs 通用两层**。

**⚠ 但分界不是先验给定的**：

```
低头 / 抬头幅度   算「不变」（身份）还是「变化」（风格）？
脸部尺度变化      算身份漂移还是风格？
眨眼频率          算身份还是习惯？
```

**这正是实测里「模长 / 方向 / 尺度」三条漂移曲线之所以有歧义的根源** —— 不是测得不准，是**分界本身没定义**。

> **「划分线在哪里」本身就是本方向要研究的第一个对象**，不是可以假定的前提。

**分解质量的三条指标（取代「另造一把尺子」）**：

| # | 指标 | 负责侧 |
|---|------|-------|
| **①** | **不变分量确实不变**（沿轨迹方差小） | 身份侧 |
| **②** | **变化分量确实承载风格**（跨角色可分） | 风格侧 |
| **③** ★ | **两者不互相渗透**（交换任一分量，另一分量统计不变） | 解耦侧 —— **这就是标准的解耦检验 / 条件替换** |

**这一条把原本的「可分性判据」从额外难题变成了分解本身的评价指标。**

**分工**：

```
共享上游   不变 / 变化分解的【定义与划分线】
本 change  分解出的【变化分量】怎么学成该角色的运动先验 / 风格
另一个     分解出的【不变分量】怎么跨动态 / 跨视角不漂
```

  - `数字人概述/数字人领域问题` §一：`身份一致性：长视频为什么会漂` · **`多参考注入：从一张图到任意多角度`** · **`切分镜与多视角：换机位之后还是不是同一个人`** · **`说话风格：从几张图或一段视频学到"这个人怎么说话"`** · `风格化：跨风格评测与风格化程度` · **`身份一致性判别器：缺的是什么，要满足什么条件`**

- **已有判据侧的硬要求**（`### 身份一致性判别器`）：输出**至少三个通道** —— **身份一致性**（只对身份类变化敏感）· **质量可信度**（对劣化单调下降）· **时序漂移量**（模长 / 方向 / 尺度三条曲线）；并列出**不该扣分的合法变化**（口型、表情、姿态、机位、光照、风格化、正常时间演化）与**必须惩罚的非法变化**（换人、画质、尺度漂移、遮挡塌陷、跨机位重置、多人归属、时序漂移量）。

### 已产调研（第一份）

`research/identity-consistent-learning.md` —— 回答两问：**① 为什么只用单帧提身份、面临什么困难；② 从多帧/视频提身份的尝试与成败原因**。

**⚠ 该文件是在网络故障下写的**（OpenAlex/arXiv/Google 不可达，只有 Crossref 通），因此**没有做新检索**；每条都标了证据等级（**【仓】** 仓库素材 / **【核】** 已验证 / **【常】** 常识·推断），并列了 **6 项待核实**（含 `BlendFace` 原文、VFR 聚合近年进展、以及 ★**身份与运动表示的分离判据是否已有工作**）。

**两个核心判断（须写进后续契约）**：
1. **VFR（识别）与头像生成（生成）对身份的需求不同** → 多帧聚合的经验不能直接搬：识别要**判别性向量**（多帧纯收益）；生成要**能重建所有视角外观的表示**（多帧给覆盖，**不给跨视角自洽**）。
2. **多帧聚合的隐含前提是循环的**：它假设「这些帧属于同一身份」，**而这正是我们要保证的东西** → 训练多帧必须来自身份已知的数据，否则会把**运动差异当身份差异**去学（v1 的坑）。

**第二版补搜的关键结果（会改变表述强度）**：

- **身份 / 运动分离这个上游命题已有三篇直接邻居** —— `RASA: Disentangled Spatial-Motional Priors`（2026, arXiv 2608.28219，原话「**the inherent entanglement of two capabilities: cross-identity spatial mapping and motion control**」）· `Facial Animation with Disentangled Identity and Motion using Transformers`（*CGF* 2022, cites=15，**motion manifold** + 解耦）· `Style-Disentangled Diffusion`（ICASSP 2026，multi-ID 学个人风格 + style disentanglement）
  → **共享上游命题不能宣称是「我们发现的问题」**；增量必须锚在 **① 时间不变性这条轴**（RASA 是能力分离、CGF'22 是表示分离、本项目是「一条轨迹里不变 vs 变」）· **② 逐角色**（RASA 是跨身份驱动）· **③ 单角色单视频**
- **单目歧义的根因已被命名**：`FlexAvatar`（2025）——「**entanglement between driving signal and target viewpoint**」；解法 = **单目+多视角统一训练 + canonical 锚**（`AniGS` CVPR 2025, cites=13：生成式多视角 canonical 图 resolve 歧义）
- **属性泄漏已被命名**：`BlendFace`（ICCV 2023, cites=58）—— ArcFace 的 **attribute biases** 导致 identity-attribute entanglement
- **VFR 三件套 2017 年就成型**：`Neural Aggregation Network`（CVPR 2017, cites=421，变长输入 + 双注意力聚合）· `Attention-Aware Deep RL`（ICCV 2017, cites=199，丢弃混淆帧）· `Eigen-PEP`（2015, cites=134）

**另新增一条必须写进契约的推论**：**单帧不是退让，是解耦架构的一部分**（多帧会让 $s$ 带上运动统计，破坏 $z=s+r$ 的可加解耦）→ 要把多帧引入，**必须先解决「多帧如何不把运动带进 $s$」**。

## Decisions

- **DC1** 本 change 与 `docs-motion-space-modeling` 是**并列两半**（身份 / 运动风格），**必须显式互引并划界**。
- **DC2** **不得重复** `数字人身份` 的漂移诊断与 `digital-human-identity-consistency` 的 CSIM 裂缝分析；只引用。
- **DC3** 所有外部工作标"**本轮已核实 / 未核实**"；**不得**把覆盖面说成穷尽。
- **DC4** **必须回答"身份 vs 风格的可分性判据"** —— 不做这一步，两篇文章都会不可信。
- **DC5** 必须沿用"**先测上界**"方法：先在**真实数据**上测跨动态/跨视角的可分性，再谈方法。
- **DC6** 任何"跨动态/跨视角保持一致"的宣称，**必须同时报随机基线与真实上界**（与 `docs-motion-space-modeling` 的 DC45 同协议）。
- **DC7** 本 change **只建骨架与调研**，不写文章正文（D1 可改）。
- **DC8** **必须写出「单帧是解耦架构的一部分」**（不只是习惯/成本），并据此说明**多帧引入的前置条件**：不得把运动统计带进身份表示。
- **DC9** **必须区分「识别」与「生成」对身份的需求**（判别性向量 vs 可重建所有视角的表示），不得把 VFR 的经验直接搬到生成侧。
- **DC10** **必须写出多帧聚合的循环前提**（「这些帧属于同一身份」正是待证目标），并规定训练多帧须来自身份已知的数据。
- **DC11** 本 change 的调研若在**网络受限**下产出，**必须标注证据等级与待核实清单**。
- **DC12** 必须写出**共享上游命题**（身份 = 轨迹里不变的部分；风格 = 轨迹里变化的部分；两者是同一个分解问题的两个输出），并与 `docs-motion-space-modeling` **双向互引、保持同步**。
- **DC13** 必须写出**分界不是先验给定的**，并明确「**划分线在哪里**」是共享上游要研究的第一个对象；**这也是与另一半划界的落点**。
- **DC14** 必须用**分解质量三指标**（① 不变分量沿轨迹方差小 ② 变化分量跨角色可分 ③ **交换任一分量另一分量统计不变**）；③ 即标准**解耦检验 / 条件替换** —— 这也是本 change「身份 vs 风格可分性判据」（DC4）的**落地形式**。
- **DC15** 本 change 只负责**【不变分量】**；**不得**把变化分量（运动风格）的建模纳入本 change 范围。
- **DC16** **共享上游命题必须写明它已被实现过**：`Facial Animation with Disentangled Identity and Motion using Transformers`（*CGF* 2022）原话「disentangles the **constant facial identity** from the **time-varying facial expressions**，using two separate codes … within **separate latent subspaces**」——**与本项目命题逐字同构**（for 3D mesh sequences）；`RASA`（2026, arXiv 2608.28219）是同类最新（**分阶段** + **显式丢弃 shape 参数 $\beta$、只用 articulation $\theta$** 得 strict geometry invariance）；`DSfusion`（ICASSP 2026）在**风格**侧。**增量严格收窄为四条**：**① 长时漂移与漂移率 ② 划分线必须从数据学（20 维 $\alpha$ 没有 SMPL $\beta/\theta$ 这类自带分工） ③ 逐角色 + 单角色单视频 ④ 视频生成侧**；**不得**宣称该分解是我们发现或首次实现。
- **DC17** **单目歧义的表述必须用已被命名的根因**（`FlexAvatar`：「entanglement between driving signal and target viewpoint」），并把「单目+多视角统一训练 + canonical 锚」列为**待评估解法**（不是本项目发明）。
- **DC18** **属性泄漏必须引 `BlendFace`**（ICCV 2023, cites=58），**不得**只凭 `数字人身份` 的转述。
- **DC19** **VFR 的「变长 + 注意力聚合 + 质量感知选帧」三件套必须引 2017 年三篇**（NAN cites=421 / ADRL cites=199 / Eigen-PEP cites=134），**不得**把「任意数量输入」当成 UIKA 的首创。

## Risks / Trade-offs

- **[身份与风格纠缠 ⇒ 两个 change 互相污染]** → DC4 强制先定可分性判据
- **[与现有文档重复]** → DC2 只引用不复制；须在 design 里列出"增量在哪"
- **[跨机位一致性没有普遍协议 ⇒ 结论不可比]** → 待调研 2；若确无协议，须自建并说明代价
- **[多视角照片被误当作能提供运动风格]** → 待调研 5；预期不能（与另一半的 DC36 一致）
- **[度量与另一半重叠]** → D8 划界
- **[`DOCS_FOLDER_ORDER` 未登记导致排序错位]** → 落地时同步登记
- **[调研覆盖面不足被当作"没有工作做过"]** → DC3 禁止穷尽性断言
