## 4. 完整章节结构（到三级标题）

### 4.1 `## 为什么重要`

**要论证**：为什么需要一篇按问题组织的文档，以及它怎么用。
**必须写到**：身份/动作/实时性是三条**并列门槛**（不是三选一）；路线是**手段**不是问题；本篇与相邻文档的分工（一句一个）。
**结论**：读论文前先定位问题域，能避免「把路线当问题」这类最常见的误读。
**不放**：领域重要性论证（已在《介绍与技术路线》的「为什么重要」，这里只讲「为什么要问题地图」）。
**规模**：约 800 字符。

### 4.2 `## 一、身份`

#### `### 身份一致性：长视频为什么必漂`

**要论证**：身份一致性不是「像不像」的标量问题，而是三个独立难题叠加——**度量不统一、长时漂移、风格化失效**。
**证据**（论文声称，数字为原文口径）：

| 证据点 | 出处 | 数字 |
|---|---|---|
| CSIM 五大缺陷（风格化失效、时序漂移、环境不鲁棒、长时身份演变、**度量循环性**） | 系列十八《身份一致性》 | 16 篇深读为证据 |
| 评测基准之间打架 | Face Consistency Benchmark | 6 个 FR 量尺分歧达 **2.7 倍**；「有锚/无锚」双协议**排名反转**；最强模型距真实视频仍差 **1.25–4 倍**；两种协议分数相差约 **3 倍** |
| **CSIM 的天花板** | Arc2Face | 纯 ArcFace 条件 + 2100 万图，未见 ID 的 CSIM 峰值 **≈0.85** |
| 风格化下 CSIM 失效 | StyleID | Cross-Method TPR **0.37 → 0.74**；手绘集 AUROC **0.9922** |
| 新度量路线 | ID-Sim | 49 个评测场景拿下 **48** 项第一 |
| 长时稳定的机制差异 | 系列五《扩散基模》、LiveAvatar、LeapTalk | LiveAvatar **10,000+ 秒**稳定（History Corrupt / AAS / Rolling RoPE，5×H800）；LeapTalk 用 reference 锚定的布朗桥把生成改成 data-to-data，长视频身份几乎不漂 |
| 多轮场景下的同一问题 | OmniMate | 用 MRCM（多参考图 + 参考语音）当**持久身份锚**，把「一段视频不漂」升级为「跨轮不漂」 |

**结论**：论文说「解决了身份一致性」时，说的是**自己协议下**的解决；跨论文比 CSIM 等于比不同的尺子。度量侧正从「FR 余弦」转向按感知/身份选择性训练的编码器。
**放进图中**：一条 Mermaid——同一句「身份一致」下的三条互不相同的失败（度量失效 / 长时漂移 / 风格化失效）。
**规模**：约 2,600 字符。

#### `### 多参考注入：从一张图到任意多角度`

**要论证**：身份注入的主线正在从「逐身份优化」转向「**一次前馈、任意数量无位姿输入**」，代价是训练算力与「专用化」。
**证据**：

| 工作 | 声称解决 | 机制 | 数字 |
|---|---|---|---|
| UIKA（CVPR 2026 Highlight） | 任意数量 **pose-free** 图像 → 可驱动 3DGS 头部 | UV 引导显式对应 + 双流注意力，一次前馈 | 渲染 **220 FPS**；7500+ 合成身份；**32×H20 × 2 周** |
| FlexAvatar | 1~4 张**无位姿**输入、无表情标签 | Head Query token 聚合 + UV 空间 UNet 解形变 | 重建 **0.4s**、驱动 **22ms/帧**（45 FPS）；2150 身份；10s 可选 refinement |
| CoFE / MoFE | **大姿态**下身份不「换人」 | ArcFace/CLIP/DINOv2 三专家 + 逐 DiT 层门控 | FaceSim-Arc **0.770/0.814**；+18.5% 参数；LaFID-180K |
| ConsisID | DiT 时代的身份注入失灵 | 按频率拆：低频 GFE 拼潜变量 + 高频双塔 cross-attn | FaceSim-Arc **0.58**（ID-Animator 0.32）；**+0.5B** 参数 |
| Arc2Face | 纯 ID 条件能把一致性推多高 | 用 ArcFace 嵌入替换文本条件 | 训练 **21M** 图 / **1M** 身份；用户研究 **71%** 胜过 InstantID |
| AniGS / LHM / MATCH | 单图或多视图 → 可动画资产 | 多视角生成 + 4DGS / 前馈 Transformer / registration-guided attention | AniGS ~**10 分钟**；LHM **2.01s**、PSNR **22.003**（AniGS 18.681）；MATCH **0.5s/帧**、45.3h → **4.63h**（**10×**）、570fps 渲染 |

**结论**：多参考注入的能力已经到「随手几张照片」，但三件事仍失守——**大姿态**（CoFE 存在的理由）、**风格化**（度量与身份定义同时失效）、**成本**（UIKA 的算力、FlexAvatar 的 scaling 曲线仍在上升）。
**规模**：约 2,500 字符。

#### `### 切分镜与多视角：换机位之后还是不是同一个人`

**要论证**：数字人交付里常有「切分镜 / 换机位 / 多视角」的需求；它的技术难点不在渲染，而在**跨机位（跨视角）的身份与外观一致性**——换机位之后还是不是同一个人、光照与背景是否连续。因此它归身份域：**能不能做**由路线决定，**判据与度量**属于身份。
**证据**：

| 层面 | 事实 | 出处 |
|---|---|---|
| **谁能换机位** | 3D 资产天然支持新视角合成——MATCH 在 **novel view synthesis** 上全面超越前作；LAM 是**纯 3D 管线、0 后处理网络**（**280 FPS**）；HyperGaussians **300 FPS**；参数化装配式（ARKit 52 + 游戏引擎）里多机位是传统图形管线的标配（我们未实测） | MATCH / LAM / HyperGaussians；系列四 |
| **谁换不了** | 2D 路线输出是**固定机位的人脸裁剪**：MuseTalk **256² 人脸区**；Talker-T2AV 以 **512² 为中间生成尺寸**再逐帧 FaceCropper 贴回源分辨率；Avatar Forcing / Ditto 同理。换机位 = 另生成一段新机位的片段 | MuseTalk / Talker-T2AV 精读 / 《工程设计》 |
| **多视角自身也会不一致** | AniGS 的观察：扩散模型生成的**多视角图像之间存在视角间不一致**，它把这种不一致当作「4D 高斯的时间维度变化」来处理 | AniGS |
| **视角是数据与生成里的显式变量** | MEAD **7 个同步视角**（60 人 / 281K clips / 39h）；NeRSemble-v2 **16 相机**（73fps / 7.1MP）；UIKA Synthetic **9 视角**（7500+ 身份 × 9 视角 × 13K+ 帧）；GenBench 把**视角**列为生成条件之一 | `knowledge/数据集整理专题` |
| **度量侧主动忽略了视角** | ID-Sim 的目标是「对背景/**视角**/光照**不变**」的身份相似度——即身份度量把视角差异当作**应当被忽略的干扰**，而不是需要度量的一致性；Face Consistency Benchmark 的双协议（有锚保真 / 无锚帧间相干）都只测**同一段视频内**，不测跨机位 | ID-Sim / FCB |
| **综述已把它列为独立质量维度** | FPSP v8 的十条质量维度里含 **「视角/几何一致性」**，并指出十条之间互相牵制 | 综述地图 |
| **我们的位置** | 我们的链路是单机位：生成帧是裁剪区域，再贴回原画面（见《工程设计》的贴回六阶段） | 《工程设计》 |

**结论**：切分镜/多视角在**能力**上由路线决定（3D / 参数化可换，2D 只能重生成），但在**问题**上属于身份——需要的是「跨机位仍是同一个人、且光照背景连续」的判据，而这个判据现在**不存在**：身份度量刻意对视角不变，现有基准只测同段视频内。这与《介绍与技术路线》里「表现范围」没有通用量化指标是同一处空白的两个侧面。
**规模**：约 1,700 字符。

#### `### 说话风格：从几张图或一段视频学到「这个人怎么说话」`

**要论证**：这一条现有三个入口，各自解决「风格从哪来」，**都不解决「风格与身份解耦」**。
**证据**：

- **几何解耦入口**：MakeItTalk —— 把输出压到 **68×3** landmark 相对位移，用 voice conversion 把音频拆成 content（说什么）/ speaker（谁在说）；只在真人数据上训练却**零样本**驱动油画/素描/日漫/卡通；28 FPS；**6480** 条 MTurk 响应
- **显式风格条件入口**：CapTalk —— 首个文本引导风格化的 3D 说话头；CapTalkingHead **24,441 clips / 200.8 小时**多模态风格标注；多尺度二值量化 Codec + T5 文本条件自回归；LVE **6.44**、FFD **25.14**；User Study 对 SelfTalk 偏好 Sync 92% / Style 96% / Expression 98%
- **few-shot 适配入口**：EmoTaG —— **5 秒**个性化视频、**11 分钟**适配、**76.4 FPS**、60K FLAME-Gaussians；情绪运动来自 GRMN + Semantic Emotion Guidance
- **风格化域的数据与评测**：ToonTalker（跨域卡通-真实双向重演）、Co-Speech NPR（非真实感角色）、GenEAva（135 类细粒度表情数据集）、系列十三（风格化评测方法论）
- **风格作为前缀**：Talker-T2AV 的 `--gt-prefix-seconds`（N>0 时用参考音频 + motion 前 N 秒借用韵律、节奏、头动风格）

**结论**：「学说话风格」目前**不是**一个被解开的单一问题，而是三条互不通用的技术：几何解耦换跨域能力、文本条件换可控性、few-shot 适配换数据效率。共同缺口是**风格与身份的混淆**，以及风格化域没有可信的身份/风格度量。
**规模**：约 2,200 字符。

#### `### 这一块的未解问题`

**要论证**：把前面三节收成一张缺口清单。
**必须写到的八条**：① 统一身份度量（表示 / 监督信号 / 评测协议三个轴上的空位）；② 长时漂移的端到端机制（历史状态、参考锚点、位置编码、误差抑制四件套）；③ **跨轮一致性**（多轮对话中身份不漂，目前只有 MRCM 这类单点做法）；④ 大姿态；⑤ 风格化下「身份」的定义本身；⑥ 多参考「几张才够」的判据缺失；⑦ 风格与身份的显式解耦；⑧ **跨机位一致性**——切分镜/多视角缺的不是渲染能力，而是「换机位仍是同一个人」的判据（身份度量刻意对视角不变，基准只测同段视频内）。
**规模**：约 1,100 字符。

### 4.3 `## 二、动作`

**归类原则（要写进正文，代替「N 个子问题」这类固定数目）**：四个域各回答一个不同的问题，**子问题是开放集合**——会随调研继续增加，所以正文**不写「有几个子问题」**，也不给编号清单。

| 域 | 回答的问题 | 收录判据 |
|---|---|---|
| 身份 | **还是不是同一个人、长什么样** | 一切关于身份/外观（含多参考、跨机位、跨轮、风格、度量）的问题 |
| 动作 | **怎么动** | 一切行为侧的量（口型、表情、情绪、手、全身、双向反应） |
| 实时性 | **跑得多快** | 延迟、吞吐、长时稳定、资源 |
| 路线 | **用什么手段** | 各技术路线各自的承诺与代价 |

当前已知的动作域子问题（**允许继续增加**）：音唇同步 · 情绪匹配 · 情绪控制 · 双向交流（反应性 / 打断 / 回合边界）。把双向交流算作动作问题的理由：它解决的是「数字人在一轮对话里**怎么动**」。

#### `### 音唇同步：嘴对得上为什么仍然难`

**要论证**：口型是唯一能从音频**直接推断**的动作量，但它仍然难——难在**训练目标**（捷径学习）、**多目标拉锯**（同步 / 画质 / 身份）、**评测失效**。
**证据**：

| 问题 | 工作 | 声称的解法 | 数字 |
|---|---|---|---|
| 真实场景大量 out-of-sync | Wav2Lip | 预训练唇形专家判别器（SyncNet）当监督 | — |
| 同步 / 牙齿清晰度 / 身份互相打架 | MuseTalk | latent inpainting 局部重绘 + 两阶段训练 | **30 FPS** on V100；256² 人脸区；90h × 8×H20 |
| **捷径学习**（模型从视觉推视觉） | LatentSync | StableSyncNet（只含唇形-音频关联的嵌入）+ TREPA | SyncNet 准确率 **94%**；HDTF Sync_conf **8.9**、FID **7.22** |
| 稀疏 landmark 丢信息 | Flow-Guided | 3DMM 参数生成稠密光流替代 sparse landmark | 首个 **512×512** one-shot；AV Confidence **5.166**（Wav2Lip 5.227、MakeItTalk 2.770）；开源 **16h HDTF** |
| 音频该驱动哪部分没拆开 | Hallo | HADVS 把音频-视觉对齐拆成 lip / expression / pose | HDTF FID **20.545**、Sync-C **7.750** |
| 非正面视角 / 动态前景 | Hallo3 | 预训练 DiT 视频基座 + Identity ReferenceNet | HDTF FID **20.359**；64×H100；Wild 主体动态度 **13.286** |
| **指标本身失效** | THEval | 八大指标重做评测 | FID/FVD/SyncNet 全部与人类判断不相关（Spearman）；17 模型 × 5011 视频；发现「Wav2Lip SyncNet 悖论」与音频驱动头部运动僵硬 |

**结论**：同步数字不可横向比——换口径不可比（LSE-C/D vs sync_c/d），且**先确认时间对齐（offset）再比指标**；所有生成方法存在系统性一帧延迟（AV Offset −2）。真正的剩余难点不是「对不上」，而是**同步与画质、身份三者同时达标**。
**规模**：约 2,000 字符。

#### `### 情绪匹配：表情跟不跟说得内容走`

**要论证**：情绪匹配有两条路——**（a）音频韵律 → 情绪运动**（有人在解）、**（b）说的内容 → 情绪**（几乎是空的）。并给出一个明确判据：Avatar Forcing 的条件三元组里没有任何语义通道，所以「平静语调说悲伤的话」它无法知道该悲伤。
**证据**：

- **数据集起点**：MEAD —— 60 演员 / **8 种情绪** / 3 级强度 / 7 视角 / **281K** 片段，情绪可控 baseline
- **（a）路线代表**：EmoTaG（情绪语音 → 上半脸 / 下颌 / 口腔运动带情绪变化，GRMN + Semantic Emotion Guidance）；SentiAvatar（plan-then-infill 把**语义规划**与**语音节奏**拆开，SuSuInterActs **21K** clips / 37h、200K+ 预训练 motion、**0.3s 生成约 6s**）；EMO-Avatar（LLM Agent 编排情感理解 + 三阶段咨询策略 + TTS 副语言控制）
- **说-听统一**：UniLS —— 解决 **listening stiffness**（听者僵硬）；两阶段（无音频先验学习 + 双轨音频微调）；听者分布指标 +**44.1%**，F-FID **13.143 → 4.304**（−67.3%）；**560.6 FPS**；但复现发现「越靠分布形状的指标越偏」（L_JDD +14.2%）
- **（b）路线现状**：`knowledge/音画同步专题` 与《数字人动作》均判定「**从说的内容推断情绪**」这条公开工作**很薄**；语音侧并行线是对比式 TTS 已支持 inline 控制 emotion 与韵律

**结论**：情绪匹配当前等于「**韵律匹配**」；真正意义上的「内容-情绪对齐」缺少输入通道与评价口径，是本篇要明确点出的一个领域级空白。
**规模**：约 2,000 字符。

#### `### 情绪控制：把情绪拧进去的三条通路`

**要论证**：控制信号按来源只有三条，控制粒度**与表示的语义可读性正相关**；隐式表示必须先靠扰动反推控制维度。
**证据**：

| 通路 | 机制 | 代表工作 | 粒度与代价 |
|---|---|---|---|
| **情绪标签** | clip 级情绪条件，与音频、眼部状态并列 | Ditto | 粗（clip 级）；不能逐句变 |
| **情绪参考** | 借一段带情绪的参考视频/图 | 多模态控制类工作；Talker-T2AV 的参考前缀 | 中；依赖参考质量 |
| **可编辑中间表示** | 把可读的参数变成扩散条件 | FLAP（**120D** FLAME 系数当条件，Progressively Focused Training 解耦 pose/expression，Audio-to-FLAME）；EchoMimic（音频 + 可编辑 landmark 双驱动，3 种驱动模式，RLS 随机 landmark 丢弃，540h / 8×A100）；PerformRecast（改 3DMM 关键点变换公式，真正解耦表情与头姿，49 显式 3D 关键点，6 FPS） | 细（可逐维编辑）；需要拟合与渲染器支持 |
| **文本指令** | 用文字描述风格 | CapTalk；LIA-X（稀疏运动字典 + edit-warp-render，~1B 参数） | 细但语义-参数映射不稳 |

**结论**：可控性不是「有没有开关」，而是**表示给了多少可读的维度**；隐式表示（LivePortrait / Ditto 的隐式关键点）靠**逐维扰动观察画面变化**反推控制映射——这是工程上的必要手续，不是实现细节。
**规模**：约 1,800 字符。

#### `### 双向交流：为什么「能回应」不等于「在交流」`

**要论证**：绝大多数数字人的条件里只有**自己的音频**，所以只能生成「单向回应」，无法对用户做出反应——这是「没有互动感」的根因，不是画质问题。
**证据**：Avatar Forcing 的动机原话是现有模型「无法传达真正交互式交流的感觉，常常生成缺少情感投入的单向回应」，并把它归成两个挑战（因果约束下实时；无标注学出鲜活反应）。三条既有双向尝试的局限：DIM（**需人工切换角色**）、INFP（双向 DiT，**需完整时序窗口**，>3s 未来上下文，故不实时）、ARIG（仅表情层、时序差）。
**结论**：双向交流的第一个问题是**输入通道**——用户的音频与画面必须进条件，否则再好的模型也只能自说自话。
**规模**：约 1,000 字符。

#### `### 反应性与听态：用户的状态怎么进条件`

**要论证**：把「用户正在做什么」编码进条件后，数字人才能对用户反应；并且有一个**免标注**的办法学出更生动的反应。
**证据**：

| 机制 | 工作 | 细节与数字 |
|---|---|---|
| 用户音频 + 用户动作进条件 | Avatar Forcing | 条件三元组 `c=(a_u, m_u, a)`；Dual Motion Encoder 两级 cross-attn 把三路多模态输入编码成**同一种条件**；消融**去掉 `m_u` → 反应退化为静态** |
| 反应性度量 | Avatar Forcing | rPCC-exp / rPCC-pose：用户与 avatar 表情/头姿的**残差相关**；表现力用 SID / Var；人类偏好研究五项指标整体 **>80%** |
| 免标注学「更生动」 | Avatar Forcing | 用**丢掉用户条件**的输出构造 preferred / less-preferred 对做 DPO，不需要人工偏好标注 |
| 听态专门模型 | UniLS | 两阶段（无音频先验学习 + 双轨音频微调）解决 **listening stiffness**；听者分布指标 **+44.1%**，F-FID **13.143 → 4.304**（−67.3%）；**560.6 FPS** |

**结论**：反应性在**机制**上已被解（用户状态进条件 + 偏好学习提生动度），但**度量口径仍弱**——rPCC 衡量的是「跟用户同步」，不等于「反应得体」。
**规模**：约 1,600 字符。

#### `### 打断与回合边界：级联管线为何做不到双向`

**要论证**：级联（ASR → LLM → TTS → Avatar）结构上做不到双向/全双工，因为每一级都要等上一级完成；而「一轮说到哪里停」是在有双向要求之后才成为问题的。
**证据**：系列十四的八个设计维度（级联 vs 端到端 vs 混合、Talk→Listen→See 交互层级、延迟预算与流式策略、打断与双工、记忆与人格、模块化与一体化、环境智能）；Wan-Streamer 用**单个因果 Transformer** 统一文本/音频/视频的输入与输出共六路（Thinker–Performer 流式推理：**160ms** 流式单元、模型侧 **~200ms**、总交互 **~550ms**、25 FPS）；Ex-Omni-2D 对话原生（VTP 视觉思维规划 + 16 码本 + 四阶段解耦训练，E2E RTF **1.293**）；OmniMate 指出 Avatar Forcing / Wan-Streamer / UniLS 生成的回应长度都是**预设**的，用显式**生成进度控制器（GPC）**处理开放式回合；**我们的实测**（见《工程设计》）：打断后立即止声**四个版本全部被推翻**（画面冻结 / 长度难调 / 尾音被一起丢弃），判据是「正确性由人眼与听感决定」。
**结论**：打断不是「静音」这么简单，而是**语义 + 画面 + 音频**三方同时收敛的行为；回合边界是双向交互独有的控制问题。端到端统一回避了跨模块对齐，代价是身份与模块替换成本上升。
**外链边界**：工具增强与 Agent 能力属能力扩展，不在本篇范围（外链 `knowledge/tool-augmented-digital-human`）。
**规模**：约 1,700 字符。

#### `### 这一块的未解问题`

**必须写到的五条**：① 内容-情绪对齐缺输入通道；② 同步指标与人类感知脱钩（THEval 已证）；③ 情绪数据集以受控表演为主（MEAD/RAVDESS）与真实对话分布有差距；④ 手部与全身的「表情-手势-语音」统一框架缺位；⑤ **双向交流没有评测基准**——「像不像在交流」没有公认指标（rPCC 量同步、不量得体），打断的正确性判据停留在人工，回合边界刚被提出。
**规模**：约 900 字符。

### 4.4 `## 三、实时性`

#### `### 延迟链：实时不是一个 FPS 数字`

**要论证**：实时是五个环节之和；论文只报生成速度时，**不能推断可交互**。
**证据（延迟链各环节的原文数字）**：

| 环节 | 具体数字 | 出处 |
|---|---|---|
| 首帧延迟（TTFF） | Ditto **385ms**、Online RTF **0.895**、**10** DiT 步；Avatar Forcing **0.5s** vs INFP\* **3.4s**；OmniMate **3.49s** TTFF | 系列三、AF 精读、OmniMate |
| 逐帧 / 模型侧 | Wan-Streamer 模型侧 **~200ms**、总交互 **~550ms**、**25 FPS**、**160ms** 流式单元 | Wan-Streamer |
| 渲染器 | LIA-X decoder **333ms/帧**（A10, 512², bf16, batch=1） | Talker-T2AV 模型精读 |
| 端到端 | Talker-T2AV 历史冒烟 RTF **21.33**、峰值显存 **15.0GB** → 「能跑」≠「实时」 | Talker-T2AV 接入与验证 |
| 我们侧的口径 | GPU **38.5ms/帧 vs 40ms 预算（96%）**，因此「**局部变快 ≠ 用户侧变快**」 | 《数字人加速》 |

**结论**：报告实时性必须同时给出**音频窗口 / 首帧延迟 / 端到端链路**三项，否则不可比。
**规模**：约 1,600 字符。

#### `### 加速手段：从少步蒸馏到流式状态`

**要论证**：所有加速手段可归为五类，每类都有明确的质量代价。
**证据**：

| 类别 | 代表 | 加速数字 | 代价 |
|---|---|---|---|
| 少步 / 蒸馏 | LiveAvatar（DMD，14B → 4 步）、LeapTalk（布朗桥，**1 步 / 200 FPS / 15000×**）、SoulX-FlashHead（Oracle 蒸馏，**96 FPS** Lite on 4090，1.3B DiT） | — | 误差累积被放大（LiveAvatar 明言少步蒸馏会放大累积） |
| 流式状态与 Forcing | Self-Forcing、Neighbor Forcing（LiveAct，**20 FPS** 小时级）、Diffusion Forcing（Avatar Forcing） | — | Forcing 策略有三大陷阱；KV cache 无限增长 |
| 缓存与 KV | Avatar Forcing 双锚 KV（缓存上限 **M=38**）、LiveAct ConvKV | — | 长时必须做有界管理 |
| 动作空间替代像素 | Ditto **265D** motion、Teller RVQ motion token（**200ms chunk**） | — | 表达上限受表示约束 |
| 架构与工程 | LiveAct 3 步蒸馏 + **FP8**；EGSTalker **68.51 FPS**；LAM **280 FPS**（A100）/ 35 FPS（iPhone 16）；MATCH **570fps** 渲染；TensorRT | — | 精度/平台绑定；渲染器替换要动契约 |

**结论**：加速不是「更快的模型」，而是**少步 + 有界状态 + 契约可控的渲染器**三件事一起做；只做其中一件会换来别的代价。
**规模**：约 2,000 字符。

#### `### 长时生成：误差为什么会累积`

**要论证**：长时的敌人不是算力而是**自回归误差**；论文各自给了不同根因与对策。
**证据**：LeapTalk 指出 noise-to-data 范式「每段从高斯噪声重建」导致误差逐段累积（身份漂移、细节退化、口型含糊），改用 reference 锚定的 data-to-data；LiveAvatar 给出三个长时漂移根因 + History Corrupt / AAS / Rolling RoPE；LiveAct 给出 Forcing 三大陷阱 + KV cache 无限增长；OmniMate 把问题推到**开放式**（模型不知道说多久、何时回到聆听）用 GPC 显式进度控制；Avatar Forcing 承认 exposure bias 未完全解决。
**结论**：长时稳定性靠**机制四件套**（历史状态 / 参考锚点 / 位置编码重置 / 误差抑制），缺一件就漂；这套机制目前分散在各工作里，没有统一设计空间。
**规模**：约 1,400 字符。

#### `### 这一块的未解问题`

**必须写到的四条**：① 实时口径不可比（FPS / TTFF / 每帧 / 端到端混用）；② 少步蒸馏与长时稳定的矛盾；③ 并发与显存（A10 上大模型 **0.8–0.9 FPS**、主机内存要求 ≥110 GiB）；④ 「局部变快 ≠ 用户侧变快」。
**边界**：本节只讲「快不快」；双向交流（听态、打断、回合边界）属动作域子问题，见 §4.3。
**规模**：约 800 字符。

### 4.5 `## 四、路线`

#### `### 3D 路线：把身份做成可复用资产`

**要论证**：3D 路线的承诺是「身份可复用 + 几何一致 + 视角自由 + 渲染快」，代价是**注册/训练成本**与**极端动作风险**；前馈化正在把注册成本压下来。
**证据**：EGSTalker（**68.51 FPS**、3.7h 训练、3–5 分钟训练视频、agent-token 中介交互）；LAM（**280 FPS** A100 / 35 FPS iPhone、**81K** 高斯、**0 后处理网络**）；HyperGaussians（**300 FPS** @512²、PSNR **29.99**、29 被试、即插即用）；AniGS（~10 分钟、21.5 PSNR）；MATCH（45.3h → **4.63h**，**10×**）；LHM（**2.01s** vs 15 分钟优化）；参数化装配式（ARKit 52 blendshape + 游戏引擎，我们未实测）。
**结论**：3D 路线解的是**身份资产化**问题，不是动作问题；换身份=重训这件事被前馈方法部分缓解，但「专用化」成本仍在。
**规模**：约 1,600 字符。

#### `### 隐动作空间路线：把「怎么动」压到低维`

**要论证**：压到低维换来**可控、可缓存、可实时**，代价是**表达上限**与**与渲染器的契约绑定**。
**证据**：SadTalker（3DMM 系数）→ VASA-1（512D 整体面部动力学，**40 FPS**）→ Ditto（**265D** 部署运动向量、**385ms** 首帧）→ Teller（RVQ motion token、**200ms chunk**）→ FLOAT / Avatar Forcing（**20D** α + `r=Bα`）；表示谱系从 3DMM/blendshape（高可读）到隐式关键点/512D latent（低可读）；系列三的关键判断——3DMM 会把面部运动压进预定义参数空间，**强情绪、眼神细节、细粒度肌肉变化与复杂风格化形象受表示上限约束**。
**结论**：隐动作空间解的是**可控性与实时性**问题；它把「说话」拆成可缓存的运动，但不解决画面上限。
**规模**：约 1,600 字符。

#### `### Talker-T2AV 路线：文本驱动的音视频联合生成`

**要论证**：T2AV 回答的是**另一个问题**——不是「给定驱动音频让头像对口型」，而是「**文本决定说什么，同时联合生成新语音与新视频**」；代价是系统更重、调试边界更复杂，且**不自动等于更实时**。
**证据**（本地 `knowledge/Talker-T2AV 模型精读` / `接入与验证`，固定上游 `6712f62`）：

- 输入/输出：目标文本 + 参考音频（音色/韵律/风格）+ 参考 motion/视频 → **新语音 + 新视频**；参考音频**不是**逐帧驱动口型的目标音频
- 架构：Qwen3-0.6B 共享自回归骨干（patch 覆盖 **4 帧**，音频与运动 patch embedding 同位置相加）→ 两条 CFM/DiT 头 → 语音头 **32 维 WhisperX-VAE** latent、运动头 **40 维 LIA-X motion** latent，两条 latent 序列均 **25Hz** 对齐
- 渲染侧：LIA-X 是 flow-warp renderer（稀疏 motion dictionary → ToFlow → warp 源特征 → 512²），A10 上 **333ms/帧**
- 接入结论：历史冒烟 RTF **21.33**、显存 **15.0GB**（「能跑」≠「实时」）；输出规格 **512² 只是中间生成尺寸**，当前逐帧 FaceCropper 贴回源分辨率；A2V / V2A 属**上游声称**、本地未形成公平验证
- 风格入口：`--gt-prefix-seconds`（0 = 只借音色 + 首帧外观；N>0 = 借韵律/节奏/头动风格）

**结论**：T2AV 解的是**内容可控 + 音视频一致**问题——两阶段级联（TTS 再驱动）需要在模块间再对齐韵律与动作，T2AV 在共享骨干里同时建模两条 latent 时间序列；但它不自动解决实时与质量，且本地只有 smoke 级证据。
**口径要求**：本地数字一律标注「历史冒烟 / 未在本机复现」，不写成模型能力。
**规模**：约 1,800 字符。

#### `### 为什么这三条路线不能互相替代`

**要论证**：三条绑定的原因（沿用《介绍与技术路线》的搭配约束，但此处只讲**问题侧**后果）：
1. **渲染器与输入契约绑定**：LIA-X 吃 **40D** motion、FLOAT/AF decoder 吃 512D appearance + 20D α、Ditto/LivePortrait renderer 吃 canonical keypoints —— 动作表示一换，渲染器要跟着换
2. **身份资产有注册成本**：3DGS/NeRF 身份训练进资产，换身份=重训；参数化接口只换一组系数
3. **端到端整帧生成没有可换的后端**：身份长在权重或 LoRA 里
**结论**：路线选择不是「哪个效果最好」，而是「**你的身份资产形态和渲染契约允许你走哪条**」。
**规模**：约 1,000 字符。

### 4.6 `## 问题总账`

**要论证**：把四域收成一张表，按「问题 → 当前最好水平 → 缺口 → 相关文档」四列。
**表行（按域分块；行数随问题清单增长，**不写进正文**）**：
- **身份**（9）：身份一致性度量、长时漂移（单段）、跨轮一致性、大姿态、风格化身份定义、多参考注入、**跨机位一致性（切分镜/多视角）**、**2D 路线跨机位重生成的连续性**、说话风格学习
- **动作**（6）：音唇同步、内容-情绪对齐、情绪控制粒度、双向交流反应性、打断、回合边界
- **实时性**（3）：实时口径、少步与长时矛盾、并发与显存
- **路线**（4）：3D 资产注册成本、隐空间表达上限、T2AV 实时化、渲染器契约绑定

**结论**：四域里真正**没有被任何工作解掉**的是三件——统一身份度量（含跨机位/跨轮两个方向）、内容-情绪对齐、双向交流的评价口径；其余都是「有条件地解了」。
**规模**：约 1,300 字符。

| 标签 | 用于 | 写法 |
|---|---|---|

- 不写产品与竞品（→《数字人行业全景》）
