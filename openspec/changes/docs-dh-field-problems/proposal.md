# Proposal: docs-dh-field-problems（新增《数字人领域问题》）

## Why

数字人这一块的知识现在按**载体**分散在四类文档里，缺一篇按**问题**组织的总账：

| 已有文档 | 组织方式 | 回答的问题 |
|---|---|---|
| `数字人介绍与技术路线` | 按路线 | 有哪几条路线、怎么搭配 |
| `数字人身份` / `数字人动作` / `数字人加速` | 按我们的深挖 | 我们这条线上做了什么、测出什么 |
| `数字人行业全景` | 按市场 | 竞品做到哪一步 |
| `knowledge/*`（52 个文件） | 按专题与单篇 | 某个模型/专题的细节 |
| `论文笔记/*` | 按单篇 | 这篇论文说了什么 |

结果是一个具体的困难：读到一篇论文时，**无法快速定位"它在解哪一个问题、这个问题现在解到什么程度、谁还没解开"**。身份、动作、实时性各自有深挖篇，但它们是"我们这条线的结论"，不是"领域的问题清单"；路线版图讲的是分类，不是问题。

## What Changes

- **新增** `management/docs/数字人概述/数字人领域问题.md`（约 1.8–2.2 万字符），插在《数字人介绍与技术路线》之后。
- **按四个问题域组织**（用户指定）：① 身份 ② 动作（音唇同步 / 情绪匹配 / 情绪控制）③ 实时性 ④ 路线（3D / 隐动作空间 / Talker-T2AV）。
- 每个问题域统一用**三段式**：**问题拆解 → 论文声称的解法（含代表工作与关键数字）→ 仍未解的部分**。
- **章序调整**：新篇 `order: 2`，`数字人身份`～`总结` 的 order 依次 +1（2→3 … 8→9）。
- **同步一处计数**：`总结.md` 的「复盘文档 8 篇」改为「复盘文档 8 篇 + 领域问题 1 篇」。
- 不新增图片资产、不加 sidecar json（与同目录 8 篇保持一致），图示用 Mermaid。
