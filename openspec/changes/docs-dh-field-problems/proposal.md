# Proposal: docs-dh-field-problems（新增《数字人领域问题》）

## Why

数字人这一块的知识现在按**载体**分散在四类文档里，缺一篇按**问题**组织的总账：

| 已有文档 | 组织方式 | 回答的问题 |
|---|---|---|
| `数字人介绍与技术路线` | 按路线 | 有哪几条路线、怎么搭配 |
| `数字人身份` / `数字人动作` / `数字人加速` | 按我们的深挖 | 我们这条线上做了什么、测出什么 |
| `数字人行业全景` | 按市场 | 竞品做到哪一步 |
| `knowledge/*`（52 个文件） | 按专题与单篇 | 某个模型/专题的细节 |
| `论文笔记/*` | 按单篇 | 这篇论文说了什么 |

结果是一个具体的困难：读到一篇论文时，**无法快速定位"它在解哪一个问题、这个问题现在解到什么程度、谁还没解开"**。身份、动作、实时性各自有深挖篇，但它们是"我们这条线的结论"，不是"领域的问题清单"；路线版图讲的是分类，不是问题。

另有两件事在现有文档里**没有作为问题被写下来**（都是用户明确点出的）：

- **双向交流**（属于动作域）：现有文档只在《数字人动作》的「听态」一节的一小段里提到过。但双向不只是一个听态行为——它包含**用户状态进条件**（反应性）、**打断**、**回合边界（说到哪里停）**三件事，Avatar Forcing 正是把它当作核心问题来解决的代表工作（它在动机里把现有模型的问题归为「生成缺少情感投入的单向回应」）。它应该作为动作域的正式子问题存在。
- **切分镜与多视角**（属于身份域）：交付上常有切镜/换机位/多视角需求，但现有文档只在《介绍与技术路线》的「表现范围」里定性提过，且身份域没有它。**它的难点不在渲染能力，而在换机位之后还是不是同一个人**——能不能做由路线决定，判据与度量属于身份，所以它归身份。

## What Changes

- **新增** `management/docs/数字人概述/数字人领域问题.md`（约 3.5–3.9 万字符），插在《数字人介绍与技术路线》之后。
- **正文只列问题**：**不写「为什么重要」**，也不写领域重要性、不写「为什么要问题地图」、不做总结式回扣；全篇唯一的非问题内容是标题下 **3 句无标题导语**（范围声明 / 归类原则 / 口径）。
- **按四个问题域 + 一节跨域收口**：① **身份**（一致性 / 多参考注入 / **切分镜与多视角** / 说话风格 / **风格化**）② **动作**（**按难度梯度排列**：音唇同步 → **跨语言适配** → 整体面部动力学 → 情绪匹配 → 情绪控制与可编辑性 → 语义 grounding → 双向交流 → 反应性与听态 → 打断与回合边界 → 多人场景 → 手部与全身）③ 实时性（含**分段边界**）④ **路线（七条）**：2D 换嘴 / 结构化动作策略 / 动作扩散 + 快速渲染器 / 视频基座与整帧 / 3D 资产 / 掩码多人控制 / T2AV 与端到端统一，后接「为何不可替代」⑤ **跨域问题**（数据分布 / 合规与安全 / 复现与口径）
- **同步一处计数**：`总结.md` 的「复盘文档 8 篇」改为「复盘文档 8 篇 + 领域问题 1 篇」。
- 归类写进正文导语：**双向交流归动作**（它解决的是「数字人在一轮对话里**怎么动**」）；**切分镜与多视角归身份**（难点不在渲染，而在「换机位之后还是不是同一个人」）；5/6/9 归**跨域问题**（不专属任何一域）。
- 每个问题域统一用**三段式**：**问题拆解 → 现有解法（代表工作与规模数字）→ 仍未解的部分**
- **路线域逐条写**（不只你最初点名的三条）：路线划分沿用《数字人介绍与技术路线》的「动作生成 × 身份呈现」搭配法；每节回答同一组问题（**这条路线解什么问题 / 代价是什么 / 为何不可替代**），最后 T2AV 与端到端统一**单列**（它换的是任务定义，不是搭配变体）
- **写法：直接论述问题**——不引述本仓库笔记（不写「见《数字人身份》」「我们的实测表明」），不标来源档位（不分「论文声称 / 我们的实测」），正文不加站内内链（导航只放「问题总账」最后一列）；数字只用于说明问题的规模与代价，不要求逐条对齐出处
- **子问题按门槛逐级抬高排列**：新增问题先判它落在哪一级，**插到对应位置**，不追加到末尾
- **插入位置**：新篇 `order: 20`（《数字人介绍与技术路线》= 10 与《数字人身份》= 30 之间），**不需要改动其它任何文件**——本文用 `docs-order-tooling` 建立的 10 步长约定插入。
- 不新增图片资产、不加 sidecar json（与同目录 8 篇保持一致），图示用 Mermaid。
