# research：基准帧与参考信息解耦（2026-09-24 讨论记录）

> 本轮讨论的原始问题与结论，供后续写入文档时引用。派生问题 H（牙齿时序）与 I（微闭眼基线）已进 `数字人领域问题` §一「多参考注入」。

## 0. 增量点的原始表述（用户）

我们实际能做的：**多视角 / 视频输入用于提供身份信息**。核心是**把基准帧与参考信息解耦**——原本的模型期待在一帧的基础上通过光流 / warp 搬运，我们希望有更多图片提供参考信息。

## 1. Q：StyleGAN 是使用光流的办法吗？

**不是，且"光流 / StyleGAN"不是二选一。**

- StyleGAN 本身从 latent code **直接生成像素**（modulated convolution 逐级上采样），没有 warping / 光流概念。
- 光流 warp 是另一个机制：预测运动场 + mask，`grid_sample` 把源图外观特征扭到目标姿态——负责"搬运动"。
- 领域里说"StyleGAN 式"只是**渲染器借用它的积木**（modulated conv / demodulation / ToRGB），负责 warp 之后的"绘制"。

## 2. 三家族的 warp / 绘制配比

| 家族 | 怎么 warping | 谁绘制 | 光流来源 |
|---|---|---|---|
| Face Vid2vid → LivePortrait → Ditto | 关键点变换生成**解析式稠密运动场**（K 个一阶流 + softmax mask） | SPADE decoder + PixelShuffle | 解析近似（关键点对 + 头旋转） |
| LIA / LIA-X | 光流生成器 $G_f$ **显式预测** flow + mask | StyleGAN2 风格渲染网络 $G_r$ | 网络预测 |
| FLOAT / Avatar Forcing | **无显式 warp**，隐空间加法 $z=z_S+m_S$（$r=B\alpha$） | 逐帧 AdaLN 条件调制解码器 | 搬运在隐空间加法里 |

## 3. Q：光流是不是就没法生成不存在的画面？

- **命题修正一半**：纯光流 = 只搬运，对；但我们的 renderer 都是"**warp 搬运 + 解码器生成**"组合，解码器有补全能力（牙 / 口腔 / 眼睑内侧靠训练数据的共享先验）。
- 准确说法：**不是"没法生成"，是"生成没有保证"**——补全部分无几何约束、无真值监督。
- **Ditto 与 AF 都有，形态不同**：AF 连显式 warp 都没有，搬运也交给学习，理论上更靠解码器想象力。
- **平时"没感觉"的三个原因**：① 驱动动作大多在源图覆盖内（牙 / 口腔是共享先验，补得自然）；② 失败全在分布外（大偏航 / 大俯仰 / 极端张嘴 / 遮挡），我们的场景不触及；③ 自重现式训练与 CSIM 类评测都不往分布外推。
- 两个一分钟实验：正脸源图 + 大幅转头 / 低头驱动，盯耳部 / 发际线 / 牙齿；与 3D 资产方法并排比。

## 4. 注入点结论（对"解耦"的直接含义）

- 三家族共同结构：**身份 / 外观只在基准帧提取一次**（$\mathcal{F}(s)$ 或 $w_S$），之后靠 warp / 加法搬运——"参考被钉死在单帧"是**范式结构特征**，不是实现缺陷。
- **不能在 warp 层加多帧**（AF 的加法层同理）：warp 层只走运动，身份信息不从那里过。
- **正确注入点 = 外观特征提取 / 聚合层 $\mathcal{F}$**：UIKA 双流注意力（任意数量无位姿图）、Face Vid2vid multi-source 是现成做法；我们链路里 Ditto 复用 LivePortrait 的 $\mathcal{F}+\mathcal{G}$，**改 $\mathcal{F}$ 侵入最小**。
- 边界照旧：解**覆盖**不自动解**自洽**（两个硬约束不因注入点移动而消失）；"这几帧属于同一身份"的多帧聚合前提仍是循环的。
