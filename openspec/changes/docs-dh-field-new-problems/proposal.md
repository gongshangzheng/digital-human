## Why

本轮讨论提出五条**新的领域问题**，它们目前都没进 `数字人概述/数字人领域问题`：

| # | 问题 | 现状 |
|---|---|---|
| **A+E** | **动作空间可以被什么调整：逐角色特化 + 情绪条件**（**两条合并为一节**，用户确认） | 只存在于两个在跑 change 的 design（`docs-motion-space-modeling` 文章 02/04 与 DC24）里，**文档层没有**；文档层已有的「情绪匹配」「情绪控制与可编辑性」两节讲的是**情绪怎么进来**，不是**情绪改空间的哪一部分** |
| **B** | **能不能传入多张图片或一段视频来提供身份特征** | 文档层只有「多参考注入：从一张图到任意多角度」讲**生成侧怎么用多参考**；**没有**"能不能从多图/视频学出身份、识别侧经验为何不能直接搬"的条目。identity change 的调研已给出四条成功路线、八条受限模式与两个硬判断 |
| **C** | **要切分镜，就绕不开"能不能展示侧面"** | 「切分镜与多视角」**已有小节**，但缺两块：① **动作潜空间的自由度里没有"机位"**（Ditto 265 维含头姿不含相机，输入是对齐裁剪人脸）② **侧面是"不变/变化划分线"最硬的实例**（视角该算不变还是变化） |
| **F** | **音视频联合生成：当音频从条件变成产物** | §五「条件与任务定义」三处**举例**已提到联合生成（可辨识性 / 可比评测），但**没有专门小节**把它当问题立起来；文档层也没有"任务定义反转之后，条件可辨识性、失败归因与评测判据要怎样重摆"这一条 |

五条里有三条是**身份侧**（B/C）、一条是**动作侧**（A/E），一条是**任务定义侧**（F），因此本 change 单独立项，不塞进任何单一章节的常驻容器。

## What Changes

- 在 `数字人领域问题` 的既有小节里**融入**四处（不另起"本轮新增"节）：
  - **§一 身份**：新增 `### 从多图或视频提身份：识别侧的经验为什么不能直接搬`（放在「多参考注入」之后）
  - **§一 身份**：**扩写**「切分镜与多视角」，补"机位不在动作潜空间里"与"侧面是不变性压力测试"两段（不新建小节）
  - **§一 身份**：把"逐角色特化 + 五档自由度谱 + 四个子问题"融入 `### 说话风格`；把"多图/视频提身份"融入 `### 多参考注入`
  - **§二 动作**：把"情绪作为调节器"融入 `### 情绪控制与可编辑性`（引用「说话风格」节的骨架）
  - **§五 条件与任务定义**：新增 `### 音视频联合生成：当音频从条件变成产物`（放在该章三小节**之前**，因为任务定义反转是其余三小节判据重摆的前提；含收益 / 代价 / 做到哪一步 / 两个结构性阻碍 / 判据表）
- 重点问题用 **★** 标出（总数 ≤4，规则见 design Decision 4）。
- 同步更新开头的**分类表**（身份行加"多输入身份学习"；动作行加"动作空间结构"；条件与任务定义行加"联合生成的任务定义反转"）。
- 每条新条目必须：引用既有文档与调研事实并标注来源；明确与相邻条目的边界（避免重复）；把"已有结论"与"本轮新增"分开写。
- 三条问题的**可检验判据**要写出来。**已删除第四条（"多人同画：身份归属与相互干扰"）**：用户判定为**伪问题**——裁剪范式的做法是逐框处理 + 贴回（LivePortrait 把"多脸同时动画"列为 stitching 的收益），身份串扰在此范式下不发生；其余问题（绑定/跟踪、框外画面、框间遮挡）已被汇报稿 ③ 的固有限制①「只解脸」覆盖，无需独立条目。
