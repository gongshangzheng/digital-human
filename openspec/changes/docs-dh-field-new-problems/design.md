### 2. 每条的内容规格

**A/E · 融入「说话风格」与「情绪控制与可编辑性」**

- **问题陈述**：动作空间不只有一个"通用"版本——它对每个角色、每种情绪都有不同的可行域。问题是：**调整的手段有哪些、能调到哪一档、边界在哪**。
- **两个调节器**：① **逐角色特化**——$p_p\propto p_{shared}\cdot r_p$，$r_p$ 来自该角色的轨迹或单图；② **情绪条件**——区域约束 $\mathbb 1[\alpha\in\mathbb E_e]$ 或条件 $p(\alpha\mid e)$。
- **五档自由度谱**（本节的结构主干）：选子区域 → 重塑密度 → 改方向集（重估 PCA/白化）→ 重分维数/秩 → 换度量/坐标。写明**现有设计只到第二档**，并指出第五档的代价是**跨角色可比性受损**。
- **四个子问题**：① 是什么在调（**情绪区域是通用的还是与身份相关的**——"这个人笑起来什么样"）② 标签形态（离散类别作软隶属度 / 连续强度轴 / 混合情绪；强度怎么标定）③ 可辨识性（**情绪**引起的形变 vs **语义/韵律**引起的形变怎么分离）④ 调整边界（调到哪还算"同一角色的情绪"，越过变成"换人/换风格"）。
- **必须保留的关键区分**：**情绪是"区域约束项"、音频是"数据/条件项"——两者不同类**；正因不同类，"情绪调空间"天然比"音频生成动作"更接近"改可行域"。
- **边界**：与 §二「情绪匹配」（讲两条映射：韵律→情绪、内容→情绪）和「情绪控制与可编辑性」（讲控制**入口**与干预副作用）不同——本节问的是"情绪与特化**改的是空间的哪一部分**"。
- **可检验判据**：升档判据（残差 $\|x-Px\|$ / 密度分位 / 留出行为）· 可辨识性实验（固定身份改情绪 vs 固定情绪换身份）· 边界用留出行为验证，不用拟合。
- **来源**：motion change 的文章 02/04 契约与 DC24、`research/manifold-modeling-and-projection.md`（密度族与投影）、待决 D9；**只引调研事实，不引未成文文档**。

**B · 融入「多参考注入」**

- **问题陈述**：能不能传入多张图片或一段视频来提供身份特征？
- **已答到哪**：识别侧**四条成功路线**（VFR / 多视角 3D 重建 / 个性化扩散 / 前馈式多图聚合）；并给出一条时间事实——"**变长输入 + 注意力聚合 + 质量感知选帧**"这套三件套 **2017 年就成型**（比"任意数量无位姿"的表述早 8 年）。
- **两个硬约束**（本节的核心）：① **识别与生成对"身份"的需求不同**——识别要判别性向量（多帧是纯收益），生成要"能重建所有视角外观"的表示（多帧给**覆盖**、**不保证跨视角自洽**）；引库内原话"多参考改善看不到的角度，但不解决所有角度是否同一人"。② **多帧聚合的隐含前提是循环的**——它假设"这几帧同一身份且身份不变"，而这正是要保证的东西；前提不成立时会把**运动差异当身份差异**去学。
- **八条受限模式**（压缩成一段，不全列）：多帧把运动带进身份 / 聚合顺序与冲突 / 固定数量编码器随输入数失效 / 多视角数据本身不一致 / 大姿态 / 低频轮廓与高频纹理分流 / 跨视角成对标注成本高 …
- **三个未决**：**视频 vs 多图谁更有效** · **单条轨迹提身份的可辨识性** · **"跨动态"与"跨视角"是不是同一个问题**。
- **边界**：与 §一「多参考注入」不同——那条讲**生成侧怎么用多参考**，这条讲**身份学习侧的输入形态**。
- **可检验判据**：与单图基线（Face Vid2vid 一类）对照 · 跨视角成对标注的构造成本 · **TIV 身份纯度**（视频里"跨帧不变"的现成候选，但只有定性证据）。
- **来源**：identity change 的调研（四条路线 / 八条模式 / 两个综合判断）、`论文笔记/{face-vid2vid,tivtok}.md`、§一「多参考注入」原话。

**C · 扩写「切分镜与多视角」（不新建节）**

- **补块一：机位不在动作潜空间里**。Ditto 的 **265 维**只含 scale / pitch-yaw-roll（**头姿**）/ translation / 表情形变，**不含相机位姿与构图**；而且输入是**对齐裁剪后的人脸**——所以在这个范式里"切镜"**不是移动相机，而是重新生成一段**（引既有节原话）。
- **补块二：侧面是"不变/变化划分线"最硬的压力测试**。**大视角下同一人的外观变化可能大于不同人在正面下的差异**——这同时冲击两件事：① "身份 = 轨迹里不变的部分"这个命题（视角一转，不变的部分还在不在）② TIV 类"跨帧共享"表示的可用性（**视角变化会直接打破它**）。
- **三类路线能力表**：3D 资产（天然有相机位姿，LAM 280 FPS / HyperGaussians 300 FPS；但换身份要重训，且"资产化并不自动保证跨视角正确"）· 2D warp 族（**不是 3D 重建**，源图只见正面，转过身后遮挡区无真值、**靠解码器想象**，论文未给"最大多少度"）· 视频基座整帧重绘（可自由换机位，身份一致性与算力是另一笔账）。
- **可检验判据**：跨机位一致性协议（**现有身份度量故意对视角不变 ⇒ 测不到跨机位外观连续性**）；同时要求"合理相机变化要允许、不合理外观重置要敏感"。
- **边界**：只补上述两块，**不重写**既有内容（3D 资产有相机、2D 只能重新生成、度量测不了这三条已在该节）。

### 5. 第五条：音视频联合生成——落 §五 章首（用户追加）

**用户指令（2026-09-24 追加）**："音频联合生成这件事也加进我们提出的数字人领域问题里面"。

**为什么单独立一条，而不是并进 §五 既有三小节**：§五 现有三小节（可辨识性 / 缺失与冲突鲁棒性 / 可比评测）**都把音频当输入条件**，它们问的是"条件从哪一路进来""条件坏了怎么办""条件预算相同没有"。联合生成把这件事**反过来**——音频是**产物**——于是三小节的判据全部需要重摆。**任务定义的反转是其余三小节的前提，所以新小节放在章首**（不新建章节、不动章节编号）。

**该节内容规格**（6 段 + 一张对照表，与会内其他条目同量级）：

- **任务定义反转**：从"给定音频 → 生成动作/画面"变成"音频与画面/运动一起生成"；音频从"可用来定位失败原因的那一路"变成"需要被评价的输出之一"。
- **换来什么**（为何最近工作变多）：同步从"事后对齐"变"同源生成"（级联靠损失函数与重定向模块事后修）· 跨模态一致性成为可约束量 · **能生成音效与环境声**（级联只成人声）· 消除级联的延迟叠加与误差累积（可共享上下文与缓存、端到端流式）。
- **拿什么换**：**可插拔性变差**（两路耦合，换一路要动整体——**与我们"运动生成与渲染器各自可替换"的工程主线直接冲突**）· 算力与数据门槛（统一音视频模型到 32×H100 四阶段量级，OmniMate）· **评测更难**（要同时评音频质量 / 视频质量 / 同步，而"跨模态一致性"无公认指标）· 身份与音色仍靠参考条件。
- **做到哪一步 / 有没有在运动潜空间做**：两路现成工作——**双流分支 + 跨模态注意力**（Unison、UniAVGen、Ovi、LTX2.3、MOVA）与**单一特征空间统一建模**（JOVA、SPEED）——**这两路的联合都在像素 / 视频 latent，不在运动潜空间**；**在低维运动潜空间里联合的实例已出现**：Talker-T2AV（共享自回归骨干，patch = 4 帧，音频与运动 patch embedding**在同一位置逐元素相加**；两条头分别出 **32 维语音 latent** 与 **40 维 LIA-X 运动 latent**，**同频 25 Hz**，再由 LIA-X 渲染 512²）。结论："运动潜空间联合"的接法是**同频两串 latent + token 序列层统一**，不是共享一个连续空间。
- **两个结构性阻碍**：**带宽不对称**（运动潜空间只有 20–40 维，而语音侧即便压到 latent 也要 32 维、波形侧还有独立采样率）· **无天然共同表示**（语音是离散 codec token / VAE latent，运动是连续低维向量）⇒ 现实中只有三种接法：token 序列层统一 / 双流分支交互 / 级联；几乎没有"同一个连续潜空间同时表示语音与运动"。
- **边界**：Talker-T2AV 上游还声称同一套权重支持音频驱动视频与视频配音，但**本地只验证了文本到音视频**，其余按上游声称能力看待；其视频侧主要成本是 LIA-X 渲染（A10、512²、bf16、batch=1 下约 333 毫秒/帧）。
- **我们的落点（标为推断）**：与固有限制"**运动侧没有角色条件**"接上——语音天然携带音色与说话风格，**联合生成等于免费给了运动侧一路角色条件**；不必端到端联合，只在运动侧引入语音的音色 / 风格条件就能补回角色条件且保住可插拔性。
- **判据表**：音频地位（条件 vs 产物）· 同步（事后对齐 vs 内生）· 失败归因（有锚 vs **失去锚**）· 可插拔（可分别替换 vs 换一路动整体）· 音效与环境声（无 vs 可生成）· 评测（唇同步族成熟 vs 需同时评三件事且跨模态一致性无指标）。

**不标 ★**（沿用 Decision 4 的"默认三个"）；若用户要第四个 ★，**此条比"切分镜与侧面"更够格**（它是任务定义级的，而后者只是 ★1 的压力测试）。

**来源**：`knowledge/Talker-T2AV 模型精读.md`（共享骨干 / 两条头 / 25 Hz / LIA-X 333 ms）· `knowledge/Avatar Forcing Motion Latent AutoEncoder.md`（40D motion latent 对比表）· `knowledge/OmniMate` 相关（双流分支与统一建模两支的划分、音效与环境声、32×H100）· §五 既有三小节原话。

### 6. 第六条：音素层显式化——落 §二「音唇同步」之后（用户追加）

**用户指令（追加）**：领域里有没有直接思考从**音素层**改音唇同步的？我们在钉钉实习后期做桌宠时的方案就是从**生成的语音里提取音素、再用音素驱动嘴部运动**，这件事也可以加进问题列表。

**为什么单独立一条**：「音唇同步」节讲的是"嘴对得上为什么难"（offset / 共发音 / 指标不一致），「跨语言适配」节讲的是"语言函数"；**都不问表示层选择本身**——即"音素层该不该显式化"。而且这一条与固有限制"隐式空间与渲染器是私有契约"直接对照： **音素/viseme 层是"越语义化越通用可编辑"一端的实例**（与 ARKit blendshape 同类），是**可插拔的一个现成候选**。

**该节内容规格**（5 段 + 一张四类角色表）：

- **两条路径**：显式音素 / viseme 中间层（音素→口型映射）vs 端到端隐式映射（wav2vec / HuBERT 帧级特征直接进生成器）；**当前主流是后者**，但前者至今活在工业管线（TTS viseme 事件、引擎 viseme 权重、唇形工具），**我们桌宠的方案属于这一族**。
- **显式层买到的是接口性质**：可编辑 · 可解释与可归因 · 可跳渲染器复用（纯运动层、与身份解耦）。
- **四条代价**：**共发音**（音素→嘴形一对多，纯音素驱动会丢上下文差异）· **边界不可见**（从**生成的**语音做强制对齐会继承 TTS 时长误差）· **音素表语言中心**（承「跨语言适配」）· **表达力只到嘴**（情绪 / 头姿要另开通道融合）。
- **四类角色表**：中间表示（VisemeNet · 工业管线 · 我们的桌宠）· 只在训练时监督（Wav2Lip 5 帧窗对齐音素 · 音素主运动 + 情绪偏差双分支 · **我们的音素辅助头**，推理时丢弃）· 完全不出现（主流端到端）· 当诊断工具（**我们的对齐 probe**：92 类音素 / 51,921 样本；wav2vec 线性可读 0.394 vs 真实运动隐变量 0.016）。
- **结论**：真问题不是"音素层有没有用"，而是**什么时候值得显式化**；中间态（显式音素给主运动 + 隐式特征补残差）最有希望但**缺判据**。
- **可检验实验**：固定音频只替换音素时间轴（应当只改口型）· 同一份音素驱动不同 TTS / 渲染器（看是否要重新对齐）· 同一音素在不同上下文下的嘴形散布（量化共发音损失）。
- **不标 ★**（沿用 Decision 4 默认三个）；但它与 ★3（多图/视频提身份）同属"表示层该不该显式化"这一类。
