## 【待审核】正文大纲（9 节 / 3 张图）

### 一、`## 为什么重要`

- 选型与产品对标决定方向：同一个任务，选错路线意味着算力、成本与周期的量级差异
- 这一篇要回答的是工程落地最常被问的问题：**"我手上有什么 GPU，能做到什么级别的实时？"**
- 边界：原理与流派见 [[实习复盘/数字人介绍与技术路线|数字人介绍与技术路线]]；工程细节见 [[实习复盘/工程设计|工程设计]]

### 二、`## 竞品与产品调研`

- **开源侧**：LiveTalking（已广泛商用的实时流式引擎，四层架构：API 层 / 逻辑层 / 渲染层 / 推流层；3060 上 wav2lip256 60 FPS、4090 上 MuseTalk 72 FPS）；OpenAvatarChat / LiteAvatar / Ultralight（轻量 2D 与端侧）；CyberVerse（实时 Agent 框架，但 **GPLv3**，商用前需法务判断）
- **产品侧**：主流云厂商的数字人产品与语音栈——可控 TTS / 声音克隆、全双工语音 LLM 的成熟度
- **我们与竞品的差**：我们在"实时 + 可插拔 3D / 扩散模型"这一段，竞品多集中在轻量 2D 或纯语音
- 结论：这一节的用处是**对标**——知道哪些能力是行业标配、哪些是我们的位置

### 三、`## 未采纳与待复跑`

- **状态不是标签，而是证据等级**（四档，写清每档能写什么、不能写什么）：

  | 等级 | 含义 | 可以写 | 不可以写 |
  |------|------|--------|---------|
  | 待复跑 | 只有口头或初步观察 | 观察原话、待补字段、复跑计划 | 分数、排序、最终结论 |
  | 初步观察 | 已有输出但对照不完整 | 单项指标 + 标注"对照不完整" | 直接排名 |
  | 已复现 | 同协议重复得到一致现象 | 结论 | 未验证的推广 |
  | 已否决 | 当前场景决定不采用 | 原因 | — |

- **待复跑清单**：
  - **ExOmni-2D**：初步观察。真人轨同步指标可用（sync-c 5.03 / sync-d 9.1，接近我们当时记录的 5.12），但**仅单条真人素材**；卡通素材上的旧结论已撤销。下一步同资产、同音频、同规格重跑
  - **MoDA**：待复跑。可运行，但主观上弱于 Avatar Forcing，缺同协议对照
  - **LiveAct**：见《数字人加速》的硬件档位节——放得下但慢，且唇同步口径不可比，只适合离线评测
  - **UniLS**：待复跑，缺一致协议
  - **Talker-T2AV 的预处理管线**：待复跑，问题出在预处理而非模型
- 结论：这一节的价值是**避免重复投入**——直接回答"这个模型我们验证到哪一步了"

## Decisions

- **D1 素材不落仓库**：整理结果只在对话中提交审核；仓库只保留正文
- **D2 来源分级必须标注**：论文披露 / 仓库 README / 我们实测，三类不混在一起比较；未公开留空不猜
- **D3 正文不写出处**：论文标题与仓库名可在正文点名，但不写路径、日期与 commit
- **D4 不越界**：原理与路线归《数字人介绍与技术路线》；工程细节归《工程设计》；速度与实时性口径归《数字人加速》
- **D5 配图 2 张**：五层技术栈图、竞品位置对照图
- **D6 标题规范**：不用桶标题、标题不用冒号、同文档内引用用 heading 链接

## Risks / Trade-offs

- [横评数字跨 GPU/分辨率被误读] → 每张表都带读表纪律；来源类别逐行标注
- [市场信息多为二手] → 逐条注明来源性质（二手整理 / 仓库公开数据），不写成我们的实测
- [趋势判断写过头] → 每条标"观察 / 推断"，不写"将胜出"
