## Context

`validate-note.py` 现在覆盖三类**不受支持的定界符**（`\(...\)`、`\[...\]`、`\begin{equation}`），全部是 WARNING；但**当前渲染器下的确定错误**一条都没覆盖。结果是我们在给 `face-vid2vid` 补架构图时，两类错同时漏过校验并进了仓库：

1. **行内误用块级定界符**：正文里写 `$$f_s$$`。`$$` 是块级公式，于是"行内引用"在页面上变成**整行居中的大公式**——读者一眼就看得出，校验器一声不响。
2. **双反斜杠命令**：写 `\\delta` / `\\Delta` / `\\times`。KaTeX 里 `\\` 是**换行符**，δ 会渲染成字面 "delta"。

这两类的共同点：**不是风格偏好，而是"渲染器一定会出错"**——只要有检查，就一定能抓到，且不可能有误报豁免的灰色地带（合法写法可以枚举穷尽）。

存量回归：`management/docs/论文笔记/` 现有 13 篇已用同一套规则扫过，**零违规**，因此可以直接做成 ERROR 级而不会让任何现有笔记失败。

## Goals / Non-Goals

**Goals：**

- 用两条 **ERROR 级**检查堵住上述两类错误，报出行号与修法，退出码非零。
- 穷举合法写法避免误报：独占一行的 `$$`、单行块级公式 `$$ x $$`、Mermaid 内的 `$$...$$`、反引号内的字面 `$$...$$`。
- 保持既有行为与 CLI 不变：三条旧警告、其余校验、退出码语义（errors 非空 → 1）都不动。

**Non-Goals：**

- 不检查公式内容本身是否正确（LaTeX 语法、符号表完整性、公式是否配解释）——那是写作规范，不是可判定的渲染错误。
- 不改 `documentation` skill、不改前端渲染器、不改 `docs-math` 契约。
- 不覆盖 `knowledge/`（那些文档不由该校验器校验；其中 `digital-human-identity-consistency.md` 有 12 处行内 `$$` 属另一件事）。

## Decisions

### D1 两条检查的精确语义

```
逐行扫描 body（frontmatter 之后）：
  维护 fence 状态（``` 开合）
  若在 mermaid 块内：
      仅检查 `\\+字母`（KaTeX 里 \\ 是换行符）→ ERROR
      不检查 `$$`（Mermaid 节点内 $$ 是受支持写法）
      跳过该行其余判断
  否则：
      code_free = 去掉行内代码（`...`）后的文本
      若 code_free 命中 `\\+字母` → ERROR（双反斜杠命令，应合并为单反斜杠）
      若 code_free 含 `$$` 且该行不是 "$$" 也不是整行匹配 `\$\$.+\$\$` → ERROR（行内误用块级定界符）
```

- 报错文案带行号与修法（"line N: ... 应改为 `$...$`" / "line N: ... 应合并为单反斜杠"）。
- 判断用**剥离行内代码后**的文本，所以文档里讨论语法本身（如本 skill 与 README 中的 `` `$$...$$` ``）不会误报。

### D2 严重级别 = ERROR（附依据）

依据有三条：① 两类都是渲染器下的**确定错误**，不是偏好；② 合法写法可枚举穷尽，误报风险可控；③ **13 篇存量零违规**，提升级别不产生历史噪音。备选方案是 WARNING（与旧三条一致），否决理由是那两条旧警告已经在实践中被忽略，导致本次错误直接进仓库。

### D3 实现位置：新增一个纯函数 + 在 main 中调用

在 `validate-note.py` 内新增 `check_math_delimiters(body) -> list[str]`，在现有三条定界符警告之后调用并 `errors.extend(...)`。理由：可单独测试、不侵入既有逻辑；同时把旧注释（"warn about unsupported delimiters"）更新为对新检查的说明。

### D4 Mermaid 的差异必须体现

`$$` 在 Mermaid 内是**受支持**写法（仓库约定），但在 Mermaid 内写 `\\delta` 同样是错的（KaTeX 规则不分位置）。因此：mermaid 块**跳过 `$$` 检查、保留双反斜杠检查**。这一条如果写反，要么误报所有 Mermaid 图，要么漏掉 Mermaid 图里的字面 delta。

### D5 不引入依赖、不改 CLI

只用标准库 `re`；不加参数、不改输出前缀（`ERROR:` / `WARNING:`）与退出码。

## Risks / Trade-offs

- [跨行 `$$` 块被判为行内] → 独占一行的 `$$` 显式跳过；验证时用一个跨行块级公式的正例回归。
- [单行块级公式被误报] → 整行匹配 `\$\$.+\$\$` 视为合法（已覆盖）。
- [文档讨论语法时被误报] → 行内代码先剥离；并用 README 第 16 行的真实文本做负例回归。
- [ERROR 级别过严，未来合法写法被禁] → 规则只覆盖"渲染器确定出错"的两类；新增例外必须同时更新 spec 的「合法写法不误报」场景。
- [与知识库文档的既有违规混淆] → 明示校验器只服务 `论文笔记/`；`knowledge/` 那 12 处不在本 change 范围。

## Migration Plan

1. 用户审核本 design（尤其 D1 的跳过规则与 D2 的级别依据）。
2. apply：改 `validate-note.py`；跑三类回归——① 13 篇存量笔记全部 OK；② 两个正例（注入行内 `$$`、注入 `\\delta`）各自以 ERROR 报出且退出码 1；③ 四类合法写法（跨行块级、单行块级、Mermaid 内 `$$`、反引号内 `$$`）不报错。
3. `openspec validate docs-validator-inline-math --strict`；提交。
