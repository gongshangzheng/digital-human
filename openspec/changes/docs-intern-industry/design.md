## 【待审核】正文大纲（9 节 / 3 张图）

### 一、`## 为什么重要`

- 选型与产品对标决定方向：同一个任务，选错路线意味着算力、成本与周期的量级差异
- 这一篇要回答的是工程落地最常被问的问题：**"我手上有什么 GPU，能做到什么级别的实时？"**
- 边界：原理与流派见 [[实习复盘/数字人介绍与技术路线|数字人介绍与技术路线]]；工程细节见 [[实习复盘/工程改进|工程改进]]

### 二、`## 实时性的三个指标与延迟链`

- **FPS** 决定持续流畅度（≥25 为实时，≥50 才有余量做多路）；**TTFF / 首帧延迟**决定交互灵敏度；**RTF**（处理时间 / 音视频时长）是吞吐效率的综合度量，RTF < 1 表示跑得比实时快
- 三者关系（本节的核心判据）：高 FPS 但首帧 3 秒只适合离线配音；首帧 200ms 但 FPS 15 只适合低帧率交互；**只有两者同时达标才支撑双向对话**
- **延迟链分解**：音频窗口 100–2000ms（往往是最大瓶颈）→ 模型推理 10–200ms → 编码传输 20–350ms。论文最常优化的"模型推理"通常不是最大项
- **配图 1**：`flowchart LR` 延迟链三段（标出谁是大头）

### 三、`## 模型实时性横评`

- **按路线分组**的 30+ 模型实时性表，并标注**来源类别**：论文直接披露 / 开源仓库 README 或 benchmark / **我们实测**。未公开的不猜，留空
- **读表纪律（必须写）**：FPS 不能脱离 GPU 型号与分辨率比较——同一模型跨 GPU 差异可达 5–10 倍；表里的"实时 ✓"只表示该 GPU 上 FPS ≥ 25 或 RTF < 1，**不代表产品级端到端实时**
- 分路线的代表数字（举例）：Ditto（A100 + TRT）RTF 0.895 / 首帧 385ms；LivePortrait（4090）67 FPS；SadTalker 消费级仅 5–15 FPS；FlashHead Lite（A10 实测）46.7 FPS 与 Pro 1.3B（A10）4.8 FPS 的档位差
- **第一手 15+ 模型 SpeedRun / Formal Eval 横评**：数据位置待确认（见决策点 1）；取不到则本节标注"待补"，不编数字

### 三之二、`## 生成侧加速`（**本次新增**）

- 定调：延迟链里"模型推理 10–200ms"不是固定的，视频推理加速是实时性的另一层；前面讲链路编排，这一节讲让生成本身更快
- `### 慢在哪`：四类成本来源（注意力时空 token 近似 N² / 去噪步数 / 模型与显存 / 系统开销）→ 四类加速方向（内核与稀疏 / 步数蒸馏与新范式 / 缓存与低比特 / 并行与推理引擎）；**配图**：`flowchart LR`
- **四个加速方向各自成三级标题**（不设四级、不逐工作展开）：`### 内核与稀疏`（FPSAttention）· `### 步数变少`（BLADE、NAR、FlashAR）· `### 缓存复用`（Latent Spatial Memory、WorldAttention）· `### 并行与推理引擎`（ZipAR、DAX、Inferix、TurboDiffusion）；每个方向 1–2 句说明"做什么、属于哪一档"
- `### 两条结论`：协同设计是唯一的免费午餐（呼应工程侧"warp 变快但 stitch 抵消"）· 训练费与即插即用的光谱（零训练 → 后训练 → 蒸馏/QAT → 从头训练），并落到"我们手里是哪一档"
- `### 能落到我们管线上的`：LIA-X decoder 蒸馏（512²/bf16/batch=1 约 **333ms/帧**，T2AV 链路瓶颈，属只需推理权重那一档）；倍数可比性写进正文句子（同模型/硬件/分辨率/步数/质量约束，幻灯片与论文口径要对齐），**不设"证据纪律"之类的元指导小标题**
- 素材：knowledge/《视频生成训练与推理加速专题》（十工作全覆盖）+ 博客成稿 `video-gen-acceleration`；两版侧重不同（知识库版偏本地实践与训练源码可用性，成稿版偏协同设计结论与落地排序），需要时对勘

### 四、`## 硬件层级与可行性`

- **四个硬件层级**：零 GPU（CPU / 移动端）→ 单张消费级 → 单张数据中心（A10 / A100 / H100）→ 多卡并行；每层能跑到什么档位
- **一个具体结论**：LiveAct 18B 在 A10 上**瓶颈是主机内存而不是显存**——排障方向因此不同
- 硬件评估结论与选型的连接：我们的目标档位落在"单张数据中心 GPU + 可插拔模型"这条线上
- **配图 2**：`flowchart TB` 四个硬件层级与可达档位

### 五、`## 竞品与产品调研`

- **开源侧**：LiveTalking（已广泛商用的实时流式引擎，四层架构：API 层 / 逻辑层 / 渲染层 / 推流层；3060 上 wav2lip256 60 FPS、4090 上 MuseTalk 72 FPS）；OpenAvatarChat / LiteAvatar / Ultralight（轻量 2D 与端侧）；CyberVerse（实时 Agent 框架，但 **GPLv3**，商用前需法务判断）
- **产品侧**：主流云厂商的数字人产品与语音栈——可控 TTS / 声音克隆、全双工语音 LLM 的成熟度
- **我们与竞品的差**：我们在"实时 + 可插拔 3D / 扩散模型"这一段，竞品多集中在轻量 2D 或纯语音
- 结论：这一节的用处是**对标**——知道哪些能力是行业标配、哪些是我们的位置

### 六、`## 选型结论`

- 早期调研（三路线）→ 以**前馈式 3D 资产方案**为主要探索方向 → 最终体系：**CyberVerse（框架）+ AvatarForcing / Ditto（模型插件）**
- 选型依据：动作空间路线便于实时化与控制；前馈式建资产成本低、便于换形象
- 代价与未选：整帧视频基座路线效果好但训练推理重；3DGS/NeRF 专人资产不适合快速换形象（本篇只写结论与代价，原理见路线篇）

### 七、`## 未采纳与待复跑`

- **状态不是标签，而是证据等级**：同一模型在"接入过 / 跑通过 / 有指标 / 有人工检查"之间差别很大，记录必须写清到哪一级
- **待复跑清单**：ExOmni-2D、MoDA、LiveAct、UniLS、Talker-T2AV 的 FaceCropper 管线——各自卡在哪一步、复跑需要什么条件
- 结论：这一节的价值是**避免重复投入**，也是"选型结论"的证据附录

### 八、`## 趋势判断`

- 素材：论文库（117 篇）+ 时间线；三条结构性关系——**模型层与推理层的开源共生**、**开源中国队 vs 闭源海外队**、**芯片厂商的全栈渗透**
- 写作纪律：**明确标注哪些是观察、哪些是推断**；不下"某路线将胜出"式定论
- 结论：趋势部分服务于选题方向，服务于《总结》里的发文方向

### 九、`## 汇报要点`

- 一页可直取：三个实时指标与延迟链、横评结论（含读表纪律）、硬件档位结论、竞品位置、选型与代价、待复跑清单、趋势的推断性质

## Decisions

- **D1 素材不落仓库**：整理结果只在对话中提交审核；仓库只保留正文
- **D2 来源分级必须标注**：论文披露 / 仓库 README / 我们实测，三类不混在一起比较；未公开留空不猜
- **D3 正文不写出处**：论文标题与仓库名可在正文点名，但不写路径、日期与 commit
- **D4 不越界**：原理与路线归《数字人介绍与技术路线》；工程细节归《工程改进》
- **D5 配图 3 张**：延迟链图、硬件层级图、（第三张待定：竞品位置图或横评分组图）
- **D6 标题规范**：不用桶标题、标题不用冒号、同文档内引用用 heading 链接

## Risks / Trade-offs

- [横评数字跨 GPU/分辨率被误读] → 每张表都带读表纪律；来源类别逐行标注
- [第一手数据缺失导致这一篇"不够第一手"] → 明确标注待补，不用二手数字冒充第一手
- [趋势判断写过头] → 每条标"观察 / 推断"，不写"将胜出"
